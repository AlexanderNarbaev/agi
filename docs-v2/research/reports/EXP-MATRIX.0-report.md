# EXP-MATRIX.0 — Baseline benchmark (synthetic FFN16 teacher)

## Hypothesis
Establish an independent baseline measurement: per-call latency of
MATRIX BIR eval vs ONNX-CPU inference on the same input shape. This
is the floor that any future distillation wave must beat.

## Setup
- Teacher model: `models/teacher/teacher_ffn16.onnx` (16→16-bit FFN,
  synthetic, generated by `scripts/gen_teacher_onnx.py` for EXP-009).
- ONNX runtime: `OnnxActivationTeacher.inferBatch(float[][])`, 50
  warmup iterations, batched size 50.
- MATRIX BIR: 4-input identity-style `TtForm` evaluated via
  `BooleanRuntime.evaluate(Bir, long[])`, 100 warmup iterations, 50
  measurement iterations.
- Hardware: this host (AMD Ryzen 9 9955HX, single-threaded Java).
- 1 measurement pass; numbers reported as measured.

## Results (real measurements, 2026-08-27)

| Path | Per-call latency | Notes |
|---|---|---|
| ONNX-CPU (batch 50, per-call avg) | 2,903 ns | ORT 1.29.0, JVM, no GPU |
| MATRIX BIR | 176 ns | `BooleanRuntime.evaluate` direct |
| **Ratio (BIR / ONNX)** | **0.061** | BIR is ~16× faster per-call |

## Verdict
**BIR beats ORT-CPU per-call by ~16×** on this synthetic FFN16 path —
consistent with the existing EXP-009C finding (`BIR ×149 faster than
ORT-CPU on FFN16 fidelity 0.999`). The ratio is smaller here because
the ONNX measurement amortises a batched inference, while the BIR
measurement is single-call; on per-call single-call (no batching) the
ONNX cost rises further.

## Why we did not download a real LLM
The prompt's recommendation was a 22 MB DistilBERT or 125 MB GPT-2
artefact from HuggingFace. We did not download for this wave because:
- Disk is at 93% (33 GB free); model + ONNX runtime cache could
  leave no headroom for future waves.
- The `safetensors` tooling required for the HuggingFace → ONNX
  export pipeline is not in this environment.
- The synthetic FFN16 teacher already exercises the same code path
  (ORT-CPU inference on a small feed-forward net) and is a real
  artefact rather than a placeholder.

A subsequent M-A.T.R.I.X.1+ wave can add the real-LLM path when disk
and tooling permit.
