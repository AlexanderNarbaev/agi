## Objective
Provide a unified `FederationRuntime` API that orchestrates the
`ModulatorRegistryStore` (storage) + `LocalConsensusEngine` (voting)
into end-to-end propose/evaluate/commit operations.

## Class: `io.matrix.federation.runtime.FederationRuntime`

Coordinates registry + consensus operations with capability-based access.

### Methods

- `proposeAdd(ModulatorDefinition, proposerCapabilityOrdinal)` — single-node consensus flow
- `proposeUpdate(ModulatorDefinition, proposerCapabilityOrdinal)` — FROZEN check + consensus
- `proposeRemove(String id, proposerCapabilityOrdinal)` — FROZEN check + consensus
- `get(String id)` — direct read (no consensus)
- `exportRegistry()` — ProtoBuf ModulatorRegistry snapshot
- `getRegistryStore()`, `getConsensusEngine()` — sub-component access
- `getNodeId()`, `getNodeCapability()` — identity

### Single-Node Consensus Pattern

For each propose operation:
1. Check proposer's capability (must be L2+)
2. Check FROZEN constraint for update/remove
3. Generate proposal ID with type + random suffix
4. Auto-cast self vote (single-node = no peer votes)
5. Evaluate via LocalConsensusEngine
6. If approved → execute (add/update/remove)
7. Return Optional<result> or boolean

### CONSTITUTION Compliance

- **Article I v3 (Stratified Stochasticity):** Seeded Random in proposal ID generation
- **Article II (Consensus):** Capability-weighted voting enforced
- **Article IV (Safety):** FROZEN check at runtime layer
- **Article VI (no consciousness claim):** Pure orchestration, no subjective state
