## Objective
Document the current thread-safety behavior of ModulatorRegistryStore
(which uses HashMap, not thread-safe) with explicit concurrency tests.

## Concurrency Tests (3 new tests)

### testSingleThreadedSafe
- Verifies expected usage pattern (single-threaded) is safe

### testConcurrentReadsAreSafe
- 4 threads × 1000 reads = 4000 concurrent reads
- All complete successfully (HashMap reads are safe)

### testConcurrentWritesMayCorrupt
- 4 threads × 100 writes = 400 concurrent writes
- DOCUMENTS limitation: HashMap corruption under concurrent writes
- Asserts size is at least half of unique IDs (allowing for some corruption)
- Prints diagnostic: successes, CME, other exceptions

## Findings

**Current behavior:**
- Single-threaded: ✓ safe (expected use)
- Concurrent reads: ✓ safe
- Concurrent writes: ⚠ HashMap corruption (documented limitation)

**Recommendation for production:**
- Use single-threaded access OR
- External synchronization (lock around ModulatorRegistryStore)
- Wait for future wave: replace HashMap with ConcurrentHashMap
