## Objective
Implement a Java class on top of generated ProtoBuf types that provides:
- In-memory storage of ModulatorDefinition objects
- FROZEN constraint enforcement (immutable definitions)
- Capability-based access control (L2+ can mutate)
- Deterministic ordering for consensus hash calculation
- Export to ProtoBuf ModulatorRegistry message

## Class: `io.matrix.federation.registry.ModulatorRegistryStore`

Note: Named `ModulatorRegistryStore` to avoid collision with generated
`io.matrix.federation.proto.ModulatorRegistry` class.

### Methods

- `add(ModulatorDefinition)` — add new modulator, throws if duplicate ID or invalid safety
- `update(ModulatorDefinition)` — update existing, throws if FROZEN
- `remove(String id)` — remove, throws if FROZEN
- `get(String id)` — returns `Optional<ModulatorDefinition>`
- `getAll()` — returns List sorted by ID (deterministic order)
- `getVersion()` — incrementing version counter
- `size()` — count of registered modulators
- `calculateHash()` — deterministic consensus hash (XOR-based, not cryptographic)
- `exportProto()` — convert to ProtoBuf ModulatorRegistry message
- `canMutate(CapabilityLevel)` — check if capability can modify modulators

### FROZEN Constraints

- Cannot update or remove modulators with `frozen=true`
- `min_consensus_threshold` must be 0-100
- FROZEN modulators must require consensus (validation)

### CONSTITUTION Compliance

- **Article I v3 (Stratified Stochasticity):** Uses `new Random(seed)` for any
  randomness. `getRng()` exposed for callers needing deterministic randomness.
- **Article II (Consensus):** Deterministic ordering + consensus hash calculation
- **Article IV (Safety):** FROZEN enforcement at every mutation path
- **Article VI (no consciousness claim):** Pure data structure, no subjective state
