# Tsetlin Automaton (Granmo Type I/II)

## Что

Атомарный двухсторонний автомат (Гранмо, 2018), портированный из `cair/pyTsetlinMachine ConvolutionalTsetlinMachine.c`. Хранит состояние в одном `int`-счётчике `state ∈ [0..2n]`; голос автомата `INCLUDED` iff `state >= n`. Все переходы — направленная арифметика с насыщением; никакой рандомизации внутри самого автомата. Источник: `matrix-core/src/main/java/io/matrix/tsetlin/TsetlinAutomaton.java`. Согласовано с `designs/DESIGN-04-learning.md` (продюсеры).

## Состояние и переходы

- `inc()` → `+1` с потолком `2n` (шаг к INCLUDE).
- `dec()` → `−1` с полом `0` (шаг к EXCLUDE).
- `includeNow()` → прыжок на `n` (первая INCLUDE-позиция); используется для батч-«включения» противоречащих литералов в Type II.
- Инициализация каноническая (`TsetlinTrainer`): `state = n−1` (EXCLUDE-позиция у границы INCLUDE) либо `state = n`; соседство с включением даёт немедленный старт обучения с эпохи 1.

## Granmo Type I (fire-and-match)

Применяется к автомату в сработавшей clause, попавшей в свой таргет:

- литерал присутствует и автомат INCLUDED → `inc()` (безусловная награда консистентности, «D2-boost»);
- литерал присутствует и автомат EXCLUDED → `inc()` (рост в сторону включения);
- литерал отсутствует и автомат INCLUDED → `dec()` с вероятностью `1/s` (штраф за неконсистентность).

`s ≥ 1` — параметр специфичности; дефолт `TsetlinTrainer.DEFAULT_S = 4.0`. Значение `s → ∞` ослабляет штраф; `s = 1` — максимально агрессивное обрезание.

## Granmo Type II (fired-against)

Применяется к автомату в сработавшей clause, попавшей в чужой таргет:

- для каждого литерала, чьё присутствие ПРОТИВОРЕЧИТ clause на текущем входе, выполняется `includeNow()` — одношаговое включение батчем. Реализовано как одношаговая чистка региона, без постепенного стока.

## Flat-варианты (учебные)

- `feedbackTypeI(present)` — flat Type I: present → `inc()`, absent → `dec()`.
- `feedbackTypeII(presentInNeg)` — flat Type II: present-in-negative ∧ INCLUDED → `dec()`; absent ∧ EXCLUDED → `inc()`. Используется вне D2-контура.

## Метрики / гейты

- Контракт: `state ∈ [0..2n]` инвариантно; `0 < 2n` обеспечивается проверкой ctor.
- Детерминизм: переходы — чистая арифметика; рандом только в `dec()` с `p = 1/s` (вызывающая сторона).
- Покрытие: 100% (юнит `TsetlinAutomatonTest`).

## Открытые вопросы

- Расширение состояния до 64-бит счётчика для k > 20 не рассматривается (CONSTITUTION: K_MAX=20).
- Per-bit насыщение (отдельные потолки для разных литералов) — отложено в research wave.
- Симметризация Type II для multiclass (несколько чужих таргетов) — отложено.
