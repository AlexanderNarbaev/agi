# Hansel Chains (послойное декодирование монотонных функций)

## Что

Декодер монотонной булевой функции `f : {0,1}^k → {0,1}` из оракула с оптимальным в худшем случае бюджетом запросов. Источник: `matrix-core/src/main/java/io/matrix/bir/producers/monotone/{MembershipOracle,MonotoneDecoder}.java`. Соответствует DESIGN-09 (Hansel-style layerwise; полные цепи Ханселя отложены в v2).

## Порядок обхода

Вершины `v ∈ [0, 2^k)` сортируются по убыванию popcount; внутри слоя — по возрастанию числового значения. Это даёт канонический layerwise-порядок, при котором каждый запрос «дотягивается» максимумом замыканий.

## Монотонное замыкание (бесплатные ответы)

Перед каждым реальным запросом проверяется up-set/down-set уже известных значений:

- если любой известный НАД-superset (`sup ⊇ v`) помечен `1` ⇒ `f(v) = 1` бесплатно;
- если любой известный ПОД-subset (`sub ⊆ v`) помечен `0` ⇒ `f(v) = 0` бесплатно.

Каждый реальный ответ `oracle.eval(v)` распространяется через всё замыкание (`propagate`):

- `f(v) = 1` ⇒ все supersets помечены `1`; одновременно проверяется, что ни один уже известный superset не помечен `0` (иначе — `IllegalStateException("non-monotone oracle")`);
- `f(v) = 0` ⇒ все subsets помечены `0`; аналогичная проверка на противоречие с известными-1.

Обход supersets/subsets — стандартным трюком bit-итерации: `(sup + 1) & fullMask` и `(sub − 1) & v`.

## Граница C(k, ⌊k/2⌋)

Хансель (Hansei, 1966) доказал, что для любой монотонной функции бюджет минимально необходимых запросов ≤ `C(k, ⌊k/2�)`. Достигается на «средних» слоях (popcount = �k/2⌋): все их значения вынуждены быть запрошены, потому что замыкания сверху/снизу до них не дотягиваются. Это точная верхняя граница для layerwise-обхода; полные цепи Ханселя (Hansel chains) дают такую же асимптотику, но более экономны на «вытянутых» функциях — отложено в v2.

## Выход и верификация

- Артефакт: `ClauseSetForm(k, clauses, provenance, fidelity)` — монотонная DNF, `neg`-маски пусты (следствие монотонности).
- Для `k ≤ VERIFY_LIMIT=16` — exhaustive verify по всем `2^k` вершинам; при успехе `fidelity = 1.0`.
- Константа-ноль выдаётся как один противоречивый clause `(x0 ∧ ¬x0)` — никогда не срабатывает.

## Метрики / гейты

- Exhaustive fidelity = 1.0 для всех `k ≤ 16` (юнит `MonotoneDecoderTest`).
- Число запросов ≤ `2^k`; стремление к `C(k, ⌊k/2⌋)` — мониторинг через `Result.queries`.
- Детерминизм: фиксированный порядок, отсутствие RNG.

## Открытые вопросы

- Полные Hansel chains (оптимальный выбор следующей вершины, а не layerwise) — research wave.
- Расширение `k > 16` (потеря exhaustive verify; `fidelity = NaN`).
- Связь с задачей H-016 (Reduce к монотонной форме) — отложено.
