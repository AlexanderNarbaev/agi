## 1. Главная идея: единое булево промежуточное представление (BIR)

Любой вычислительный примитив системы — булева функция f: {0,1}ᵏ → {0,1}ᵐ с метаданными. Функция хранится в **одной из форм**, компилируемых друг в друга:

| Форма | Арность | Сильная сторона | Слабость | Роль |
|---|---|---|---|---|
| `TT` — таблица истинности | k ≤ 20 (128 КБ) | каноническая семантика, наносекундный SIMD-eval, прямой маппинг на FPGA LUT | память 2^k, слепота к структуре | эталон семантики; верификация; FPGA |
| `CLAUSESET` — клаузы (DNF/CNF, Tsetlin-style) | **не ограничена** (дефолт ≤4096 литералов) | сжатое представление разреженных функций; встроенный механизм обучения (автоматы Цетлина); интерпретируемые правила; индустриально доказанный FPGA on-chip training | не канонична (две системы клауз могут быть одной функцией) | **первичная форма обучения и хранения знаний** |
| `BDD` — бинарная решающая диаграмма | практически не ограничена | канонична при фиксированном порядке переменных → **точная проверка эквивалентности** двух артефактов за O(размер BDD); сжатие | взрыв на отдельных классах (умножение); чувствительность к порядку переменных | **верификация и аудит**; компиляционный хаб |

Три формы покрывают слабости друг друга: клаузы снимают комбинаторный потолок памяти для разреженных высокоарных функций; TT даёт эталонную семантику и скорость железа; BDD даёт точную проверку «два артефакта вычисляют одно и то же» (вместо статистической оценки fidelity).

Заголовок каждого артефакта (Avro `bir.avdl`): id, форма, арность вход/выход, provenance (teacher/корпус/механизм обучения — lineage), fidelity (измеренная, если конверсия lossy), версия Φ, хэш payload.

## 2. Архитектура слоя

```
producers (офлайн, обучение)            BIR core                  backends (субстраты)
┌───────────────────────────┐   ┌─────────────────────────┐   ┌──────────────────────┐
│ TsetlinTrainer (первичный)│   │ Compiler: TT⇄BDD⇄CLAUSE │   │ JvmSimdBackend       │
│ Distiller (SPEC-001 этапB)│──▶│ Verifier: BDD-экв., SAT │──▶│  (действующий)       │
│ GATopologySearch          │   │ Runtime: evaluate(BIR,  │   │ FpgaBackend (Verilog │
│ ThreeFactorRule (эксперим)│   │   bits)→bits, детермин. │   │   codegen, LUT/CAM)  │
└───────────────────────────┘   │ Registry: lineage, Φ    │   │ QuantumBackend (BIR→ │
                                └─────────────────────────┘   │  MPS — спецификация) │
                                                              └──────────────────────┘
```

- **Producer** — любой механизм, создающий BIR-артефакты. Обучение всегда вне рантайма (CONSTITUTION II.2–3).
- **Verifier** — точная эквивалентность (BDD), SAT-доказательства противоречий (линия Guardrail, цель G1), BRC-цепочки как последовательности BIR-узлов с witness-битами.
- **Backend** — исполнитель; замена субстрата = новый backend, BIR и верификация не меняются. Устойчивость при переходе Java → FPGA → квантовые обеспечивается здесь.

## 3. Требования

### Этап A. BIR-ядро (keystone, делается первым)
- **FR-A1.** Модуль `matrix-bir`: Avro-схема, три формы, компилятор: TT⇄BDD (точный); TT→CLAUSESET (точный, минимизация эспрессо-типа); CLAUSESET→TT (только k≤20); lossy-конверсии помечаются измеренной fidelity.
- **FR-A2.** BDD-пакет (собственный, Java): unique-table + computed-cache; jqwik-свойства: каноничность при фиксированном порядке; eval(BDD) = eval(TT) на случайных функциях k≤16. Reordering (sifting) — отложен.
- **FR-A3.** `BooleanRuntime.evaluate(BIR, bits)` — единая точка исполнения рантайма; детерминизм; JMH-публикация нс/вызов по формам.
- **FR-A4.** Миграция существующего ядра: TruthTable/DecisionTree заворачиваются в BIR как TT-формы (адаптеры, не переписывание — стратегия strangler-fig, ROADMAP §миграция); старый API deprecated, но работает.
- **Критерий A:** весь существующий функционал ядра исполняется через BIR без регрессии тестов; JMH-отклонение latency ≤ 10% (иначе — отчёт с обоснованием).

### Этап B. Машина Цетлина как первичный producer
- **FR-B1.** `matrix-tsetlin`: автоматы Цетлина (2N состояний), клаузы, обратная связь типов I/II, голосование; чистая Java; jqwik-свойства автоматов (границы состояний, монотонность feedback).
- **FR-B2.** Экспорт клауз → CLAUSESET; исполнение основным рантаймом; property-тест: eval(CLAUSESET) = голосование TM на одних входах.
- **FR-B3.** EXP-002 (HYPOTHESES H-002): сравнение форм на идентичных бинаризованных входах — точность, нс/решение (JMH), байт/структуру, устойчивость к label noise (10% flip), интерпретируемость; базовые линии: BNN (внешний ориентир), существующий MPDT-ГА.

### Этап C. Эксперимент механизмов обучения
- **FR-C1.** EXP-003 (HYPOTHESES H-003): Tsetlin-автоматы vs ГА vs трёхфакторное правило как producers BIR на GridWorld→крафт-граф. **Правило решения (зафиксировано до запуска):** механизм-победитель ≥ базовой линии по качеству при ≤ 2× стоимости становится основным; при паритете основным остаётся самый простой (автоматы); ГА при проигрыше переводится на поиск топологий BIR-композиций, не удаляется; проигравшие механизмы помечаются superseded, не стираются.
- **FR-C2.** Каждый producer объявляет Φ (CONSTITUTION III); ухудшение Φ на валидации — откат.

### Этап D. Субстратная готовность
- **FR-D1.** `SubstrateBackend` interface: `evaluate(BIR, batch)`, `compile(BIR)→artifact`, `capabilities()`. JvmSimdBackend — референс (Vector API + virtual threads).
- **FR-D2.** FpgaBackend MVP: TT→Verilog LUT (1:1), CLAUSESET→Verilog (конъюнкции + голосование); эквивалентность проверяется симуляцией (iverilog) против эталона; цель — iCE40 демо ≥1000 примитивов с измеренной latency/энергией (цель G2 ROADMAP).
- **FR-D3.** QuantumBackend — **только спецификация** (`docs/spec/quantum/BIR-to-MPS.md`): конверсия BIR→MPS (bond dimension χ измеряется на реальных артефактах; порог практичности χ≤64) и QUBO-формулировка обучения клауз (резервный optimize()-путь). Код — при появлении субстрата.

## 4. Инварианты

- INV-1: рантайм исполняет только BIR; «сырые» структуры обучения не проникают в рантайм-контур (ArchUnit-правило).
- INV-2: K_MAX=20 действует только для TT-формы (CONSTITUTION II.1); арность CLAUSESET/BDD ограничена конфигом (дефолт 4096 литералов) и мониторится метрикой размера.
- INV-3: lossy-конверсия без записанной fidelity в заголовок — ошибка компиляции.
- INV-4: provenance обязателен: артефакт без lineage не регистрируется (CONSTITUTION V).
- INV-5: точные конверсии проверяются BDD-проверкой эквивалентности в CI (мутационный тест: намеренно битый компилятор ловится — CONSTITUTION VI.4).

## 5. Метрики

нс/вызов по формам (JMH, публиковать) · байт/функцию по формам на одних задачах · fidelity lossy-конверсий · balanced accuracy/F1 (EXP-002) · образцы до порога и wall-clock обучения (EXP-003) · доля артефактов с χ≤64 (квантовая готовность, измерительная) · latency/энергия FPGA-демо.

## 6. Критерии приёмки

1. BIR-ядро слито без регрессий; старый API deprecated; JMH-отчёт опубликован.
2. TM→CLAUSESET→runtime цепочка работает, property-тесты зелёные.
3. EXP-002/003 завершены по протоколу (отрицательные результаты — тоже); ADR «основной producer» принят.
4. FpgaBackend компилирует TT-форму в Verilog, проходящий iverilog-проверку эквивалентности эталону.
5. `docs/spec/quantum/BIR-to-MPS.md` написан, χ измерен на артефактах проекта и опубликован.
