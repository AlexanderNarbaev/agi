# BIR → MPS: спецификация квантового маппинга

**Статус: normative** · Реализует SPEC-002 FR-D3 (QuantumBackend — только спецификация). Это документ-спецификация: он описывает *что* должно быть вычислено и *как* это проверить, но **не содержит рантайм-кода** и не делает заявлений о работоспособности на квантовом железе.

> **Changelog**
> - 2026-08-25 — закрытие отсутствующего артефакта SPEC-002 FR-D3: создан документ `docs/spec/quantum/BIR-to-MPS.md`. Содержимое — только спецификация конвертации BIR→MPS и QUBO-формулировка обучения клауз; рантайм-код отсутствует по правилу FR-D3.

## 1. Цель и границы

**Цель** — зафиксировать контракт конвертации булевых артефактов BIR (форма TT) в матричные произведения состояний (MPS), чтобы при появлении квантового субстрата (`QuantumBackend`, SPEC-002#этап-d §2) маппинг был заранее формализован и проверяем на классическом референсе.

**Границы (жесткие):**

- Это **спецификация, не реализация**. Рантайм-код появляется только при наличии субстрата — SPEC-002#этап-d, FR-D3: «Код — при появлении субстрата».
- Референсная реализация допустима **только** как research-only Python в `docs/research/` или `scripts/`, за guard `Boolean.getBoolean("matrix.research.enabled")`, с fail-fast (CONSTITUTION#статья-vii).
- Числа в этом документе — **целевые метрики** (targets), а не измеренные результаты. Измерения χ на артефактах проекта — отдельный артефакт (SPEC-002#этап-d §5, критерий приёмки 5).

## 2. Математическая основа

Булева функция `f : {0,1}^k → {0,1}^m` представляется как **тензор амплитуд/весов**, не как нормализованное квантовое состояние.

- **Тензоризация.** Таблица истинности из `2^k` строк раскладывается в k-индексный тензор `T[i_1, …, i_k]`, где каждый индекс `i_j ∈ {0,1}` — входной бит, а `T[i_1, …, i_k] = f(i_1, …, i_k)`. Для `m > 1` выход — дополнительный (или m-кратный) индекс; базовый случай — `m = 1`, общий — m независимых тензоров (по одному на выходной бит). Значения `T` — из `{0,1}`: это **классический** весовой тензор (амплитуда-индикатор), нормализация не требуется и не выполняется.

- **MPS-разложение.** Тензор записывается как цепочка ядер:

  `T[i_1, …, i_k] = Σ_{α_1 … α_{k-1}} A^(1)[i_1, α_1] · A^(2)[α_1, i_2, α_2] · … · A^(k)[α_{k-1}, i_k]`

- **Bond dimension χ.** `χ_j = dim(α_j)` — размер промежуточного индекса между ядрами j и j+1. Глобальный `χ = max_j χ_j`. Точное разложение требует `χ ≤ 2^{min(j, k-j)}` в худшем случае; приближённое (SVD-усечённое) даёт меньший χ ценой контролируемой погрешности ε.

- **Отличие от квантового состояния.** У нормализованного состояния сумма квадратов амплитуд равна 1; здесь амплитуды — булевы значения 0/1, и MPS используется как **компактное факторизованное представление таблицы истинности**. Интерпретация как (ненормализованной) волновой функции регистра — вопрос этапа субстрата, вне объёма этого документа.

## 3. Алгоритм конвертации TT → MPS

1. **Тензоризация.** TT-форма (SPEC-002#этап-a) → тензор `T` формы `(2, 2, …, 2)` (k индексов) прямым перекладыванием строк таблицы истинности.
2. **Последовательные SVD.** Двигаясь слева направо, на каждом межъядерном разрезе выполняется сингулярное разложение матрицизации текущего тензора: `M_j = U Σ V†`. `U` формирует ядро `A^(j)`, остаток `Σ V†` — вход следующего шага.
3. **Усечение по порогу ε.** Сингулярные значения σ удерживаются, пока их вклад в норму Фробениуса значим: отбрасываются σ < ε·‖T‖_F. Число удержанных значений на разрезе = локальный χ_j; итоговый χ = max.
4. **Запись fidelity.** По INV-3 (SPEC-002#этап-d §4) lossy-конверсия обязана нести измеренную fidelity в заголовке артефакта: fidelity = 1 − ‖T − T_approx‖_F² / ‖T‖_F². Точная конверсия (χ максимален, ε = 0) помечается fidelity = 1.0.

**Свойство:** процедура детерминирована — фиксированный входной TT и ε дают фиксированный набор ядер (CONSTITUTION#статья-ii, детерминизм).

## 4. Оценка χ: протокол измерения

χ — ключевой индикатор «квантовой готовности» (SPEC-002#этап-d §5).

- **Экспоненциальный потолок.** Точное представление произвольной функции ограничено `χ ≤ 2^{⌊k/2⌋}`. При k = 20 потолок 1024 — заведомо выше порога практичности χ ≤ 64 (FR-D3). Поэтому χ ≤ 64 достигается **не для всех** функций; его следует измерять на реальных артефактах, а не гарантировать.

- **Ограничение k ≤ 20.** K_MAX = 20 действует только для TT-формы (CONSTITUTION#статья-ii, BIR-контракт, п. 1). Множество кандидатов на конвертацию — ровно TT-артефакты с арностью k ≤ 20; арность CLAUSESET/BDD (до 4096 литералов) в этот маппинг не входит.

- **Протокол измерения.** Для каждого TT-артефакта проекта: выполнить конвертацию §3 при наборе порогов ε (напр. 1e-4, 1e-6, 1e-8), зафиксировать (k, m, χ, ε, fidelity). Результат — гистограмма χ по артефактам и доля с χ ≤ 64. **Целевая метрика:** доля артефактов с χ ≤ 64 публикуется как есть; числовой целевой уровень не декларируется до первого измерения (запрет непроверяемых чисел, CONSTITUTION#статья-vi).

## 5. Обратное преобразование MPS → TT

Для верификации маппинга нужен обратный путь, восстанавливающий таблицу истинности из MPS.

1. **Проекция.** Для каждого из `2^k` входных наборов `(i_1, …, i_k)` вычислить значение `T` свёрткой ядер (полное сжатие цепочки) — на классическом референсе это точное суммирование, не сэмплирование.
2. **Округление.** Результат сжатия — вещественное число; восстановленный бит = round к ближайшему из `{0,1}`. (Опционально — вероятностное сэмплирование из квадратов амплитуд; не используется для критерия эквивалентности.)
3. **Критерий эквивалентности.** Восстановленный TT сравнивается с исходным **побитово** по всем `2^k` входам, либо через BDD-проверку эквивалентности (SPEC-002#этап-a, Verifier). Точная конвертация обязана давать равенство на всём домене (fidelity = 1.0); lossy — декларирует отклонение в заголовке.

## 6. Метрики

| Метрика | Определение | Тип |
|---|---|---|
| χ | bond dimension после усечения по ε | измеряемая |
| ε | порог SVD-усечения (вход) и достигнутая погрешность ‖T − T_approx‖_F / ‖T‖_F | вход/измеряемая |
| fidelity | 1 − относительная квадратичная ошибка; обязательна при lossy (INV-3) | измеряемая |
| gate count | число 1-кубитных + 2-кубитных гейтов при компиляции MPS в квантовую схему | **целевая оценка** |

Gate count — оценочная формула `O(k · χ²)` (линейная по числу ядер, квадратичная по bond dimension) и НЕ является измеренным результатом; валидация возможна только после появления компилятора под субстрат.

## 7. Критерии приёмки

1. Документ `docs/spec/quantum/BIR-to-MPS.md` существует и согласован с SPEC-002 FR-D3.
2. Референсная реализация TT→MPS→TT — **research-only Python** (`docs/research/` или `scripts/`), запускается только за guard `matrix.research.enabled`; продакшн-код на Java отсутствует до появления субстрата (CONSTITUTION#статья-vii).
3. Свойства референса проверяются **исчерпывающе на k ≤ 10** (полный перебор `2^k` входов, m = 1): точная конвертация даёт fidelity = 1.0 и побитовое равенство восстановленной TT исходной; lossy при заданном ε даёт fidelity ≥ 1 − ε.
4. Измерения χ на реальных TT-артефактах проекта опубликованы (SPEC-002#этап-d, критерий приёмки 5); числовые целевые уровни помечаются как «целевая метрика», не как достигнутый результат.

## 8. Вне объёма

- **Исполнение на реальном QPU** и интеграция с любым квантовым бэкендом — до появления субстрата.
- **Шумовые модели**, квантовая коррекция ошибок, выбор конкретного набора гейтов (native gates) — этап субстрата.
- **QUBO-формулировка обучения клауз** (резервный optimize()-путь FR-D3) — фиксируется отдельным дополнением к этому документу при необходимости; здесь не специфицируется.
- **Нормализация в квантовое состояние** (интерпретация весового тензора как амплитуд) — вне объёма классического референса.
