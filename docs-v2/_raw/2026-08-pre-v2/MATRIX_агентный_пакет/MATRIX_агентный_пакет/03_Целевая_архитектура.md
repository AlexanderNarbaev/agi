# Целевая архитектура MATRIX

**Статус: normative** · **Версия 2.0 (2026-07-31)** · Изменения — через changelog в шапке.
**Changelog:** v2.0 — вычислительный слой перепроектирован: вместо привязки к MPDT-спецификации нейрона — гибридный Boolean Compute Layer на едином промежуточном представлении (BIR): таблицы истинности (k≤20), клаузы Цетлина, BDD; субстратные бэкенды JVM → FPGA → квантовые. v1.0 — первый выпуск.

Позиционирование (заменяет все прежние формулировки): **«Детерминированное нейро-символическое ядро верификации и безопасного исполнения для ИИ-систем. Каждое решение — проверяемая булева цепочка. Этические и доменные ограничения неизменяемы на уровне FROZEN-слоя и формально верифицируемы».** AGI-направление существует только как `vision/OPEN_PROBLEMS.md` — без сроков и маркетинговых обещаний.

**Ключевой принцип устойчивости:** вся система выше Boolean Compute Layer зависит только от контракта `evaluate(BIR, bits) → bits` и верификационных сервисов — не от формы примитивов и не от субстрата. Замена субстрата (JVM→FPGA→квантовый) = новый backend; замена механизма обучения = новый producer; формы компилируются друг в друга. Ничего выше слоя при таких заменах не переписывается.

## 2. Разделение ролей MATRIX ↔ rag-system (ADR-обязательное)

| Слой | Владелец | Роль |
|---|---|---|
| Semantic retrieval, generation, RAGAS, NLI-grounding, Neo4j, федеративный RAG | **rag-system** | Корпоративные задачи «здесь и сейчас» |
| Exact-match, верификация цитат, нормативный точный поиск, детерминированные фильтры, исполнение решений | **MATRIX** | Верификация и безопасность |
| API-фасад, MCP-сервер, observability | **общие, по одному экземпляру** | Устранение дублирования |

Boolean RAG как самостоятельный retrieval-стек **не развивается**; его ниша — точность и верификация. Переносятся в rag-system: ExactTermGuard, Skeleton Tree breadcrumb-контекст, Lie Detector (дополнение к NLI-grounding).

## 3. Ключевые контуры

### 3.1. Developmental Loop (SPEC-000)
Curriculum engine: оценка компетентности → выбор задач из ЗБР (максимум learning progress) → диагностическая обратная связь (контрпример + BRC) → fading поддержки → MA-гейты. Потребляет BIR-артефакты, не зависит от их формы и producer'а.

### 3.2. Agent Loop
Planner → Reasoner → **Judge** (SAT/SMT + BDD-верификация + FROZEN-фильтры + session-level) → Generator → Act. MCTS — только поверх World Model (предиктор «состояние+действие → состояние» из журналов Kafka).

### 3.3. Memory / CLS-консолидация
Циклы «сна»: реплей эпизодов → сжатие в паттерны/навыки (CLAUSESET-формы) → удаление сырья; MDL-рачет как Φ (Конституция III). Drift detection + Ricci-fingerprint (SPEC-003).

### 3.4. Noosphere (управление общим ресурсом знаний)
Полное решение, четыре слоя:
1. **Governance (Остром):** 8 принципов commons — ясные границы участия (MA-4+); локальная адаптация правил; коллективное участие в изменении правил (RFC); мониторинг участниками (взаимный аудит BRC); graduated sanctions (Конституция IV.4); доступный арбитраж (ByzantineConsensus); признание самоорганизации (P2P); вложенность (узел → кластер → сеть).
2. **Доверие (Луман):** редукция сложности проверки чужого инстанса до проверки подписи — lineage ledger (causal-ancestry граф) + genesis-check (Конституция V) + статистическая доказуемость дистилляции (H-008).
3. **Транспорт:** gossip для рутины; CRDT (G-set/OR-set — знания, PN-counter — кредиты; SEC без координации); византийский консенсус только для критики (кредиты, genesis, конституция).
4. **Устойчивость знания (Эйген/гиперцикл + химические организации):** пакеты знаний с ECC, размер ≤ порога верности канала; кластер зрел, если его сеть знаний замкнута и самоподдерживающа (проверка SPEC-003 инструментарием); CreditModel как механизм с incentive-compatibility анализом и red-team EXP-006 (сговор 10/30/49%).

## 4. Уровни зрелости (MA) — операционная таблица

| Уровень | Аналог (Пиаже) | Возможности | Гейт перехода (EXP-карточка) |
|---|---|---|---|
| MA-0 | сенсомоторный (наблюдение) | shadow-режим: предсказания без действий | fidelity предсказаний ≥ порога на эталонном наборе |
| MA-1 | дооперационный (игра) | действия в песочнице (Minecraft, сим-SCADA) | этюдный набор пройден; 0 нарушений конституции за N эпизодов |
| MA-2 | конкретных операций | действия в реальной среде, каждое подтверждает человек | стабильность метрик на скользящем окне; аудит BRC |
| MA-3 | раннеформальных | автономия в одном сертифицированном домене + пост-аудит | доменная сертификация; стресс-тесты контрфактикой («magic if») |
| MA-4 | формальных операций | полноправный узел Noosphere | Byzantine-репутация ≥ порога; эксплуатационная история |
| MA-5 | наставник | право обучать клоны (teacher), инициировать клонирование | решение оператора + консенсус узлов + genesis-check |

Понижение уровня — автоматическое (drift/нарушения); повышение — только с человеком. Каждый гейт = preregistered EXP (Статья IV).

## 5. Обучение не с нуля (инициализация культурой)

Teacher (открытые веса LLM) → дистилляция по активациям → **BIR-артефакты** (CLAUSESET/TT) → Developmental Loop продолжает обучение на данных среды. Дистилляция — инициализация, не метод существования. Родословная доказуема криптографически (lineage) и статистически (H-008).

## 7. Нефункциональные требования

- Latency по формам BIR: JMH-измерение и публикация (заявления без измерений запрещены, Статья VI).
- Стоимость вычислений (токены teacher, CPU/GPU-часы) — метрика первого класса; бюджет — поле EXP-карточки.
- Воспроизводимость: любой бенчмарк — одна команда из чистого клона.
- Квантовая готовность (измерительная, не обещательная): доля BIR-артефактов с bond dimension χ ≤ 64 при MPS-конверсии — публикуемый показатель.
