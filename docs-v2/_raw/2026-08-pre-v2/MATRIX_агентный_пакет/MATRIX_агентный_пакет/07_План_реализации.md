# План реализации MATRIX

**Статус: normative · v2.0 (2026-07-31)** · Расчёт: один разработчик (Java) + доступные ИИ-агенты; сессии ≤ 30–45 минут; каждый этап заканчивается измеримым критерием выхода. Даты — ориентиры в человеко-неделях, не обещания.
**Changelog:** v2.0 — keystone этапа 1 заменён на BIR (Boolean Compute Layer, SPEC-002 v2.0): гибридный вычислительный слой вместо привязки к MPDT; добавлена стратегия миграции кодовой базы; субстратный путь JVM → FPGA → квантовые формализован через backends. v1.0 — первый выпуск.

## Цели (заменяют все прежние)

- **G1 (верификация LLM):** MATRIX Guardrail — 0% нарушений доменных ограничений на эталонном сценарии при FPR ≤ 5%, latency ≤ 50 мс; публичный красно-командный набор; BDD/SAT-доказательства вместо меток.
- **G2 (safety-critical):** SCADA-пилот — детерминированный Safety Monitor с трассируемостью каждого решения SHUTDOWN к булевой цепочке (логика IEC 61508); FPGA-прототип ≥ 1000 BIR-примитивов с измеренными latency/энергией.
- **G3 (Knowledge Stack):** консолидация с rag-system; Recall@5 ≥ 0.85, faithfulness ≥ 0.8, citation precision ≥ 0.9; Boolean-слой — 100% на exact-match нормативных запросах.
- **G4 (обучение):** Developmental Loop + основной producer (решение EXP-003) демонстрируют прогрессию в Minecraft не хуже базовых линий (ReAct/Reflexion) с воспроизводимым бенчмарком.
- **G5 (доверие):** один препринт («BIR: гибридный верифицируемый булев слой — формы, компиляция, сложность»), открытый бенчмарк-репозиторий, один внешний ревьюер.
- **G6 (видение):** AGI — только как `vision/OPEN_PROBLEMS.md` без сроков.

## Стратегия миграции кодовой базы (strangler-fig, обязательна)

Никакого big-bang переписывания. Правила:

1. **Новое — рядом, старое — за адаптером.** Новые модули (`matrix-bir`, `matrix-tsetlin`, `matrix-ricci`, `matrix-developmental`) создаются рядом; существующее ядро (TruthTable, DecisionTree, SimdTruthTableEval) заворачивается в BIR-адаптеры и продолжает работать.
2. **CI зелёный после каждого шага.** Каждый PR — работающая система; миграция отслеживается в WAL.md (раздел «Что сделано»).
3. **Deprecation, не удаление** до полного переключения: старый API получает `@Deprecated` с указанием BIR-эквивалента; удаление — отдельным PR после ≥ 2 недель чистого прогона.
4. **Карантин неработающего:** `pretrain_neurons.py` и lookup-таблицы действий — первые кандидаты (SPEC-001 этап A, этап 3).
5. **Целевая карта модулей:**
   - `matrix-bir` — схемы, формы TT/CLAUSESET/BDD, компилятор, верификатор, registry;
   - `matrix-runtime` — BooleanRuntime + JvmSimdBackend (ядро нынешнего рантайма мигрирует сюда);
   - `matrix-learn` — producers: TsetlinTrainer, Distiller, GATopologySearch, ThreeFactorRule;
   - `matrix-substrate` — FpgaBackend, (будущее) QuantumBackend;
   - `matrix-developmental`, `matrix-ricci`, `matrix-noosphere` — по своим SPEC;
   - существующие пакеты (ethics, memory, agent, api, cluster) — без переименования до стабилизации.

## Этап 0. Честная рамка и среда (1–2 недели)

1. Положить пакет в репо по 00_README_пакета.md; слить AGENTS.md; создать WAL.md.
2. README-claims: удалить запрещённые формулировки (Конституция VI); разделить «инженерные гарантии» / «исследовательское видение».
3. Карантин конвертации весов (SPEC-001 этап A) — отдельный PR.
4. Юридическая правка: «приоритет над законодательством» → «соответствие праву + право отказа (Eleutheria)».
5. CI: coverage gate ≥ 82%, ArchUnit-скелет, еженедельный GC shared state.
- **Выход:** ни одного непроверяемого утверждения в публичных файлах; карантин слит.

## Этап 1. Boolean Compute Layer (keystone, 5–8 недель)

1. SPEC-002 этап A: `matrix-bir` (схема, TT-форма + адаптер MPDT, BDD-пакет, компилятор точных конверсий, Registry lineage) → **миграция ядра на BIR без регрессий** (критерий A SPEC-002).
2. SPEC-002 этап B: `matrix-tsetlin` → CLAUSESET → runtime; EXP-002 (формы: компактность/скорость, H-002).
3. SPEC-002 этап C: EXP-003 (producers, H-003) → **ADR «основной producer»**.
4. SPEC-002 этап D (старт): `SubstrateBackend` interface + JvmSimdBackend референс; FpgaBackend: TT→Verilog→iverilog эквивалентность.
5. benchmarks/: одна команда; публикация нс/вызов по формам и байт/функцию.
6. Закрыть дыры тестов: `api/`, `cli/`, `cluster/events/`, `R2dbcEventJournal`.
- **Выход:** весь рантайм исполняет BIR; EXP-002/003 завершены (отрицательные отчёты тоже считаются); ADR принят; Verilog-конвейер доказан на симуляции.

## Этап 2. Консолидация Knowledge Stack + Developmental Loop MVP (4–8 недель)

2. Перенос ExactTermGuard / Skeleton Tree / Lie Detector в пайплайн rag-system; golden-набор; RAGAS → замер G3.
3. SPEC-000: Developmental Loop MVP → EXP-005 (гейты MA-0→MA-2); потребляет BIR-артефакты.
4. SPEC-003 старт: matrix-ricci + fingerprint-сервис → EXP-004.
- **Выход:** retrieve → generate → verify с трассировкой; G3 измерен; MA-гейты в интеграционных тестах.

## Этап 3. Обучение и агент (6–10 недель)

1. SPEC-001 этап B: Distiller (DJL/ONNX teacher → активации → BIR-артефакты) → EXP-001 (H-001: судьба линии «конвертер LLM»).
2. AgentLoop: Judge-фаза (BDD-эквивалентность + SAT/SMT + session-level), Skill Library (навыки = CLAUSESET/TT композиции; консолидация BRC → навыки).
3. World Model MVP на журналах Kafka; разблокировка MCTS.

- **Выход:** G4 измерен; EXP-001 отчёт с решением владельца; World Model выше тривиальной базовой линии.

2. SCADA-пилот: чек-лист трассируемости (IEC 61508-логика), runbook; **FPGA-демо на железе** (iCE40, ≥1000 примитивов, измеренные latency/энергия — G2).

## Чего не делать (зафиксировано)

- Не масштабировать «число нейронов/примитивов» как KPI; масштабируется компетенция.
- Не big-bang переписывание кодовой базы (только strangler-fig).
- Не новые формы BIR без ADR и доказанной компилируемости/эквивалентности.
- Не два retrieval-стека параллельно; Boolean RAG — только верификация/exact-match.
- Не Python в продакшн-пути; не модели-зависимости без ONNX-контракта.
- Не обещания AGI и квантовых сроков; не код QuantumBackend до появления субстрата.
- Не развивать matrix-micro/matrix-ros2 до SCADA-пилота (заморожены).

## Риски (топ-6 с митигацией)

| Риск | Вер. | Митигация |
|---|---|---|
| Миграция на BIR выявляет скрытые зависимости от MPDT-семантики | средняя | адаптеры + регрессионный JMH/тест-прогон на каждом шаге; критерий A SPEC-002 как гейт |
| Fidelity дистилляции низкая (H-001 отвергнута) | высокая | заранее принято: линия закрывается по протоколу EXP-001; ценность guardrail/SCADA сохраняется |
| BDD взрывается на части функций | средняя | BDD — только верификация/хаб; хранение в TT/CLAUSESET; fallback — SAT-эквивалентность; замеры публикуются |
| Один разработчик — узкое горло | высокая | агенты на SPEC-циклах; WAL; этап 5 как рекрутинг; quickstart |
| Scope creep | высокая | «чего не делать»; один SPEC — одна сессия; еженедельный GC |
| Этический фильтр не достигает FPR ≤ 5% | средняя | H-007 с эскалацией; negative selection; session-level |
