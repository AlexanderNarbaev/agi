# HARNESS-PRACTICE-SCAN. Индустрия агентных харнессов — скан для MATRIX

Разбор пяти источников 2026 года об инфраструктуре вокруг LLM («agent harness»)
и их отображение на стек MATRIX (L0–L10, ADR-006: LLM — не зависимость).
Назначение: зафиксировать, какие решения индустрии независимо подтверждают
наши инварианты, какие практики переносятся как механизмы, и где проходят
границы (у нас нет attention-окна, токенов и весов — переносятся только
функциональные роли). Источники: разбор харнессов Anthropic/OpenAI/LangChain
[^h1^]; методология СТРАТУМ (Степанов) [^h2^][^h3^]; практическая лестница
принятия агентов Hashimoto [^h4^]; Meta-Harness (Stanford/MIT/KRAFTON) —
автоматический поиск харнессов в код-пространстве [^h5^].

## 1. Конвергенция индустрии: «harness» ≡ наш контур вне модели

Индустрия зафиксировала: производительность системы определяется не весами,
а обвязкой — LangChain поднялся с позиции за пределами топ-30 на 5-е место
TerminalBench 2.0, изменив только инфраструктуру при той же модели [^h1^];
независимо: смена харнесса при фиксированных весах даёт до 6× разрыва на
бенчмарке [^h5^]. Формула LangChain «если ты не модель — ты харнесс»
[^h1^] — индустриальная форма нашего конституционного разделения: контур,
память, верификация и бюджеты (L3–L7) — отдельные проверяемые артефакты,
а не свойство «модели». Для нас это внешнее подтверждение постановки G-C/G-D:
система строится как харнесс без LLM-ядра (BIR-ядро вместо весов), и цена
ошибки проектирования харнесса измерена индустрией (6×).

## 2. Независимые подтверждения наших инвариантов

|---|---|---|

| Трёхуровневая память: лёгкий индекс всегда загружен → детальные файлы по требованию → сырые транскрипты только через поиск [^h1^] | M1 (срез с TTL) / M2 (эпизоды) / M4 (журнал, извлечение со свидетелем); definite event §75 | Индустриальная конвергенция с нашей иерархией доступа по цене |
| Ошибки инструментов возвращаются в цикл как результаты с ошибкой, цикл продолжается [^h1^] | Отказы — первоклассные типизированные события, не аварии (§69, ADR-005) | У них — эвристика продолжения; у нас — четыре класса с witness |

| Enforcement разрешений архитектурно отделён от reasoning модели [^h1^] | Асимметрия верификатора (§64, §70); продюсер ≠ гейт | У Anthropic: модель решает, что попытаться; система — что разрешено |
| Сырые execution-трассы для предложения правок сильно превосходят саммари: best accuracy 56.7 (полный доступ) против 41.3 (только скоры) и 38.7 (скоры+саммари); саммари могут ВРЕДИТЬ, сжимая диагностику [^h5^] | Append-only журнал M4; компилятор журнала §87 — кандидат из валидированной трассы, «порождение по статистике» — антипаттерн | Сильнейшее внешнее свидетельство за нашу дисциплину трассы: сжатие истории теряет причинность отказов |

## 3. Что переносится как механизм (кандидаты)

1. **Вторая ось типологии отказов.** LangGraph различает ошибки по источнику:
   транзиентные (retry с backoff), LLM-recoverable (вернуть в цикл),
   исправляемые пользователем (прерывание за вводом), неожиданные (проброс)
   [^h1^]. Наша типология — по механизму (reject-by-budget, reject-by-proof,
   deadlock, divergence). Осей не пересекаются: один класс отказа может иметь
   разные источники. Кандидат: расширение записи журнала отказов второй осью
   (источник × механизм) — процедурный кандидат, меняет только схему записи.
2. **Харнесс-оптимизация ≡ χ-акты над конфигурацией контура.** Meta-Harness
   показывает: поиск по коду харнесса с полной историей через файловую систему
   обходит ручной дизайн (76.4% против 74.7% Terminus-KIRA на TerminalBench-2;
   +7.7 п.п. над ACE при 4× меньшем контексте; перенос на пять held-out
   моделей +4.7 п.п.) [^h5^]. Наш аналог — ряды Cauldron над χ-меню контура
   (коридоры, пороги, бюджеты) с полной трассой M4: внешний ориентир выигрыша
   и метод (Pareto-фронт «качество × контекст» вместо одного скаляра).
   Кандидат на калибровку в H-021: целевой функционал бюджетера как Pareto-
   фронт, не скаляр.
3. **Дисциплина «engineer the harness»** [^h4^]: каждая наблюдаемая ошибка
   агента обязана закрываться инструментом/документом так, чтобы не
   повториться (AGENTS.md как накопленная история отказов). У нас это уже
   норма (каждый класс нарушений → AT-тест, EXP-017); источник даёт
   операционное правило для параллельного трека разработки: правка процесса
   вместо правки симптома.
4. **Калибровка «reproduce your own work»** [^h4^]: прежде чем доверять
   агенту класс задач — воспроизвести собственные решения вручную vs агентом
   вслепую до совпадения качества. Перенос на продюсеры: калибровка класса
   кандидатов на эталонных трассах владельца (goldens) до допуска в ряды —
   уточнение AT-FNL/EXP-005-кандидатов.

## 4. Что за границей (не переносится)

- **Вся токеновая экономика**: context rot и «Lost in the Middle» [^h1^],
  SCEI-раскладка под KV-кэш [^h3^], «налог на кириллицу» — болезни attention-
  окна. У нас нет окна: срез M1 ограничен типизированными единицами ioSchema
  с бюджетом в чанках (§79), а не токенами; переносится только жест
  «минимальный высокосигнальный срез» (context engineering ≡ дисциплина
  среза M1), не его механика.
- **LLM-as-a-Judge** [^h1^][^h3^]: судья-модель — тот же класс субстрата, что
  и отвечающий; у нас верификатор обязан быть независимым механизмом
  (BDD-эквивалентность, гейты с внешним критерием), судья-продюсер запрещён
  асимметрией верификатора (§64/§70, граница №10).
- **Температура, квантование, сикофансия, гауссиана компетенций** [^h3^] —
  свойства LLM-субстрата; для нас не существуют (нет softmax, весов, RLHF).
- **Размышляющие модели (R1/o1) и их дисциплина промптов** [^h3^] — вне
  субстрата проекта.
- **Заявленная «управление когнитивной логикой нейросети» (СТРАТУМ)** —
  маркетинговая рамка; переносимы только инженерные разделения (слои,
  контракты, версионирование), не претензия на управление «мышлением»
  (Статья VI).

## 5. Итог для программы

Индустрия 2026 независимо пришла к трём нашим центральным решениям и
измерила их цену: (1) разделение «модель/харнесс» с ценой ошибки 6×;
(2) верификация как множитель качества 2–3×; (3) полная сырая история
против сжатых саммари — 15+ п.п. точности поиска. Ни один из пяти
источников не даёт контрпримера нашим границам; все переносимые механизмы
ложатся на существующие слои (L4 журнал, L5 ряды, L6 контур, L7 жизненный
цикл) без новых зависимостей (ADR-006 сохраняется). Кандидаты §3 внесены
в копилку пререгистрации (SYSTEM-SYNTHESIS §4, волна 26).
