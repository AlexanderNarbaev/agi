# Цели и требования MATRIX — консолидация

**Статус: normative** · Собирает в один реестр всё, выработанное сессиями проекта: цели, функциональные и нефункциональные требования. Каждое требование имеет источник (спека/исследование) и проверку. Изменение — через changelog в шапке; противоречие с CONSTITUTION.md недопустимо.

## 1. Миссия и цели

Миссия: энергоэффективная, верифицируемая, честная вычислительная система класса ИИ, разворачиваемая от ноутбука и мобильного устройства до кластера и федерации узлов, с развитием к AGI как **последовательное расширение компетенций через пререгистрированные эксперименты**, а не как декларация (CONSTITUTION VI).

| ID | Цель | Критерий достижения | Источник |
|---|---|---|---|
| G-A | Энергетический паритет и превосходство над LLM-подходом на структурированных доменах | H-009 accepted: ±3 п.п. качества при ≥10⁴× энергии, ≥10³× latency | ANALYSIS §6, EXP-009 |
| G-B | Работа без GPU: CPU-ядро с путём JVM→native→FPGA→quantum | JMH-гейты METRICS; native-сборка модулей; тест «один артефакт — два бэкенда» | JAVA_NATIVE §5 |
| G-C | Верифицируемость решений: каждый ответ — с доказательством (witness, BRC-цепочка) | 100% ответов контура с PipelineTrace; воспроизводимость бит-в-бит | DESIGN-03 §3 |
| G-D | Непрерывное развитие без деградации: обучение только через монотонный Φ-гейт | ни один promote без улучшения Φ; отрицательные результаты фиксируются | CONSTITUTION III, DESIGN-04/05 |
| G-E | Локальный инференс на устройствах пользователя (ноутбук → смартфон → носимые) | профиль устройства ≤ заданной мощности; DEGRADED-режим автономен | DESIGN-08 §3 |
| G-F | Федерация знаний с защищёнными протоколами и обезличенным вкладом в общий пул | подписанный обмен артефактами, MitM-стойкость, ноль персональных данных в пуле | DESIGN-08 §4–6 |
| G-G | Самосоздание элементов (Cauldron) под контролем бюджетов и гейтов | протокол рождения FNL/Capability через Φ-гейт и карантин | DESIGN-07 §2 |

## 4. Трассировка

Каждый FR покрыт минимум одной спекой и минимум одним приёмочным тестом; каждый NFR имеет зарегистрированную метрику в METRICS.md. Новые направления (федерация, TaskCell, Operator) входят через ROADMAP-этапы 4–5 и гипотезы H-01x — не как обещания сроков, а как пререгистрированные проверки (OPEN_PROBLEMS).
