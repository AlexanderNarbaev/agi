# Целевая архитектура MATRIX

**Статус: normative** · Изменения — через changelog в шапке (дата, причина, суть).

Позиционирование: **детерминированное нейро-символическое ядро верификации и безопасного исполнения для ИИ-систем**. Каждое решение — проверяемая булева цепочка. Этические и доменные ограничения неизменяемы на уровне FROZEN-слоя и формально верифицируемы.

Три продуктовые линии из одного ядра:
1. **MATRIX Guardrail** — слой верификации для LLM-систем: LLM генерирует план/ответ → булево ядро + SAT/BDD проверяет соответствие аксиомам, доменным ограничениям и фактам → StructuralSafetyGuard решает: выполнить / запросить человека / отклонить.
2. **MATRIX Safety Core** — детерминированный контроллер safety-critical ниш (SCADA): наносекундные решения TT-форм, полная аудируемость, FPGA-компиляция (LUT FPGA = таблица истинности, совпадение 1:1).
3. **MATRIX Knowledge Stack** — булев слой точной верификации и нормативного поиска поверх источников знаний: локальной памяти (DESIGN-05) или внешнего retrieval-сервиса по контракту (DESIGN-03 §6).

**Ключевой принцип устойчивости:** всё выше Boolean Compute Layer зависит только от контракта `evaluate(BIR, bits) → bits` и верификационных сервисов — не от формы примитивов и не от субстрата. Замена субстрата (JVM→FPGA→квантовый) = новый backend; замена механизма обучения = новый producer; формы компилируются друг в друга. Ничего выше слоя при таких заменах не переписывается.

**Почему три формы (таблица: слабости покрываются взаимно):**

| Форма | Арность | Сильная сторона | Слабость |
|---|---|---|---|
| TT (таблица истинности) | k ≤ 20 | каноническая семантика, наносекундный SIMD-eval, LUT-маппинг | память 2^k, слепота к структуре |
| CLAUSESET (клаузы Цетлина) | не ограничена (дефолт ≤4096 литералов) | сжатие разреженных функций, встроенное обучение (автоматы), интерпретируемые правила, индустриально доказанный FPGA on-chip training | не канонична |
| BDD (решающая диаграмма) | практически не ограничена | канонична → **точная** проверка эквивалентности; сжатие | взрыв на отдельных классах функций |

## 2. Внешние зависимости (включая rag-system)

Зафиксировано в `docs/engineering/ADR-001-matrix-vs-rag-system-roles.md` и `docs/design/DESIGN-03-pipeline.md` §6. Кратко: rag-system — **внешний, независимо развиваемый проект**; MATRIX использует его как retrieval-сервис по REST/MCP-контракту и заимствует его принципы (гибридный поиск, реранк, grounding на цитатах), но не разделяет с ним код, данные и рантайм. Ядро MATRIX работает без rag-system (деградация до локального булева recall, DESIGN-05 §3). Ниша булева слоя внутри MATRIX — exact-match, верификация цитат, нормативный точный поиск, BRC-witness.

**Алгоритмическая детализация всех слоёв этой карты — в `docs/design/DESIGN-01…05`** (единица → композиция/персоны → контур запроса → обучение → память).

## 3. Ключевые контуры

### 3.1. Developmental Loop (SPEC-000)
Curriculum engine: оценка компетентности на верифицируемых задачах → выбор задач из зоны ближайшего развития (максимум learning progress) → диагностическая обратная связь (контрпример + BRC-объяснение, не скаляр) → затухание поддержки по объявленному расписанию → открытие permissions через MA-гейты. Потребляет BIR-артефакты, не зависит от формы и producer'а.

### 3.2. Agent Loop
Planner → Reasoner → **Judge** (формальная фаза: BDD-эквивалентность + SAT/SMT + FROZEN-фильтры + session-level анализ) → Generator → Act. MCTS имеет смысл только поверх World Model (предиктор «состояние+действие → следующее состояние», обучаемый на журналах Kafka).

### 3.3. Memory / консолидация
Паттерн «гиппокамп → неокортекс»: циклы «сна» — реплей эпизодов из Event Sourcing → сжатие в паттерны/навыки (CLAUSESET-формы, Skill Library) → удаление сырья. Φ консолидации — MDL-рачет (принимать сжатие только при уменьшении суммарной длины описания). Честная формулировка: «консолидирует суть, забывает сырьё». Drift detection + Ricci-fingerprint (SPEC-003) как ранние детекторы деградации.

### 3.4. Noosphere — четыре слоя решения

1. **Governance (по Элинор Остром, 8 принципов управления общим ресурсом):** ясные границы участия (уровень MA-4+); правила адаптированы к локальному контексту узла; коллективное участие в изменении правил (RFC); мониторинг участниками (взаимный аудит BRC-цепочек); graduated sanctions (CONSTITUTION IV.4); доступный арбитраж (византийский консенсус); признание права самоорганизации (P2P без центра); вложенность (узел → кластер → сеть).
2. **Доверие (по Никласу Луману — доверие как редукция сложности):** проверка чужого инстанса сводится к проверке подписи — lineage ledger (causal-ancestry граф) + genesis-check (CONSTITUTION V); перспективно — статистическая доказуемость происхождения дистиллированных артефактов (гипотеза H-008).
3. **Транспорт:** gossip для рутинного обмена; CRDT (G-set/OR-set — знания, PN-counter — кредиты; strong eventual consistency без координации); византийский консенсус только для критических решений (кредиты, genesis, изменение конституции).
4. **Устойчивость знания (предел Эйгена + гиперцикл):** размер пакета знаний ограничен верностью канала (L_max ≈ 1/μ); пакеты передаются с ECC и поэтапной верификацией; совокупное знание устойчиво как сеть взаимно проверяющих узлов (гиперцикл), а не как единый «длинный геном»; кластер зрел, если его сеть знаний замкнута и самоподдерживающа (проверка инструментарием SPEC-003). CreditModel анализируется на совместимость стимулов; red-team сговора — эксперимент EXP-006.

## 4. Уровни зрелости (MA)

| Уровень | Аналог развития (Пиаже) | Возможности | Гейт перехода (preregistered EXP) |
|---|---|---|---|
| MA-0 | сенсомоторный (наблюдение) | shadow-режим: предсказания без действий | fidelity предсказаний ≥ порога на эталонном наборе |
| MA-1 | дооперационный (игра) | действия в песочнице (Minecraft, сим-SCADA) | этюдный набор пройден; 0 нарушений конституции за N эпизодов |
| MA-2 | конкретных операций | действия в реальной среде, каждое подтверждает человек | стабильность метрик на скользящем окне; аудит BRC |
| MA-3 | раннеформальных | автономия в одном сертифицированном домене + пост-аудит | доменная сертификация; контрфактические стресс-тесты |
| MA-4 | формальных операций | полноправный узел Noosphere | Byzantine-репутация ≥ порога; эксплуатационная история |
| MA-5 | наставник | право обучать клоны (teacher), инициировать клонирование | решение оператора + консенсус узлов + genesis-check |

Понижение — автоматическое (drift/нарушения); повышение — только с человеком. Шаблон гейтов — фазы клинических испытаний: безопасность на малом (фаза I ≈ MA-1), эффективность под наблюдением (II ≈ MA-2), подтверждение (III ≈ MA-3), пост-регистрационный надзор (IV ≈ MA-4/5).

## 5. Обучение не с нуля (инициализация культурой)

Teacher (открытые веса LLM) → дистилляция по активациям (SPEC-001) → BIR-артефакты → Developmental Loop продолжает обучение на данных среды. Дистилляция — инициализация (аналог дошкольного воспитания), не метод существования. Teacher работает только офлайн (детерминизм рантайма сохраняется). Родословная каждого артефакта фиксируется в заголовке BIR (provenance).

## 7. Нефункциональные требования

- Latency по формам BIR — JMH-измерение и публикация; заявления без измерений запрещены (CONSTITUTION VI).
- Стоимость вычислений (токены teacher, CPU/GPU-часы) — метрика первого класса (research/METRICS.md); бюджет — обязательное поле EXP-карточки.
- Воспроизводимость: любой бенчмарк запускается одной командой из чистого клона.
- Квантовая готовность (измерительная, не обещательная): доля BIR-артефактов с bond dimension χ ≤ 64 при MPS-конверсии — публикуемый показатель.
