# ADR-001: rag-system как внешняя зависимость MATRIX

**Статус: accepted** · Заменяет все прежние представления о «консолидации» двух проектов. Обязателен для разработчиков и агентов.

## Контекст

**rag-system** — отдельный, независимо развиваемый проект владельца: RAG-платформа (приём документов, эмбеддинги, гибридный поиск BM25 + векторный + графовый (Neo4j), генерация ответов с цитатами). **MATRIX** (этот репозиторий) — детерминированное булево ядро верификации и безопасного исполнения.

Ранее границы размывались: в MATRIX существовал собственный retrieval-модуль (`rag/HybridBooleanRag.java`), планировалась «консолидация» стеков. Дублирование функций в двух рантаймах — источник рассинхрона, двойной верификации и конфликтов статусов. Слияние кодовых баз при этом нежелательно: разные темпы развития, аудитории и требования к развёртыванию.

## Решение

**rag-system — внешний сервис по отношению к MATRIX. Никакой консолидации кодовых баз.**

1. **Заимствуются принципы, не код.** Из rag-system заимствуются как проверенные инженерные принципы: гибридный поиск (лексический + семантический + графовый сигналы), обязательный реранк, grounding ответов на цитированных фрагментах, метрики retrieval-качества (Recall@k, citation precision, faithfulness — они же в `docs/research/METRICS.md`).
2. **Использование — только по контракту.** Если rag-system развёрнут и доступен, MATRIX вызывает его как retrieval-сервис через REST/MCP-контракт (DESIGN-03 §5.2): запрос → фрагменты с цитатами. Контракт версионируется; интеграционные тесты — через Testcontainers-мок, не через живой rag-system.
3. **Ядро автономно.** MATRIX полностью работает без rag-system: булев recall локальной памяти (DESIGN-05 §3) покрывает exact-match, верификацию цитат, нормативный поиск и BRC-witness. Недоступность rag-system = режим `DEGRADED` в трейсе, не отказ (DESIGN-03 §6).
4. **Не разделяются:** код, данные, индексы, граф знаний, рантайм, CI, релизные циклы. Никаких импортов исходников или зависимостей сборки в любую сторону.
5. **Собственный модуль `rag/HybridBooleanRag.java`** в MATRIX рефакторится в verifier-компонент булева слоя (exact-match + верификация выдачи любого retrieval-источника); retrieval-часть делегируется настроенному источнику (локальному или внешнему) — это устраняет пропуск эмбеддинга в нет-LLM конфигурации (H-007).

## Последствия

- (+) Одна кодовая база верификации — один контур аудита; rag-system сохраняет независимость развития.
- (+) Контрактный интерфейс позволяет подменить retrieval-провайдера (другой сервис, локальный индекс) без изменения ядра.
- (−) Сетевая граница — latency на внешнем retrieval; митигация: co-deployment, локальный транспорт, режим деградации.
- Ограничение: никаких «временных» прямых зависимостей «потом выпилим» — любая интеграция только через контракт (проверяется ArchUnit: пакеты MATRIX не импортируют пакеты rag-system).

## Альтернативы (отклонены)

- **Слияние репозиториев:** разные темпы и аудитории; монолит усложнил бы пилоты обеих систем.
- **Глубокая консолидация (общий фасад с разделёнными внутренностями):** сохраняет двойную верификацию и рассинхрон статусов при видимости единства.
- **Полный отказ от rag-system:** теряется зрелый retrieval-стек и принципы, доказавшие ценность на данных владельца.
