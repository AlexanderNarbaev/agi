# DESIGN-08: Федерация, локальные инференсы, безопасность протоколов

Статус: proposed · Связи: DESIGN-07 (жизненный цикл, Operator, FederatedPeer CRD),
DESIGN-05 (память, M4-гейты, tombstone), JAVA_NATIVE (эдж-профили),
GOALS-REQUIREMENTS (G-E локальный инференс, G-F федерация, NFR-08 приватность,
NFR-09 переносимость)

---

## 1. Модель федерации

Система глобальна, но вычислительно локальна. Каждый узел (Node) — автономный
инференс-контур; глобальность возникает из двух и только двух каналов обмена:

1. **Вверх (в общий пул знаний):** обезличенные артефакты обучения — кандидаты
   в нейроны (BirNet-пакеты), метрики селекции Φ, статистика согласия.
2. **Вниз (из пула):** свежие нейроны (BirNet-пакеты, прошедшие Φ-гейт и
   аудит пула) для импорта в локальную Persona через M4-гейты.

Прямой обмен между пользовательскими узлами в базовой конфигурации отсутствует.
Пул знаний (Noosphere-сервис) — посредник, и он же точка аудита.

**Инвариант INV-F1 (конфиденциальность):** сырые пользовательские данные,
короткосрочный контекст M1 и долгосрочные слепки M3 никогда не покидают узел.
В пул уходят только производные структуры: булевы таблицы/клаузы + агрегированные
счётчики. Это цифровой аналог tombstone-политики DESIGN-05.

**Инвариант INV-F2 (детерминированный импорт):** импорт свежего нейрона =
регистрация BirNet-пакета с фиксированным id+hash. Два узла, импортировавшие
один пакет, получают бит-в-бит одинаковый элемент. Детерминизм BIR делает
федеративное распространение эквивалентным копированию файла — без дрейфа весов.

## 2. Профили локального инференса (эдж)

| Профиль | Устройство | Состав | Ограничения |
|---|---|---|---|
| EDGE-0 | ноутбук/десктоп | полный контур: модульная шина, BRC, память M1–M3, Cauldron, сон | эталонный профиль |
| EDGE-1 | смартфон/планшет | GraalVM native, off-heap ≤ 512 МБ, сон по расписанию ОС, Cauldron в урезанном окне | фоновые лимиты ОС; proactive-активность по бюджету батареи |
| EDGE-2 | очки/носимые | только PERCEPTION→ReflexLayer→RENDERING + микро-BRC; глубокая дельберация делегируется на EDGE-0/1 того же владельца | задержка < 20 мс, энергия < 1 Вт |
| EDGE-3 (перспектива) | имплант | не реализуется в текущем горизонте; архитектурно зарезервирован профиль с аппаратной аттестацией и жёстким энерго-лимитом | медицинская сертификация вне скоупа проекта |

Общие правила эджа:
- один и тот же BIR-артефакт (Avro-пакет) исполняется на всех профилях без
  перекомпиляции — переносимость обеспечивается булевой природой данных (NFR-09);
- на EDGE-1/2 кластеры сворачиваются до подмножества доменов; маршрутизация
  указывает, какие домены локальны, какие делегированы;
- делегирование между своими устройствами идёт по тому же защищённому протоколу,
  что и межэлементный обмен (§3) — «свой» EDGE-0 для EDGE-2 это просто ещё один
  элемент федерации.

## 3. Криптография межэлементного протокола (anti-MitM, anti-tamper)

Угроза: перехват и подмена сообщений между элементами (модули, кластеры, узлы,
пул). Булева природа payload делает подмену особенно опасной: один бит меняет
смысл.

**Протокол ELSP (Element Link Security Profile), минимальный профиль v1:**

1. **Идентичность.** У каждого элемента — пара ключей Ed25519, идентификатор
   `element_id = SHA-256(pubkey)[0:16]`. Ключи генерируются при рождении элемента
   (Cauldron) и заносятся в lineage.
2. **Подпись.** Каждое сообщение подписано: `sig = Ed25519_sign(header ‖ payload)`,
   header = {element_id, version, monotonic_seq, schema_hash}. Проверка подписи
   обязательна до любой интерпретации payload.
3. **Анти-replay.** `monotonic_seq` на пару (sender, receiver); приёмник хранит
   последний принятый seq и отбрасывает ≤ него. Внутри процесса (monolith) seq
   заменяется ссылочной идентичностью объектов.
4. **Шифрование канала.** Межпроцессный/межсетевой транспорт — TLS 1.3 с
   взаимной аутентификацией (mTLS) по element-сертификатам; внутрипроцессный —
   подписи без шифрования (нулевая стоимость копирования).
5. **Ротация.** Ключи ротируются при смене версии мажорной и по таймеру; старый
   ключ подписывает новый (цепочка доверия в lineage).
6. **Аттестация пула.** Пакеты свежих нейронов из пула подписаны ключом пула;
   узел принимает пакет только при валидной подписи и совпадении hash с
   манифестом.

Открытый вопрос (исследование): постквантовые подписи (Dilithium) как профиль v2 —
стоимость на булевых пакетах мала, но размер подписи сопоставим с самим пакетом.

## 4. Телеметрия и обезличенный экспорт в пул

**Что экспортируется (whitelist, расширение только через PR + аудит):**
- BirNet-пакеты кандидатов (таблицы/клаузы) + метаданные селекции (Φ-score,
  энергия, домен, версия схемы);
- агрегированные счётчики: частоты срабатывания клауз, гистограммы задержек,
  доли refusal;
- сводки согласия Viewpoint (скаляры).

**Что не экспортируется никогда:** сырые входы, текст/аудио/видео пользователя,
идентификаторы сессий, любые bitMeaning-привязки к личному словарю.

**Механизм анонимизации:**
- k-анонимность: доменная статистика экспортируется, только если в окне
  агрегации ≥ k=100 независимых событий; иначе накапливается;
- дифференциальный шум на счётчиках (ε, δ)-бюджет на узел, учёт в ledger;
- экспорт — отдельный изолированный элемент (Exporter) без доступа к M1/M3
  (INV-TC-подобный: читает только whitelist-источники);
- экспорт подписан ключом узла, но пул обязан отбросить идентификатор после
  проверки подлинности (аутентификация без идентификации: подпись доказывает
  «настоящий участник федерации», не «кто именно»; реализация — через
  анонимные креденшелы / group signatures в v2).

**Честная граница:** k-анонимность + DP снижают, но не обнуляют риск
ре-идентификации по паттернам булевых таблиц. Перед включением экспорта по
умолчанию требуется эксперимент (гипотеза H-013) с измерением utility/privacy
компромисса. По умолчанию экспорт выключен (opt-in).

## 5. Распространение свежих нейронов (импорт)

1. Пул публикует манифест: список {net_id, hash, Φ-score, домены, schema_version},
   подписанный ключом пула.
2. Узел периодически (или в фазе сна) тянет манифест, отбирает пакеты по доменам
   и политике (минимальный Φ, совместимость schema).
3. Импорт = M4-гейт (DESIGN-05): карантин → теневой прогон на локальном
   бенчмарке узла → принятие/отклонение. Импортированный нейрон никогда не
   попадает в активный роутинг минуя карантин.
4. Конфликт-резолюция: если импортированный BirNet перекрывает существующий
   домен, решение принимает Viewpoint голосованием; слияние весов запрещено
   (правило иерархии) — только замена целого элемента или коэкзистенция как
   отдельный Viewpoint.

## 6. Связь с Operator (DESIGN-07 §7)

- CRD `FederatedPeer` описывает пул/соседний узел: endpoint, pubkey,
  политики экспорта/импорта, DP-бюджет.
- Экспорт/импорт — отдельные поды (stateless), подлежат тем же
  readiness-правилам (реестр заморожен, hash совпал).
- ConsolidationWindow (сон) — рекомендуемое окно для фонового импорта:
  роутинг снят, своп атомарен.

## 7. Приёмочные тесты

| Тест | Критерий |
|---|---|
| AT-F1 подмена | пакет с 1 инвертированным битом payload отвергается на проверке подписи, 100% |
| AT-F2 replay | повтор валидного пакета со старым seq отбрасывается |
| AT-F3 конфиденциальность | статический аудит кода Exporter: нет чтения M1/M3 (граф зависимостей) |
| AT-F4 k-анонимность | при <100 событиях в окне экспорт домена не происходит |
| AT-F5 детерминированный импорт | два узла после импорта одного пакета дают бит-в-бит равные выводы на 10⁶ случайных входах |
| AT-F6 карантин | импортированный нейрон не влияет на роутинг до прохождения M4-гейта |
