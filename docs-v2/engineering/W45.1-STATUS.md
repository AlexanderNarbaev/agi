## 2. What was completed

### Priority A — the disposition survives a repeated observation

*(see `W45.1-DISPOSITION-LIFECYCLE.md` for the full account)*

- The `INSERT OR REPLACE` that could reset an adjudicated disposition is gone. The defect was
  **reproduced against the pre-fix code**: the same program, run against the previous commit's
  `KnowledgeStore` and against this one, resets the adjudication in the first and keeps it in
  the second.
- The knowledge schema is **v17 → v18**, additively: two new tables
  (`observation_occurrence`, `observation_adjudication`) and four indexes; **no existing table
  changes shape**.
- The current disposition is a **projection** of the **append-only adjudication history**, and
  `rebuildDispositionProjection` recomputes it and reports whether it agreed.
- A re-observation **never adjudicates**: it adds an occurrence and leaves the decision alone.
- The canonical case identity and the observation occurrence identity are separate: two
  independent observations of the same fact are two occurrences and two sources of evidence.
- `ObservationDisposition` now distinguishes `awaitingAdjudication()` (only `UNRESOLVED`) from
  `terminallyExcluded()` (only `REJECTED`), and the review queue asks the first, so a
  terminal rejection is never treated as pending review.
- `MicroWorldSession.dispositionOf()` now returns a **reviewed** disposition instead of
  collapsing it — a restored observation that a review accepted is `ACCEPTED`, not `ELIGIBLE`.

### Priority B — the request survives process death

- **The request lifecycle is an explicit state machine** (`RequestExecutionState`), with the
  rule that a request may be executed again only from a state that proves nothing was written.
- **The claim allocates the identities** — the request id, the signal id, the episode id, the
  arrival number — and stores them, so a retry continues the SAME logical execution and never
  gets a second episode.
- **The owner is asked whether it is alive** (`OwnershipToken`): the pid, the start instant of
  the process and an instance token. A dead owner's request is recovered; a live owner's
  request is not stolen.
- **The mapping is never deleted.** A failure is recorded with the classification that says
  whether the work may be repeated.
- **The completion is fenced** by the owner: a process that lost the request cannot complete
  it.
- The lifecycle history is append-only (`cognitive_request_event`).

### Priority C — a failed cycle has a truthful terminal state

- A runtime failure inside the cycle is caught, written into the trace as a `FAILURE` step, and
  the episode is **closed**. Before W45.1 the episode stayed open and the store said the cycle
  was still running.
- The outcome is `FAILED` — never converted into a normal answer — and it is durable and
  replayable.
- The HTTP surface maps it to `500`; a timeout maps to `503`.

### Priority D — the legacy v16 semantics, verified

*(see `W45.1-LEGACY-DISPOSITION-REPORT.md`)*

**The W45.0 backfill was wrong for one class of records, and the correction is in this wave.**
The W45.0 rule classified a legacy record from the EVIDENCE RELATION alone. The W44 code
shows that `CONTRADICTS` means "no surviving hypothesis explains the observation" — not "the
observation disagrees with a belief". So the W45.0 rule held every unexplained observation,
which is the **obsolete W44 rule** preserved inside the migration: the live kernel applies
such an observation, and the restored session held it. That is exactly the class of defect
W45.0 exists to fix.

The corrected rule consults the cognitive error records — a disagreement with a **unanimous**
prediction is a conflict with a belief; everything else is learning — and falls back to the
relation only when those records are absent. The v16 fixture confirms all six combinations.

### Priority E — a real `SIGKILL`

`scripts/w45-cognitive-recovery-journey.sh` — **37 checks, 0 failed, exit code 0**, with
three real `SIGKILL`s of separate JVMs (each confirmed by the exit status 137 = 128+9), each
against its own disposable database, on its own port, in its own directory.

| the scenario | the failpoint | the result |
|---|---|---|
| A | `OBSERVATION_COMMITTED` | the retry is refused with **409 `INDETERMINATE`**; the case, the occurrence, the evidence and the predictions are **exactly as many as before the kill** |
| B | `CLAIMED` | the retry **executes the request again, in the SAME episode**; one episode, one case, one occurrence |
| C | `IDEMPOTENCY_COMPLETED` | the retry answers **200** with the original outcome; no second episode, no second prediction, no second case |

No request is left silently in `IN_PROGRESS`, and the lifecycle history explains every
transition.

## 4. The unresolved items

| what | why |
|---|---|
| the **finalisation is not one transaction** | the trace, the episode close, the outcome snapshot and the idempotency completion are separate writes. A crash between them leaves the request `INTERRUPTED_PARTIAL`, and the outcome is **not** reconstructed from the trace — an outcome that cannot be established is not invented. Making them one transaction would mean a transaction across the two store abstractions, which the directive rules out. |
| the **liveness check is local** | a writer in another container or on another host would not be visible, and its claim would be wrongly considered dead. The supported topology is one writer process per database file, and the rule "when the liveness cannot be disproved, the claim is treated as owned" keeps the failure mode safe inside it. |
| a **hung** process is not recovered | a request whose owner is alive is never recovered: the work must not be stolen. The cost is that a hang stays claimed until the process dies. |
| the **destructive workspace reload** | unchanged, as the directive requires. It remains the highest-severity open item: it can delete the epistemic history that W45.0 made durable and that W45.1 makes auditable. It is an owner decision. |
| the **three architecture decisions** | unchanged, documented in `W45-OWNER-DECISIONS.md`, not enacted. |
| the **in-sample validation domain** | unchanged from W45.0: nothing is promoted, and the fast path remains an in-sample derived shortcut. |
