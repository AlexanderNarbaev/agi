### 2.1 The chain isolation gate

from the constant pool (`javap -p -c`), not by a textual search, because a textual search
mistakes a mention for a call.

| the universe | **2908 classes, 76 815 resolved edges** (`matrix-core` 2621, `matrix-brain-runtime` 208, `matrix-api-gateway` 67, `matrix-audit` 12) |

| reached from chain B: the classes that NAME the epistemic database | **0** |
| reached from chain B: the classes that serve the chain A surface | **0** |

### 2.2 The process-kill journey, re-run under the new single-writer guard

The W45.1 harness was re-run after the guard was added, because the guard changes who may
open the database file — and a killed process leaves its lock file behind.

| the scenario | before the kill | after the retry |
|---|---|---|
| A — killed at `OBSERVATION_COMMITTED` | 1 episode / 1 case / 1 occurrence / 2 predictions, `IN_PROGRESS` | the same counts, `INTERRUPTED_PARTIAL`, **HTTP 409 `INDETERMINATE`** |
| B — killed at `CLAIMED` | 0 episodes, `IN_PROGRESS@CLAIMED` | 1 episode, **HTTP 200** — the same episode |
| C — killed at `IDEMPOTENCY_COMPLETED` | `COMPLETED` | **HTTP 200**, the original outcome, no second episode |

**37 checks, 0 failed, exit 0.** The three kills are confirmed by the exit status 137 =
128+9. **The lock left behind by the killed process did not block the restart** — which is
the behaviour the guard had to have.

### The single-writer guard — 8 tests

`io.matrix.cognitive.CognitiveWriterLockTest`:

| the test | what it proves |
|---|---|
| a second store of the **same process** joins the writer it already holds | the contract is one writer **process**: the cognitive store and the epistemic store open the same file, and both belong to one process |
| a store on a different file is unaffected | the guard is scoped to the file |
| the holder closes → the lock file is gone → the file opens again | the lock is released on a normal close |
| a lock left behind by a **dead** owner does not block | a killed process does not lock the database forever |
| a lock held by a **live** owner blocks | a live owner is never displaced |
| **a second real PROCESS is refused** | the decision itself, proved with a second JVM rather than an in-process simulation |
| a killed writer leaves the lock file behind with its dead pid, and the next writer takes it over | the crash path |
| a store opened without the guard says so | the escape hatch is loud |

### The workspace snapshot — 23 tests

`io.matrix.knowledge.WorkspaceSnapshotTest` (12), `WorkspaceSnapshotMigrationTest` (4),
`WorkspaceLoadEndpointTest` (7):

- a load into an **empty** workspace works without the flag;
- a load into a **non-empty** workspace **without** the flag is **refused** and **nothing is
  deleted** — the contradiction, the evidence and the revision rows are all still there;
- a load **with** the flag takes a snapshot first, and the snapshot holds what the workspace
  held;
- restoring brings the workspace back, **including the contradiction and the revision rows**;
- the snapshot is inspectable without being restored;
- a snapshot exists for every destructive load, and restoring snapshots what it replaced;
- the migration from v18, from a fresh database, and after an interruption;
- two concurrent loads of the same workspace cannot interleave into a state without a snapshot.

## 5. The tests the wave could not write

| what | why |
|---|---|
| a test that a **second host** is refused | the guard's protection against another host depends on the shared filesystem's locking. A test would prove the filesystem, not the code. The limit is documented in the design, not hidden. |
| a test that the **whole HTTP surface** of chain B is free of chain A routes | the runtime part probes three representative chain A routes; the **route census** covers the surface statically. A fuzzing harness would be a different kind of evidence. |
| a test that a **reflection, JNI or native-image** crossing is impossible | the constant pool does not resolve those. The limit is documented in `W45.2-CHAIN-BOUNDARY.md` §5. |
| a test that the **legacy in-process load** refuses | it cannot: `KnowledgeWorkbenchTest.reloadingIsIdempotent` loads the package three times into one workspace, and the owner's decision requires a refusal on the second. The HTTP surface — the door the owner named — does refuse, and that is tested. |
| a test of the **snapshot payload's size** | there is no limit to test; it is a JSON of the whole workspace. |
