# W45.2 — THE OWNER'S ARCHITECTURE DECISIONS

**Status:** decided. **Date:** 2026-11-04.
**Origin:** the owner's questionnaire, taken after RECON-W44.0 §2.20 and the W45.0/W45.1 waves
had left the questions open.

---

## 0. How the decision was taken, and what changed

The questions were put to the owner as a questionnaire with every option the evidence
supported. **The first answer chose the heavier options**: `TrueMindCycle` as a global
conductor, an authenticated write bridge between the chains, and a non-destructive reload by
versioning. The owner then **re-answered**, and took the recommended option on all four
questions.

**This document records the re-answer, which is the decision.** The first answer is recorded
here too, because a decision that was taken, changed and taken again is part of the
architecture's history, and because the difference between the two answers is the difference
between a refactor and a boundary.

| the question | the first answer | the decision (re-answered) |
|---|---|---|
| the canonical conductor | `TrueMindCycle` is the conductor | **name the canonical entry point per application; keep the five cycles** |
| the chain B boundary | an authenticated write bridge | **keep the two chains isolated and fail closed** |
| the destructive reload | non-destructive by versioning | **fail closed, with a recoverable snapshot** |
| the recovery topology | (the same answer) | **one writer per database, enforced and documented** |

## Decision 1 — the canonical entry point per serving application

### The evidence

RECON-W44.0's bytecode archaeology found **five** coexisting cycles, none delegating to the
others, and **two** serving chains that do not meet. `BrainLoopService` has 25 production
callers — all inside `io.matrix.consciousness`, a package of 297 types of which **11** are
served, so the count measures the package and not a serving path. The ADR that named
`TrueMindCycle` the conductor was scoped to `matrix-brain-runtime` and `matrix-api-gateway`;
read next to the W44 ADR it read as if one cycle governed the whole system, which the compiled
code contradicts.

### The decision

**The five cycles are kept, each with its distinct responsibility. Each serving application
names its canonical entry point. Nothing is merged and no global conductor is declared.**

| the application | the canonical entry point | the routes | the cycles it runs |
|---|---|---|---|
| the epistemic and workbench application | `io.matrix.knowledge.LearningWorkbenchResource` | `/v1/workbench/**` | `io.matrix.cognitive.CognitiveKernel` |
| | `io.matrix.api.OpenAIChatResource` | `/v1/chat/completions` | `io.matrix.reasoning.BrainLoopService` |
| the brain runtime | `io.matrix.api.MinimalHttpServer` | `POST /v1/analyze` | `io.matrix.brain.runtime.TrueMindCycle` |

**The full contract, the costs and the limits:** `ADR-W45.2-01-canonical-entry-point.md`.
**The implementation:** `io.matrix.api.CanonicalEntryPoint`, checked by
`CanonicalEntryPointTest` and `CanonicalEntryPointChainBTest`.

### What it does not do

It does not merge the cycles, does not create a sixth cycle or a framework, does not revive
the measurement cluster, and does not join the two chains — Decision 2 keeps them apart.

## Decision 2 — the two chains stay isolated and fail closed

### The evidence

The two chains do not meet: there is no call between the brain runtime and the epistemic
store. The brain runtime's world model is a persistent HDC plus an episodic log; the
epistemic application's is the knowledge store's claims and cases. The gateway's own JAX-RS
facade is **unmounted** and constructs a **stub** cycle — it is not the brain runtime, and
the decision must not confuse the two.

### The decision

**No bridge. No implicit write path. No automatic trust. No new network surface. Chain B
cannot alter claims, confidence, goals or safety policy.**

The isolation is **proved**, not asserted: a gate resolves the compiled call edges from the
chain B entry points and shows that no class reachable from them references the epistemic or
the cognitive store.

**The contract for any FUTURE bridge** — written down now so that a later wave does not invent
it — requires a bridge to be:

1. **explicit and versioned** — a named, versioned contract, not an implicit path;
2. **authenticated** — the caller identifies itself and is refused without a credential;
3. **provenance-carrying** — every record it writes says which chain, which run and which
   actor produced it;
4. **bounded by a safety boundary of its own** — the brain runtime may not alter claims,
   confidence, goals or safety policy; it may propose, and a separate authority decides;
5. **fail-closed** — an error, a timeout or an unrecognised version stops the write rather
   than falling back to a default;
6. **audited and replayable** — every write is a record with a stable id, so a replay cannot
   duplicate it and an audit can explain it.

**The full contract and the honest limits of the proof:** `W45.2-CHAIN-BOUNDARY.md`.
**The implementation:** `scripts/w45-chain-isolation-check.sh`.

### What it does not do

It does not add a bridge, does not grant chain B access to the epistemic store, and does not
expose a new network surface. The two applications remain separate systems.

## Decision 3 — the destructive workspace reload fails closed and leaves a snapshot

### The evidence

`POST /v1/workbench/workspaces/{id}/load` calls `KnowledgeStore.importWorkspace`, which runs
`deleteWorkspace` **inside the same transaction** as the insert. That deletes the rows of
eleven tables for the workspace — including `contradiction`, `evidence` and `revision` — plus
the workspace row and two link tables.

So the endpoint **silently erases the contradiction history, the evidence and the revisions**
of the workspace it replaces. W45.0 made the observation dispositions durable and W45.1 made
the adjudication history auditable; this endpoint deletes both, without asking.

### The decision

**The load refuses to replace a non-empty workspace unless the caller explicitly asks for it,
and it takes a recoverable snapshot before the replacement. The contradiction history is never
silently erased.**

The contract:

| the call | what happens |
|---|---|
| the workspace is **empty**, no flag | the load proceeds; a first load is not a replacement |
| the workspace is **non-empty**, no flag | the load is **REFUSED** with an error that names the flag the caller must send; **nothing is deleted** |
| the workspace is **non-empty**, the explicit flag | a snapshot is taken **in the same transaction** as the replacement, and the response carries the snapshot's id so the caller can restore it |

Restoring is an explicit operation, and it is as safe as the load: restoring replaces the
current workspace, so it takes a snapshot of what it replaces — unless the current workspace is
empty.

### What it does not do

It does not remove the capability to replace a workspace — the owner chose "fail closed with
a snapshot", not "never replace" — and it does not version every read of a workspace, which
the "non-destructive by versioning" option would have required.

## Decision 4 — one writer per database, enforced and documented

### The evidence

W45.1's recovery asks the operating system whether the owner of a claim is alive: the pid,
the **start instant** of the process and an instance token. Its safety margin is deliberate —
**when the liveness of an owner cannot be disproved, the claim is treated as OWNED**, because
a claim wrongly considered alive is visible while one wrongly considered dead duplicates an
execution.

That rule is correct only for **one writer process per database file**. Until now that was an
assumption in prose: a second JVM opening the same SQLite file from another container or
another host would have a pid the first process cannot see, and its claims would be wrongly
considered dead.

### The decision

**A second process opening the same cognitive database is REFUSED at start-up. The topology
becomes a fact, not an assumption, and the contract says so.**

The guard is a lock file next to the database, holding the owner's pid, the start instant and
the instance token — a row in the database cannot work, because opening the database is
exactly what is being guarded. A lock left behind by a **killed** process does not block the
next one: the same primitives `OwnershipToken` already has tell a dead owner from a live one.

### What it does not do

It does not add leases, a fencing service, or multi-writer support. The owner chose the
single-writer enforcement over multi-writer leases deliberately; the W45.1 fencing machinery
stays as it is, and the "cannot disprove → owned" rule keeps its meaning inside the enforced
topology.

## What the four decisions together say

**MATRIX is two local applications that do not meet, each with a named entry point, each
writing to its own store, each running its own loop(s) with a distinct responsibility — and a
knowledge base that cannot be silently rewritten by either of them.**

The waves before this one made the writes durable and the semantics honest. This wave makes
the **boundaries** explicit: which entry point serves which application, which chain may not
write to which store, which operation must ask before it destroys, and which process may
write to which file. None of it is a capability claim; all of it is a contract.
