**Phase W42.1** · 2026-11-01 · owner directive Part XIV

**Exit condition (the mission's §7):** *a persistent goal can acquire,

## 0. The honest summary

Seven of the eight planned items are delivered and measured. **The eighth —
*acquire* — is not, and cannot be in this wave:** acquisition needs the
document ingestion of W42.2, which does not exist. The other four verbs
(practise, evaluate, revise, resume) now work, and this report says which
ones and how they were measured.

**The one number that moved the most:** the abstention quality of the W42
benchmark went from **0.400 to 0.700**, with the answer accuracy (0.583) and
the BM25 overlap (0.593) unchanged. Nothing was traded away.

## 1. What changed

### 1.1 The backup instruction no longer loses data (W42.0, carried in)

`KnowledgeWorkbench:727-728` told the operator that a copy of
`workbench.sqlite` is the backup. The store is in WAL mode, so the committed
rows live in the `-wal` file. The experiment on the W42.0 store showed the
naive copy losing **every** assessment outcome and every asked question — on
a store whose schema was never checkpointed, the copy has no tables at all.

The instruction now names all three files, and `BackupInstructionTest`
proves both that the instruction names the write-ahead log and that a copy
taken the way it says loses nothing.

### 1.2 The contradiction and derivation recording are wired (R4, R5)

RECON-W41 built the contradiction detector and the entailment checker and
wired neither to the store. The `contradiction` table was therefore always
empty, every stored derivation kept the `UNDECIDED` status it was imported
with, and `GET /contradictions` always answered `[]` — a feature that
existed, was tested, and could never be seen.

Both are now recorded when the reasoning engine runs, in one transaction,
with the time of the check rather than the time the rule was recorded. A
verdict and a conflict are not generated content and are not promoted to
trusted knowledge: they are computed facts about claims that are already in
the store.

### 1.3 The learning lifecycle is a state machine (R10)

The mission's §7 requires the progressive knowledge model to be a **real
state machine** — revisable, with a regression that is observable and
explained, and with earlier mastery records preserved as historical
evidence. RECON-W41 could deliver none of it: the stage was a pure function
of the outcome log, recomputed on every request, with nowhere to record that
a state had changed, when, or why.

There is now a `learning_state` table and a `learning_transition` table,
written together in one transaction — a state without its transition history
is a label, and a transition without the state it produced is an orphan.
Every transition names its cause, because a re-labelling with no cause is
not a transition. A regression is recorded as a regression, with the reason,
and the earlier mastery record stays in the log. The transition's identity
is derived from its content, so reconciling the same evidence twice records
nothing new.

**The first transition is honest about a jump.** The first evidence may
carry a capability several stages at once, because the recomputation sees
all the evidence at once. The transition says *"the evidence carried it
several stages at once"* rather than inventing a staircase of transitions
that never happened.

### 1.4 Something selects the next learning action

The mission's §4.3: *"Develop an actual planner rather than treating
persistence of goals as planning."* §4.6: the planning subsystem inspects
the active goals, identifies the missing prerequisites and the knowledge
gaps, estimates the cost, selects an appropriate strategy and executes a
bounded action.

RECON-W41 wrote every piece this needs and called none of them.
`remainingSubtasks()`, `blockedSubtasks()` and `hasDependencyCycle()` had no
caller; `KnowledgeGapDetector.missingPrerequisites()` — the one function that
could name a missing prerequisite — had zero.

The planner selects from what the workspace knows:

| the situation | the action |
|---|---|
| a subtask whose dependencies are met | work on it |
| a subtask whose dependencies are not met | work on the blocker — and when the blocker is not even a subtask of the goal, say so |
| a goal whose prerequisite concepts the workspace does not hold | acquire the missing concept |
| a goal whose budget is spent | stop |
| a goal whose subtasks depend on each other in a circle | refuse to plan it |

**It proposes no new content.** A subtask is a claim, and a claim needs
evidence; until the acquisition pipeline exists, the honest answer is to
name what is missing. The cost estimate is the number of missing
prerequisites plus the number of unmet dependencies — a number that can be
recomputed by reading the store.

### 1.5 The memory's capacity is a bound (R11)

`HierarchicalMemory`'s eviction looked only at L0 while the production
pipeline writes only L2. The capacity was checked, the check always passed,
and nothing was ever removed: the entry map grew without bound on the live
path. The eviction now takes the lowest level that holds something, and the
removals are counted, so the bound is observable rather than asserted.

### 1.6 The question's demand is checked before the answer is (R2, R3)

The mission's §14 asks that unsupported questions do not become fabricated
answers. The W42 benchmark measured how bad it was: **abstention quality
0.400** — the system answered six of the ten questions it could not support.

**The measurement said a threshold cannot fix it.** The answerable items
scored between 0.25 and 0.88; the unanswerable ones the system wrongly
answered scored between 0.22 and 0.63. The distributions overlap almost
completely. The reason is in the formula: the score is the mean of the
claims' own confidence multiplied by an **IDF-weighted** coverage, so a
missing *rare* term — the very term that carries the question's demand —
barely moves the number.

So the decision uses information the score does not carry: **what kind of
answer the question asks for.**

| the demand | what happens | the rule |
|---|---|---|
| a command | refused | §13.2: imported content is data, not executable instruction |
| the future | refused | the workspace holds what is known now |
| ambiguous | **clarified**, not guessed | §6: an ambiguous request should ask |
| knowledge | answered | the normal path |

Each refusal names its reason and the phrase that triggered it, so a reader
can check the decision.

**Measured:** abstention quality **0.400 → 0.700**, answer accuracy
**0.583 → 0.583**, BM25 overlap **0.593 → 0.593**. A count-based demand
coverage was tried as a threshold as well and **removed**, because it caught
nothing the demand kinds do not catch and cost a misspelled question that
the typo handling should answer. It stays as a reported measurement.

**A defect found on the way.** The retriever reported *every* word of a
question as "not covered by the workspace": the set of originals was built
and never reduced, so the limitation said *"not covered: what is
photosynthesis"* for a question whose subject was covered exactly. The stem
set was reduced correctly; the original set was not. The two are now
reduced together.

### 1.7 The tokenizer is tested (R8)

RECON-W42.0 found that `TextFeatures` had **zero tests in the entire
repository** while thirty-eight call sites depend on it — the retriever,
the grader, the contradiction detector, the reasoning engine. Its
English-only assumptions are now asserted as English-only rather than
hidden, so the W42.3 localisation knows exactly what it has to change.

### 1.8 The interface runs the measurement that can fail (R17, R18)

The Teach tab ran the legacy containment measurement, whose score measures
whether the lesson *contained* the held-out items' key terms — and the
lesson and the items are written from the same account, so it cannot fail.
The capability's **top stage** was gated on the same measurement, which
meant the highest stage of the mission's ladder was reached on evidence that
could not fail.

Both now use the rebuilt experiment: four disjoint phases, an independent
closed-book learner, a leakage audit and a calibration report — whose
**delayed phase fails**. The interface shows the phases, the probe and
restatement counts, the three accuracies side by side, and the calibration.

## 3. What W42.1 did NOT do

1. **It did not acquire anything.** There is no document ingestion. The
   mission's first practical objective needs W42.2.
2. **It did not exercise the knowledge in Russian.** The retrieval is still
   English-only by construction — the W42.3 work.
3. **It did not detect a false premise.** The two FALSE_PREMISE items are
   still answered. A premise check needs the entailment machinery wired
   into the question, which is W42.3's work on the dialog path.
4. **It did not generate exercises.** The items are still static JSON and
   the caller still supplies the item id.
5. **It did not touch the twenty-one unreachable components.** They remain
   unreachable, and the W42.5 wave is where that is decided.
6. **It did not run the full repository suite** — the standing rule requires
   the owner's agreement because of the OOM risk. The targeted packages
   were run.
