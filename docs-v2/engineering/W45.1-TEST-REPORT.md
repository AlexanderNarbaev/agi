## 3. The process-kill evidence

### 3.1 How the evidence is produced

The application is started **six times** — one reachability probe, and one application plus one
restart per scenario — each from its own private directory, with its own disposable SQLite
database, on its own port:

```
( cd "<private dir>" && exec env QUARKUS_HTTP_PORT=<port> \
    java -Djava.io.tmpdir=<private dir>/tmp \
         -Dmatrix.auto-train.enabled=false \
         -Dmatrix.knowledge.path=<private dir>/knowledge.sqlite \
         [-Dw45.failpoint=<CHECKPOINT> -Dw45.failpoint.marker=<private dir>/failpoint.marker] \
         -jar matrix-core/build/quarkus-app/quarkus-run.jar ) &
```

| the decision | how it is made | why |
|---|---|---|
| the port | `socket.bind(("127.0.0.1", 0))` — the port is asked of the operating system | 8080 and 8180 are never used |
| the database | `-Dmatrix.knowledge.path=<private dir>/knowledge.sqlite` | the database of the owner is never opened |
| the working directory | `cd <private dir>` before the `exec` | the application writes its logs, its chain state and its memory files relative to it; nothing of the run lands in the repository |
| the scratch directory | `-Djava.io.tmpdir=<private dir>/tmp` | the native library the ONNX runtime extracts never lands in `/tmp` |
| readiness | `GET /q/health/live` must answer **200** | the *readiness* endpoint of this application also carries the check of the optional PostgreSQL datasource (`localhost:5433`), which this journey does not use; it answers 503 for that reason alone, so the liveness endpoint is the honest signal that the process serves HTTP |
| the kill | `kill -9 <pid>` of the **exact** pid the harness started, then `wait` | no `pkill`, no wildcard; the exit status of the child is the evidence that the death was a signal |
| the request | `POST /v1/cognitive/observe` with `{"assignment":"power=1,switch=0","idempotencyKey":"<key>"}` | the assignment names every variable of the micro-world |
| the cleanup | an `EXIT` trap that removes the private directory and the one pid it owns | nothing else is ever deleted |

### 3.2 Scenario A — the kill after the epistemic commit, before the idempotency completion

**The scenario the wave explicitly demands.** The failpoint is `OBSERVATION_COMMITTED`: the
observation is durably committed, and the request has not yet been completed.

| | before the kill | after the retry |
|---|---|---|
| episodes (total / of the request) | **1 / 1** | **1 / 1** |
| cases / occurrences / evidence | **1 / 1 / 1** | **1 / 1 / 1** |
| predictions of the episode | **2** | **2** |
| the idempotency state | `IN_PROGRESS` | `INTERRUPTED_PARTIAL` |
| the durable checkpoint | `OBSERVATION_COMMITTED` | `OBSERVATION_COMMITTED` |
| the retry | — | **HTTP 409** |

The body of the refusal, verbatim:

```json
{"state":"INDETERMINATE",
 "error":"the request with the idempotency key <key> was interrupted after it had already committed durable work (it had reached OBSERVATION_COMMITTED); its outcome cannot be established and the request will not be executed again"}
```

The lifecycle history explains it:

```
IN_PROGRESS      @CLAIMED             — the request was claimed
INTERRUPTED_PARTIAL @OBSERVATION_COMMITTED — the owner of the request is gone and the execution
                                  had reached OBSERVATION_COMMITTED; the outcome cannot be
                                  established and the request may not be repeated
```

**The contract holds:** nothing was duplicated, there is no second episode, the row is not left
in `IN_PROGRESS`, and the caller is told the truth.

### 3.3 Scenario B — the kill before anything durable was written

The failpoint is `CLAIMED`: the request is claimed and the identities are allocated, and nothing
else has been written.

The harness asserts the two things that matter:

```
OK  the retry ran in the SAME episode (ep-sig-665027bc-…)

```


**The request was executed again, in the same episode, and it did not become a second
request.**

### 3.5 What the journey does NOT prove

1. **A kill inside a write transaction.** The failpoint fires only at committed boundaries.
2. **A kill of a process whose owner is alive.** The claim is not stolen — that is the
   opposite property, and it is proved by the unit tests.
3. **A native-image run.** Every number is a JVM number.
4. **The epistemic restoration across a kill.** The journey exercises the request lifecycle;
   the restoration of the drives and of the dispositions across a process kill is proven at
   store-reopen level (`CognitiveRegulatoryPersistenceTest`,
   `CognitiveContradictionDurabilityTest`) and is **not** re-proven across a kill. The wave
   does not claim a test it did not run.

## 4. The JVM tests of the wave

### `CognitiveRequestLifecycleTest` — 9 tests

| test | what it proves |
|---|---|
| a request whose owner is gone and that wrote nothing may be executed again | the recovery branch, and the episode is kept |
| a request whose owner is gone after a durable effect is NOT executed again | the `INDETERMINATE` branch |
| the recovery of a dead request is recorded in the request history | the decision is inspectable |
| a process that lost the request cannot complete it | the fence |
| a failure after the observation was committed does not duplicate the observation | the case count does not grow on the retry |
| a failed cycle closes its episode instead of leaving it open | the terminal semantics, and the `FAILURE` step in the trace |
| a timeout is a terminal outcome that a retry replays | the timeout is replayable, with a stepped monotonic clock |
| the recovery closes the episode of a request that a dead process left open | the `INTERRUPTED` event |
| the request mapping of a failed request is never deleted | the mapping survives |

## 4b. The schema migrations, and how each was proved

| the migration | what it adds | how it is proved |
|---|---|---|
| **knowledge v16 → v17** | the observation disposition table | `ObservationLegacyBackfillTest` — a **hand-written v16 database** with six cases covering every combination, and the knowledge-only fallback |
| **knowledge v17 → v18** | `observation_occurrence`, `observation_adjudication`, four indexes | `ObservationHistoryMigrationTest` — a **hand-written v17 database**; the additivity is proved by comparing the DDL of every existing table before and after, and the interruption by forcing the version back to 17 and migrating again |
| **cognitive v3 → v4** | the checkpoint, the owner, the request id, the arrival number, and the append-only request history | `CognitiveStoreMigrationTest` — a **hand-written v3 database**: the request it holds survives with its outcome, the new columns exist and are empty for the old row, and a new request can be claimed afterwards |
| **a fresh database** | the whole chain | `ObservationHistoryMigrationTest.aFreshDatabaseIsBuiltAtTheCurrentVersion` and the same path in the cognitive store |

**Every migration is additive and re-runnable:** the tables are created with
`CREATE TABLE IF NOT EXISTS`, the columns are added only when they are missing, the backfills
are `INSERT OR IGNORE`, and **the schema version is written LAST** — so an interrupted
migration leaves the database claiming the old version with the new structures already in
place, and running it again completes it.

**The owner's production database was never opened by any of these tests.** Every fixture is
written by hand inside a `@TempDir`.

## 6. The tests the wave could not write

| what | why |
|---|---|
| a kill **inside** a write transaction | the failpoint fires at committed boundaries; interrupting a transaction would need a fault inside SQLite |
| a kill of a process whose owner is **alive** | that is the opposite property — the claim must not be stolen — and it is proved by the unit tests |
| the **epistemic restoration across a kill** | the restoration is proven at store-reopen level; the journey exercises the request lifecycle. The wave does not claim what it did not run |
| a **native-image** run | the tooling is absent on this host |
| a **stateful external environment** | the micro-world's probe is a pure computation; the contract for a stateful one is written down, and no framework was introduced for it |
