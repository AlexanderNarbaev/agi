# W45.1 — CAPABILITY DELTA

**Status:** what now survives an actual process kill, what is only recoverable at store-reopen
level, and what is still indeterminate.
**Prepared:** 2026-11-04.

The rule of this document: **a capability is listed as proven only when it was observed in an
executed test, and the evidence is named.** The distinction that matters in this wave is
between a state that survives a **store reopen** (what W45.0 proved) and a state that survives
a **process kill** (what this wave proves).

---

## 1. What now survives an actual `SIGKILL`

| capability | what it does | the evidence | where |
|---|---|---|---|
| **a request that was killed after committing an observation is not repeated** | the retry is refused with `409 INDETERMINATE`; the case, the occurrence, the evidence and the predictions are **exactly as many as before the kill** | the journey, scenario A: before 1/1/1/2, after 1/1/1/2 | `scripts/w45-cognitive-recovery-journey.sh` |
| **a request that was killed before writing anything is executed again, in the SAME episode** | the claim's identities survive; the retry continues the same logical execution and opens exactly one episode | the journey, scenario B: before 0 episodes, after 1 episode, "the retry ran in the SAME episode" | the same |
| **a request that was killed after it completed replays its outcome** | the retry answers `200` with the original outcome; no second episode, no second prediction, no second case | the journey, scenario C | the same |
| **no request is left silently in `IN_PROGRESS`** | the recovery classifies it from its durable checkpoint and records the decision | the journey: the row is `INTERRUPTED_PARTIAL` or `COMPLETED` in every scenario, and the history explains it | `cognitive_idempotency.state`, `cognitive_request_event` |
| **the interrupted episode is closed with a terminal event** | an episode a dead process left open is closed and carries an `INTERRUPTED` event | `CognitiveRequestLifecycleTest.theRecoveryClosesTheEpisodeOfARequestThatADeadProcessLeftOpen` | `CognitiveStore.interruptEpisode` |
| **the kill is a real signal death** | the exit status of the child is 137 = 128+9, and the pid in the marker is the pid that was killed | the journey, every scenario | the harness |
| **a process that lost the request cannot complete it** | the completion is `WHERE owner_token = ?`; a stale owner is refused | `CognitiveRequestLifecycleTest.aProcessThatLostTheRequestCannotCompleteIt` | `CognitiveStore.completeIdempotency` |
| **a failure after a committed observation does not duplicate it** | the failed request's outcome is durable and replayable; the retry does no work | `CognitiveRequestLifecycleTest.aFailureAfterTheObservationWasCommittedDoesNotDuplicateTheObservation` | the kernel's `FAILED` outcome |
| **an adjudicated disposition survives a repeated observation** | the pre-fix build resets it to `ELIGIBLE`; this build keeps `ACCEPTED` | the pre-fix/post-fix comparison against the code of the previous commit | `KnowledgeStore.recordObservationOccurrence` |
| **the adjudication history is append-only and rebuildable** | the projection is a pure function of the history; the rebuild reproduces it exactly | `ObservationHistoryMigrationTest`, `ObservationDispositionDurabilityTest` | `KnowledgeStore.rebuildDispositionProjection` |
| **a legacy record is classified by the durable evidence, not by a guess** | the v16 fixture's six cases land on the dispositions the W45 policy requires | `ObservationLegacyBackfillTest` | `KnowledgeStore.backfillObservationDispositions` |

## 2. What is recoverable only at store-reopen level

These were already true in W45.0 and remain true — they are proven by reopening the stores
inside one JVM, **not** by a process kill:

| capability | the evidence | what a process kill adds |
|---|---|---|
| the drives are restored after a restart | `CognitiveRegulatoryPersistenceTest` | the journey does not exercise the regulatory state across a kill — the W45.1 checkpoint protocol covers it (`REGULATION_PERSISTED`), but no scenario kills exactly there |
| a contradiction stays out of the model across a restart | `CognitiveContradictionDurabilityTest` | the same |
| the reference method and the fast path read the same data | `CognitiveContradictionDurabilityTest` | the same |

**The honest statement:** the W45.1 journey covers the request lifecycle end to end. The
epistemic restoration was proven at store-reopen level in W45.0 and is **not** re-proven across
a process kill — the store's own recovery is the same, but the wave does not claim a test it
did not run.

## 3. What is still indeterminate

| what | why it is indeterminate |
|---|---|
| **the outcome of a request killed after a durable effect** | the work may have committed an observation whose result was not stored. The system answers `INDETERMINATE` and does **not** invent an outcome. Recovering it would need a per-effect journal that this domain does not have. |
| **the finalisation is not one transaction** | the trace, the episode close, the outcome snapshot and the idempotency completion are four writes. A kill between them leaves an indeterminate request. |
| **an external effect of a future stateful environment** | the micro-world's probe is a pure computation, so repeating it is harmless. A stateful environment would need a durable intent, an idempotent effect and an explicit recovery — the contract is written down in `W45.1-CRASH-CONSISTENCY-DESIGN.md` §7, and **no framework was introduced for it**. |
| **the liveness of an owner on another host** | the check is local. The supported topology is one writer process per database file; when the liveness cannot be disproved, the claim is treated as owned. |
| **a request whose owner is alive but hung** | its work is never stolen. The cost is that the request stays claimed until the owner dies. |
| **the legacy classification of a v16 case with a `CONTRADICTS` relation and no error row** | the knowledge tables alone cannot tell a conflict with a belief from an unexplained observation. The case is held and waits for an explicit adjudication. |
| **the v16 classification when the cognitive tables are not in the same database file** | the rule degrades to the conservative relation-only fallback. |
| **`observation_occurrence` grows without bound** | one row per act of observation, with no retention policy. |

## 5. What the wave did NOT change

- **No exactly-once claim for an external side effect.** The micro-world has none; the contract
  for a stateful one is written down and no framework was built for it.
- **No new executor, no cancellation framework, no generic action bus.** The W45.0
  `CycleDeadline` is preserved exactly, and the 250 ms figure remains a **configured
  convention**, not a calibrated one and not a promise.
- **No new application, no Gradle module, no second knowledge store.** The occurrences and the
  adjudications live in the existing store.
- **The three owner decisions are untouched** — the canonical conductor, the Chain B security
  boundary, and the destructive workspace reload. The last one remains the highest-severity
  open item: it can delete the history this wave makes auditable.
- **No revival** of the biochemical island, the Connectome, the ReplayPhase, the
  SleepConsolidator, the inactive consciousness metrics, or the unlanded MIND-W3/MIND-W4
  files.
- **No semantic, multimodal, GPU or consciousness claim.**
- **Nothing was committed and nothing was pushed.** The wave is local and reviewable, as the
  directive requires.
