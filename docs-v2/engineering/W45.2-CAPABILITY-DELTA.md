# W45.2 — CAPABILITY DELTA

**Status:** what the wave changed, separated into what is now **enforced and proved**, what is
**implemented but not proved end to end**, and what is **still open**.
**Prepared:** 2026-11-04.

The rule of this document: **a capability is listed as enforced only when an executed check
demonstrates it, and the check is named.** This wave is not a capability wave — it is a
boundary wave — so the list is short and the evidence is the point.

---

## 1. What is now enforced and proved

| what | the change | the evidence |
|---|---|---|
| **the architecture has one statement of the canonical entry point per serving application** | `io.matrix.api.CanonicalEntryPoint` — the declaration is a class, not a sentence | `CanonicalEntryPointTest` (7), `CanonicalEntryPointChainBTest` (3): two serving applications, each with an entry point and its routes; **no cycle is the cycle of two applications**; every declared class that can be resolved **does** resolve; the gateway's client really holds the `TrueMindCycle` |
| **the two serving chains are isolated** | no bridge, no implicit write path, no new surface | `scripts/w45-chain-isolation-check.sh` — **16 checks, 0 failed**: over **2908 classes and 76 815 constant-pool edges**, **0** classes of `io.matrix.cognitive.**`, **0** of the store itself, **0** of the classes that name the epistemic database, **0** of the chain A surface; at runtime the chain B server answers **404** for three chain A routes and leaves the owner's database **byte-identical** |
| **the isolation gate can go red** | the negative control breaks the isolation on purpose, in a private copy of the classes | `scripts/w45-chain-isolation-selftest.sh` — **6 checks, 0 failed**: `FAIL 78 class(es) of the epistemic store are reachable from chain B` and `FAIL 1 route(s) of chain B belong to the chain A surface` |
| **the destructive reload fails closed** | `POST /v1/workbench/workspaces/{id}/load` refuses a non-empty workspace without `replace=true`, and **nothing is deleted** | `WorkspaceLoadEndpointTest` — the contradiction, the evidence and the revision rows are all still there after the refusal |
| **a destructive load leaves a recoverable snapshot** | the snapshot is taken **in the same transaction** as the replacement, and the response carries its id | `WorkspaceSnapshotTest` — the snapshot holds what the workspace held, and restores it **including the contradiction and the revision rows** |
| **the contradiction history survives the reload** — with one honest exception | the W45.0 dispositions, the observation occurrences and the W45.1 adjudication history are **not** in the erasure set, so a load leaves them alone | the erasure set is ten tables (`revision, prerequisite, representation, evidence, derivation, contradiction, learning_goal, claim, source, concept`); the observation tables are not among them. **The `evidence` table IS** — and the W45.0 observations wrote their evidence there. A load therefore leaves a case and a disposition whose evidence rows are gone. That inconsistency is real; it is a consequence of the erasure set predating the observation tables, and it is recorded here rather than smoothed over |
| **a second writer process is refused** | the lock belongs to the **process**; a second process cannot take it | `CognitiveWriterLockTest` — **8 tests**, including one that starts **a second JVM** and is refused, and one that `SIGKILL`s a writer and shows the next writer takes the lock over |
| **a killed process does not lock the database forever** | the lock file records the owner; the same primitives `OwnershipToken` carries tell a dead owner from a live one | the same test, and the W45.1 journey re-run under the guard: **37 checks, 0 failed** — the restart was not blocked |

## 2. What is implemented but not proved end to end

| what | why |
|---|---|
| the **contract for a future bridge** | it is written down as ten requirements (BRIDGE-1…10) and the gate asserts that the document exists and names every one of them. It is a contract, not a capability: there is no bridge, and none is to be built without a further decision. |
| the **snapshot's inspectability** | the snapshot can be read programmatically (`store.workspaceSnapshots(workspaceId)`), but there is **no HTTP endpoint** for it — the decision's scope was the restore path, and an extra read surface was not created. |
| the **guard covers the file, not one store** | the epistemic store now takes the same lock, so a second **process** is refused whichever store it opens first. It is proved for the cognitive store; the epistemic store's participation rests on the same lock file and the same primitive. |

## 3. What is still open

| what | why |
|---|---|
| the **evidence of an observation does not survive a workspace load** | the erasure set of a workspace replacement predates the observation tables: it erases `evidence` but not `epistemic_case`, `observation_disposition`, `observation_occurrence` or `observation_adjudication`. A load therefore leaves a case and a disposition whose evidence rows are gone — the evidence is the part of the epistemic record that the load takes, and the decision is what it keeps. Fixing it means either taking the observation tables out of the erasure set (they are not the workspace's content — they are the system's observations) or erasing them together with the evidence (which would destroy the adjudication history the decision is meant to protect). The first is the smaller change and it is NOT made here: it changes what a workspace replacement means, which is the owner's call |
| the **legacy in-process door** `KnowledgeWorkbench.loadBundledPackage(String)` | it still replaces without the flag, because an existing test loads the package three times into one workspace and the decision requires a refusal on the second. **It is no longer a silent erase** — it leaves a recoverable snapshot. The HTTP surface, the door the owner named, fails closed ✓. Deprecating the one-argument method and moving its callers is the next step. |
| the **snapshot payload is not bounded** and the **snapshot table grows without bound** | there is no compression, no size limit and no retention policy. The owner asked for recoverability, not for storage. |
| the **guard is per host** | the operating system's lock protects the file against another writer on the same host, and against another host only when the shared filesystem implements cross-host locks. A network volume whose filesystem does not coordinate locks degrades the guard to a per-host guard. |
| a **container with its own PID namespace** | its pid is invisible to the host process; the shared inode's operating-system lock is what protects that case. |
| a **crashed store instance inside a live JVM** | keeps the lock for the life of that JVM. Deliberate: a leaked instance may still hold an open connection and write. |
| **the six W44 cycles that the archaeology did not name** | the declaration named the sixth cycle (`io.matrix.reasoning.BrainLoopService`, behind the chat route) while implementing the decision. The W44 cycle map listed five. The W44 documents are historical evidence and were **not** rewritten; the correction is recorded here and in the ADR. |

## 4. What the wave did NOT change

- **The five cycles were not merged**, and no sixth conductor, kernel, bus or framework was
  created. The declaration names them; it does not replace them.
- **No bridge between the chains**, no network exposure, and chain B cannot alter claims,
  confidence, goals or safety policy.
- **No new HTTP surface** beyond the restore endpoint the decision required and the `replace`
  parameter on the existing load.
- **No schema shape was changed**: the knowledge schema moved **v18 → v19** by ADDING one
  table (`workspace_snapshot`) and an index; the cognitive schema stayed at **v4**. Every
  migration is additive and re-runnable after an interruption.
- **The W45.0 and W45.1 semantics are unchanged**: the durable observation disposition, the
  adjudication history, the request lifecycle, the phase-boundary deadline and the
  crash-consistent recovery all stand. The W45.1 journey re-run under the new guard is the
  evidence.
- **The two historical ADRs were not rewritten** — they carry a one-line status annotation
  pointing at the superseding document.
- **Nothing was revived**: not the biochemical island, the Connectome, the ReplayPhase, the
  SleepConsolidator, the inactive consciousness metrics, nor the unlanded MIND-W3/MIND-W4
  files.
- **No semantic, multimodal, GPU or consciousness claim.**
