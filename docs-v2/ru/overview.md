# Что такое MATRIX

MATRIX — открытая исследовательская система **детерминированного нейро-символического
вывода**. Знание представлено таблицами истинности и их компилируемыми формами, путь
обучения отделён от рантайма, а решение во время исполнения — булева цепочка, которую
можно прочитать.

Это простое введение. Без метафор, и каждое число на странице снабжено артефактом, который
его породил: там, где утверждение проекта было однажды опубликовано и не пережило собственной
проверки, здесь приводится именно проверка.

## Идея

У системы вывода две очень разные работы, и большинство систем их смешивают:

1. **решать** — по состоянию какой ответ? и
2. **учиться** — по опыту что меняется?

MATRIX разделяет их. **Численный субстрат** — метрики, веса, детерминированные ядра —
реализован как чистые функции, без случайности и без чтения часов. **Когнитивный слой** —
обучение на ошибках, exploration-семплирование, генерация гипотез — может использовать
seeded-случайность, но только там, где сам seed есть чистая функция состояния. Обучение
стохастично; рантайм — нет.

Это конституция проекта, и её проверяют, а не декларируют
([`CONSTITUTION.md`](../../CONSTITUTION.md), статья I).

### Что из этого следует

| | |
|---|---|
| **Никаких LLM на пути решения.** | Гейт сканирует рантайм-модули обеих цепочек на устаревшие LLM-импорты и роняет сборку при попадании; воспроизведённое значение — **0**. Он выполняется как блокирующая CI-задача ([`CAPABILITY-REGISTRY.yml`](../architecture/CAPABILITY-REGISTRY.yml), строка `C-01b`) |
| **Каждое решение в рантайме — булева цепочка**, аудируемая через заголовок `x-matrix-trace` и hash-chain (статья VIII) |
| **Булевы артефакты ограничены**: K_MAX = 20 входов, а увеличение требует правки всех компиляторов и бэкендов (статья II) |
| **Четыре запрета действуют при любом содержимом входа**: система не убивает, не мучает, не порабощает и не размножается без явного согласия оператора. Они реализованы в `EthicalFilter`, `StructuralSafetyGuard`, `LieDetector` и замороженном хранителе FROZEN-FNL (статья IV) |
| **Гейт покрытия** — ≥ 82 % METHOD на `matrix-core`, и понижение требует RFC (статья V) |

**И что конституция запрещает в письменном виде.** «AGI», «общий искусственный интеллект»,
«сверхразум»; утверждения об абсолютной безопасности вроде «не лжёт» или «не может быть
использован во вред»; и **числовые характеристики без измерения**. Последнее — причина, по
которой приведённые ниже числа несут свой источник, а несколько когда-то опубликованных чисел
здесь отсутствуют (статья VI).

## Три семейства вывода, которые реализованы

| | что делает | где живёт |
|---|---|---|
| **BIR** — булев вывод | правила и факты, компилируемые в таблицы истинности, клаузы и BDD, вычисляемые детерминированно | `io.matrix.bir` |
| **HDC** — гиперразмерные вычисления | образы как высокоразмерные векторы, сравниваемые по сходству | `io.matrix.neuron` |
| **MCTS** — поиск по дереву Монте-Карло | планирование по дереву поиска | `io.matrix.mcts` |

Рядом с ними **портфель алгоритмов** допускает метод только тогда, когда в запросе
присутствует каждое объявленное методом предусловие, и ранжирует допущенные методы по
измеренным данным — восемь методов из четырёх семейств, `SERVED` с названным путём
([`CAPABILITY-REGISTRY.yml`](../architecture/CAPABILITY-REGISTRY.yml), строка
`W44-ALGO-PORTFOLIO`).

## Архитектура в двух строках

Система работает как **два обслуживающих приложения, которые намеренно не вызывают друг
друга**.

```
цепочка A   io.matrix.MatrixApplication      Quarkus        127.0.0.1:9091   210 маршрутов
цепочка B   io.matrix.api.MinimalHttpServer  JDK HttpServer 127.0.0.1:8765    28 маршрутов
```

Цепочка A владеет эпистемическим хранилищем (утверждения, случаи, свидетельства, ревизии)
и когнитивным (эпизоды, предсказания, ошибки). Цепочка B владеет циклом мозга и его постоянным
состоянием. Изоляция доказана по скомпилированным классам гейтом, который падает при встрече
цеппочек, и самопроверкой, которая намеренно ломает изоляцию, чтобы показать, что гейт умеет
краснеть. Каноническое описание с переписью за ним —
[`docs-v2/architecture/RUNTIME-TOPOLOGY.md`](../architecture/RUNTIME-TOPOLOGY.md).

**Один флаг решает, что обслуживает цепочка B.** По умолчанию её режим — `stub`,
87-строчный `StubBrainCycle`, а настоящий мозг работает только при `MATRIX_MODE=production`.
Активный режим сообщает `GET /health/live`. Это открытый вопрос владельца F-01, и поэтому
первым делом стоит проверить именно его.

## Что действительно измерено

Это проверенные утверждения в собственных словах реестра, с корпусом, на котором каждое
измерено. **Утверждение — это измерение, иначе это ничего**, поэтому в каждой строке назван
отчёт и границы применимости.

| утверждение | измерение | границы |
|---|---|---|
| BIR на логических задачах | **75,0 %** на 100 задачах против случайного базового уровня **30,0 %** — и против эвристики с теми же 75,0 % | один названный корпус из 100 задач ([`BENCHMARK-REPORT-W620.md`](../research/BENCHMARK-REPORT-W620.md) §1) |
| эффективность по выборке HDC | **AUC 0.899**, 90 % после **50 примеров**, против случайного AUC 0.253 | один корпус ([`BENCHMARK-REPORT-W620.md`](../research/BENCHMARK-REPORT-W620.md) §2) |
| MCTS в headless-симуляторе | **92 %** успеха и 0 смертей для федерации из 5 узлов против 78 % для одного агента | **headless-симулятор Minecraft**, а не публичный сервер |
| консенсус федерации | **100 %** консенсуса при убитых 10 %, 30 % и 50 % узлов, на 100, 500 и 1000 узлах | **модель** ([`FEDERATION-SCALE-REPORT-W635.md`](../research/FEDERATION-SCALE-REPORT-W635.md)) |
| GPU как необязательный ускоритель | **12,06×** на пути обслуживания за три прогона (12,06 / 11,68 / 11,47); сквозной путь 12,69×; одиночный вызов ONNX **0,24×** — примерно в 4 раза медленнее | одна машина, одна модель ([`W48-GPU-BENCHMARK.md`](../engineering/W48-GPU-BENCHMARK.md)) |

**И утверждения, которые проверку не пережили.** Реестр хранит их как проверенные строки, а
индекс отрицательных результатов — вместе с ценой повторения
([`docs-v2/research/NEGATIVE-RESULTS-INDEX.md`](../research/NEGATIVE-RESULTS-INDEX.md)):

- **«в 33 000 раз быстрее, чем LLM»** — никогда не измерялось: опубликованная цифра делила
  *скорость генерации* на *задержку одного вызова*, а это разные величины. Отчёт бенчмарка
  содержит другое число против **синтетической** модели ops/sec для LLM. Реестр помечает
  утверждение как `REJECTED` и `REMOVED` (строка `C-02`).
- **«90 % сохранения точности после дистилляции LLM»** — конвейер описан, цифра сохранения
  никогда не измерялась (`REJECTED`, `REMOVED`; строка `C-08`).
- **«100 % соответствия Конституции»** — механизмы соответствия существуют и работают в CI;
  **процентент — не измеримая величина** (строка `C-03`).
- **«production-grade hybrid AI framework»** — утверждение о готовности, а не измерение;
  реестр записывает его как неизвестное по всем осям (строка `C-09`).
- **опубликованные счётчики тестов** — «724 теста», позже «9 432 теста / 1 282 сьюта» — это
  устаревшие числа устаревшего целого. Базовая линия — это **набор scopes**, каждый
  проверенный на названном коммите (строка `C-01`).

## Что не работает

| | |
|---|---|
| **сборка native-image** | **BLOCKED** — инструментарий GraalVM на машине разработчика отсутствует; native-scope отказывается запускаться, а не сообщает о проходе |
| **режим шлюза по умолчанию** | обслуживает заглушку; F-01 |
| **незаявленные порты цепочки A** | 9093 (multicast) и 9094 (TCP) открываются, не появляясь ни в одной записи обслуживания — F-02 |
| **проба готовности** | всегда 503, и производственный код её не читает |
| **переживают два мутанта формальных спецификаций** | `Consensus-evaluate-without-quorum` и `KnowledgeAxes-conflict-forgets-what-it-recorded` |
| **свойства на корпусе владельца** | пропускаются на чистом раннере, потому что корпуса нет в git. Пропуск — не проход |
| **нет резервной копии всей базы** | SQLite backup API не встречается в репозитории |

Полный список с владельцем у каждого пункта — в
[`docs-v2/governance/PROJECT-STATE.md`](../governance/PROJECT-STATE.md) §4.
