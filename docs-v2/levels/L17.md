# L17 — Contributor Onboarding

## 1. Scope

Layer 17 specifies the path from first checkout to first merged
PR: prerequisites, the 30-minute first-contribution flow, where
to find tasks, code style, review process, and support channels.
Onboarding is normative for the public repository.

## 2. Prerequisites

- Read Code of Conduct (engineering/STANDARDS-MATRIX.md §X).
- License: AGPLv3 with ethical restrictions (L12). Submission
  implies acceptance.
- JDK 25, Gradle 9.x. Native-image toolchain optional.
- For technical tasks: Java 25, Quarkus 3.37.3, JUnit 5.
- For non-coding tasks: docs, translations, design — listed
  separately in §4.

## 3. First Contribution Flow (30 minutes)

1. Clone and build: `./gradlew build && ./gradlew test`
   (≈10 min).
2. Find a task: filter issues by `good first issue`; comment to
   claim; if empty, propose a new issue (≈5 min).
3. Branch, change, test, commit with conventional prefix
   (`feat`, `fix`, `docs`, `test`, `refactor`, `chore`)
   (≈10 min).
4. Open PR with rationale, linked issue, and review notes
   (≈5 min).

## 4. Issue Labels and Discussions

- `good first issue`, `help wanted`, `documentation`, `bug`,
  `enhancement`, `rfc` (architecture-impacting).
- GitHub Discussions: `Ideas`, `Q&A`. RFCs originate here with
  a 14-day (or 30-day for L0–L8) feedback window.

## 5. Code Style

- Java per Google Java Style Guide; Checkstyle in build.
- 4-space indent, 120-char line limit.
- Javadoc on all public classes and methods, referencing the
  spec section by name (no cross-document links, see
  engineering/DOC-CONVENTIONS.md).
- Tests: JUnit 5 + AssertJ; naming
  `should_expectedBehavior_when_condition`.
- Coverage floor: ≥ 82% METHOD on matrix-core (CONSTITUTION V).

## 6. Commit and PR Hygiene

- One logical change per commit. Conventional prefix mandatory.
- PR description: what changed, why, link to issue, test plan.
- CI must be green: tests, Checkstyle, JaCoCo gate.

## 7. Review

- Module maintainers review; one reviewer for small changes,
  two for architectural changes.
- Initial review within 48 working hours.
- Disagreement handled by argument, not vote; maintainer
  tie-break.
- Approval + green CI = merge; squash preferred.

## 8. Support Channels

- Matrix room `#matrix-dev:matrix.org` (primary).
- Discord mirror.
- Weekly Office Hours, time rotated for time-zone fairness.
- GitHub Discussions `Q&A`.

## 9. Promotion

Sustained quality contributions may lead to maintainer nomination
per L11. Maintainers gain review and voting rights; formal
status is recorded in the repo governance file.
