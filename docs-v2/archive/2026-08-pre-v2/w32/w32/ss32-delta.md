# Дельта волны 32 к карте системы

SYSTEM-SYNTHESIS.md покрывает §1–§115 (волны 1–31). Этот файл — официальное
дополнение до §1–§118 (волна 32, ALGORITHM-ATLAS-WAVE32.md). При следующей
ревизии монолита дельта вливается в основной файл; до тех пор читать
SYSTEM-SYNTHESIS.md + эту дельту вместе.

## §1. Дополнения стека механизмов

- **L2 (компилятор, основания)** += §116 (Тюхтин), §118 (Тихонов). К L2-механизму:
  значение сигнала ≡ типизированная роль относительно акцептора, назначаемая
  схемой и планом (реестр типов ролей версионируется configHash); регуляризация ≡
  объявление класса до поиска как норма компиляции.
- **L3 (верификация, основания)** += §118 (Тихонов): класс — условие
  применимости, входит в заголовок BIR; вне объявленного класса ≡ UNDECIDED.
- **L6 (контур, основания)** += §116 (Тюхтин): роль сигнала проверяется
  использованием в доказанных шагах BRC; незадействованный сигнал журналируется.
- **L7 (жизненный цикл, механизм)** += два переноса:
  - нормативная организация знания (§117, Финн) ≡ жизненный цикл как инженерия
    уровней с документированными χ-переходами: знание организуется по норме, не
    «вырастает само»; JSM-генератор ≡ кандидат-генератор причинных связей над
    булевой таблицей наблюдений (сходства ≡ пересечение покрытий, различия ≡
    near-miss пары §111): гипотеза — SHADOW с таблицей подтверждения как witness,
    проверка на непересекающемся контрольном корпусе (§49), метод версионируется;
  - регуляризация (§118, Тихонов) ≡ SearchClassDeclaration (класс + решающая
    процедура + потолок бюджета) до запуска ряда: вне класса ≡ UNDECIDED;
    стабилизатор ≡ MDL-скоринг при выборе внутри класса; устойчивость артефакта
    проверяется на границе validatedClass (неустойчивость у границы ≡ сигнал
    гомеостату о слишком широком классе).
  Основания L7 += §117 (Финн), §118 (Тихонов).
- **L9 (исследовательский контур, основания)** += §117 (Финн/JSM): JSM как
  кандидат-генератор в исследовательском контуре.

## §4. Новые кандидаты на пререгистрацию (в копилку HYPOTHESES)

- аудит ролевой типизации сигналов (§116) — доля входных сигналов с назначенной
  типизированной ролью и доля задействованных в доказанных шагах по классам
  задач: процедурный кандидат (систематическая незадействованность класса
  сигналов — повод к пересмотру ioSchema);
- аудит JSM-пар причинных гипотез (§117) — доля SHADOW-гипотез, подтверждённых
  на непересекающемся контрольном корпусе, по канонам (сходства/различия/
  остатков/сопутствующих изменений): кандидат на сравнение по корпусам (FR-15);
- аудит порядка регуляризации (§118) — доля поисков, начатых с действительной
  SearchClassDeclaration, против «сначала перебор»: процедурный кандидат
  (компилятор журнала проверяет декларацию класса до события поиска);
- калибровка стабилизатора (§118) — сравнение MDL-скоринга с альтернативными
  функционалами выбора внутри класса: кандидат на сравнение по корпусам (FR-15).

## §5. Дополнение границы №10 (когнитивные/методические прецеденты — не истина)

Роль сигнала (прецедент Тюхтина, §116) — назначение схемой и планом, не свойство
сигнала: «критичность» сообщения вычислима только относительно акцептора;
причинная гипотеза (прецедент Финна–Милля, §117) — SHADOW-кандидат с таблицей
подтверждения, не вывод: канон порождает кандидата, принятие — контрольной
проверкой и Φ-гейтом; регуляризованный ответ (прецедент Тихонова, §118) —
решение на объявленном классе, не истина исходной задачи: стабилизатор выбирает
внутри класса, класс — условие применимости, а не гарантия.
