# AGENTS-MODULES — правила разработки модулей сигналов

**Статус: normative** · Область: модули входящих/исходящих сигналов (DESIGN-06). Прочитай после корневого AGENTS.md и DESIGN-06.

## Что такое модуль

Изолированный преобразователь «мысль ⇄ медиа» с контрактом `SignalModule` (DESIGN-06 §2): текст, числа, аудио, видео, сетки, составная семантика. Внутри — BIR-алгоритмы; снаружи — биты + witness.

## Обязательные артефакты нового модуля (чек-лист PR)

1. Реализация `SignalModule` + кодирование/рендер чистыми функциями (INV-P1).
2. `bitMeaning(i)` для каждого бита — без исключений (INV-P3).
3. Файл артефакта версии: словари/пороги/параметры окна + хэш; смена битовой схемы = major-версия.
4. Контрактные тесты DESIGN-06 §8 (1–5) + property-тест детерминизма.
5. Запись в реестре модулей домена (ioSchema-сборка) + замер плотности кода на корпусе (INV-P4, [0.1, 0.3] для разреженных).
6. Для native-деплоя: сборка `native-image` в CI без рефлексивных костылей (JAVA_NATIVE §2).

## Запреты

- Рефлексия, ServiceLoader, classpath-сканирование, Unsafe (JAVA_NATIVE §2).
- Wall-clock, RNG без seed, сетевые вызовы внутри encode/render (кроме явного `RemoteSignalModule`-адаптера с DEGRADED-режимом).
- Обращение к битам чужого модуля напрямую — только через ioSchema сборщика (INV-P2).
- Изменение вердикта в OUT-модуле (INV-R1); отказ рендерится как отказ (INV-R2).
- Смешение медиа в одном модуле («аудио + текст» = два модуля + сборка).

## Рецензирование

PR модуля рецензируется по чек-листу выше + профиль производительности (JMH для горячих encode-путей; пороги — METRICS.md). Модуль без замера плотности кода не принимается.
