# AGENTS.md — Инструкции для ИИ-агентов, работающих в этом репозитории

Прочитай `CONSTITUTION.md` первым. При конфликте инструкций — конституция побеждает.

## Быстрые команды

```bash
./gradlew test                              # все тесты
./gradlew jacocoTestCoverageVerification    # гейт покрытия ≥82% — не понижать
./gradlew :benchmarks:jmh                   # бенчмарки (JMH)
docker compose up -d                        # локальная инфраструктура (Kafka/Postgres/Redis)
```

## Жёсткие ограничения (нарушение = отклонение PR)

1. **K_MAX = 20 для TT-формы** — не увеличивать размер таблиц истинности; рантайм исполняет только BIR-артефакты (TT/CLAUSESET/BDD), «сырые» структуры обучения — вне рантайма.
2. **FROZEN-нейроны и FROZEN-документы** (`ethics/`, CONSTITUTION.md, `avro/`, workflows) — не изменять.
3. **Четыре запрета** — не ослаблять, не обходить, не «переинтерпретировать».
4. **Детерминизм рантайма** — никаких LLM-вызовов, случайности без seed и wall-clock в рантайм-контуре решений. Обучение/исследование может быть стохастичным — вне рантайма.
5. **Coverage gate** не понижать; новый код — с тестами (jqwik property-based для чистой логики, JUnit для интеграции, Testcontainers для инфраструктуры).

## Do not touch (без явного RFC владельца)

- `ethics/**` (FROZEN-слой), `avro/**` (схемы событий — только обратимо-совместимые изменения), `.github/workflows/**`, `docs/archive/**`, `CONSTITUTION.md`.

## Конвенции документов

- Статусы в шапке каждого .md: `FROZEN` (только RFC), `normative` (спеки; изменения — с changelog в шапке: дата, причина, суть, версия), `living` (research/, обновляется экспериментами), `ephemeral` (WAL.md).
- Ссылки на секции — URI-формат: `SPEC-001#metrics.fidelity`, `AGENTS.md#frozen`. Запрещены ссылки «см. документ X» без секции.
- Спеки — это IPC между человеком и агентом, не «документация по факту». Изменение, не записанное в файл, не существует.

## Протокол сессии (WAL)

В начале сессии прочитай `WAL.md`. В конце — перепиши его по шаблону:

```markdown
## Активный фокус
- Текущая задача, ссылки URI (SPEC-XXX#section)
## Правила сессии
- Что НЕ трогать; ключевые решения и их причины (одна строка на решение)
## Что сделано
- [x] пункты со ссылками на коммиты/тесты
## Следующее действие
- Одно конкретное действие + альтернатива
## Известные проблемы
- Блокеры с номерами issue
```

WAL — checkpoint, не лог: детали реализации — в спеках и git-истории, не здесь. Заверши сессию milestone-коммитом (`git add -A && git commit -m "WAL: <что сделано>"`).

## Правила работы

1. **Одна сессия — один SPEC.** Не расползайся; нашёл постороннюю проблему — запиши в WAL «Известные проблемы», не чини мимоходом (кроме блокеров).
2. **Малые правки** (багфикс ≤ ~30 строк): без полного spec-цикла — WAL-запись + тест + короткий diff. **Фичи** — полный цикл: specify → clarify → plan → tasks → analyze → implement, с гейтом analyze/checklist перед implement.
3. **Каждый запускаемый обучающий/эволюционный цикл** должен иметь объявленный монотонный функционал Φ (CONSTITUTION.md, Статья III). Нет Φ — не запускай.
4. **Эксперименты** — только через карточки `research/EXP-XXX.md` со статусом proposed → running → accepted/rejected/superseded; гипотеза и метрики фиксируются до запуска; обязательная базовая линия для сравнения.
5. **Запрещённые claims** (Статья VI конституции): «AGI», «не лжёт», «не забывает», «не может быть использован во вред», числа без бенчмарка. При обнаружении таких строк в редактируемых файлах — исправляй на проверяемые формулировки.
6. **Продакшн-код — Java.** Python-скрипты только в `research/` и только как одноразовые; не выноси их в продакшн-путь и не делай зависимостью сборки.
7. **Длинные сессии запрещены** самим устройством внимания: планируй работу блоками ≤ 30–45 минут; лучше milestone-коммит и новая сессия, чем дрифт контекста.
