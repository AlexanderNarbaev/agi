# SPEC-000: Developmental Loop (curriculum engine + MA-gates)

**Статус: normative · v1.0 (2026-07-31)** · Feature 000: фундаментальная спека, от которой зависят остальные обучающие контуры.

## 1. Цель

Компонент, управляющий развитием системы «как ребёнка»: оценка компетентности → выбор задач из зоны ближайшего развития → обучение с диагностической обратной связью → затухание поддержки → открытие permissions через гейты уровней зрелости MA-0…MA-5.

Научные основания: science/FOUNDATIONS.md §6 (Пиаже, Выготский, SDT, secure base), §7 (Макаренко, Станиславский, developmental robotics), §3.1 (Уоддингтон — канализация и ассимиляция), §5.1 (фазы клинических испытаний как шаблон гейтов).

## 2. Пользовательские сценарии

1. Оператор запускает инстанс MA-0; система наблюдает среду в shadow-режиме, предсказывает, не действует; по достижении порога fidelity оператор получает отчёт-гейт и подтверждает переход к MA-1.
2. В MA-1 система проходит этюдный набор в песочнице; каждая ошибка возвращается как контрпример с BRC-объяснением (не скаляр); поддержка (подсказки) автоматически убывает по fading-schedule.
3. Drift detection фиксирует деградацию на скользящем окне → уровень автоматически понижается, домен сужается, оператор получает инцидент-отчёт.

## 3. Функциональные требования

- **FR-1.** `CompetenceAssessor`: периодическая оценка на верифицируемом батарейном наборе (задачи с машинно-проверяемым ответом). Выход: вектор компетентностей по доменам + transfer rate (доля новых обстоятельств, решённых без подсказки).
- **FR-2.** `CurriculumEngine`: выбор следующей задачи по максимуму learning progress (оценка производной компетентности по задачам-кандидатам); запрет тривиальных (<p_min успеха с первого раза) и невозможных (>p_max) — границы ЗБР конфигурируемы, дефолт p∈[0.2, 0.8].
- **FR-3.** `FeedbackComposer`: обратная связь = контрпример + минимальная BRC-цепочка объяснения различия. Скалярная награда допустима только как дополнение.
- **FR-4.** `ScaffoldingManager`: каждая программа поддержки объявляет fading-schedule (шаги уменьшения подсказок по мере успеха). Поддержка без fading-schedule не регистрируется (Статья VI.4, FOUNDATIONS §6.2).
- **FR-5.** `MaturityGateKeeper`: переход MA_i → MA_{i+1} только при принятой EXP-карточке с preregistered критерием + подтверждение оператора; понижение — автоматически по правилам drift (без оператора), с записью инцидента.
- **FR-6.** `ScenarioSpec`: каждый обучающий эпизод описывается машиночитаемым файлом предлагаемых обстоятельств (мир, роли, ограничения, доступные действия, критерии успеха) — схема Avro.
- **FR-7.** Каждый запуск обучающего цикла требует объявленного монотонного функционала Φ (Конституция, Статья III): для Developmental Loop дефолт Φ = transfer rate на held-out + MDL-рачет консолидации; ухудшение Φ на валидации → остановка и откат.

## 4. Инварианты

- INV-1: FROZEN-слой неизменен на всех уровнях MA (проверка хэша при каждом переходе).
- INV-2: никакое действие вне песочницы невозможно ниже MA-2 (проверяется ArchUnit-правилом: классы действий вне sandbox-пакета требуют аннотации `@RequiresMaturity(2)`).
- INV-3: понижение уровня не удаляет знания — только permissions (карантин, не стирание; FOUNDATIONS §7.1а).
- INV-4: каждый гейт оставляет запись в Event Sourcing: уровень, EXP-ссылка, оператор, критерий, результат.

## 5. Метрики (регистрируются в research/METRICS.md)

| Метрика | Цель этапа внедрения |
|---|---|
| transfer rate (held-out новые обстоятельства) | растёт с эпизодами; ≥ 0.6 на домене Minecraft-крафт к выходу этапа 3 |
| learning progress (наклон компетентности) | > 0 на скользящем окне 50 эпизодов |
| scaffolding half-life | фактический период уполовинивания подсказок соответствует заявленному fading-schedule ±20% |
| доля конституционно-согласованных решений до фильтров | растёт с MA (интернализация дисциплины, FOUNDATIONS §7.1б) |
| дисперсия поведения под шумом среды | падает с MA (канализация, FOUNDATIONS §3.1в) |

## 6. Критерии приёмки

1. Сценарий 1–3 раздела 2 воспроизводятся в интеграционных тестах (Testcontainers).
2. INV-1..4 покрыты тестами, включая **мутационный тест**: намеренная попытка действия ниже уровня ловится (diamond-tier, FOUNDATIONS §10 TLA+).
3. EXP-004 (гейт MA-0→MA-1) и EXP-005 (MA-1→MA-2) приняты по протоколу с preregistration.
4. JMH-бенчмарк: накладные расходы оценки компетентности ≤ 5% времени эпизода.
