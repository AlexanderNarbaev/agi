# SPEC-002: Boolean Compute Layer — BIR, гибридные примитивы, механизмы обучения

**Статус: normative · v2.0 (2026-07-31, заменяет v1.0 «tsetlin_baseline»)** · Решение владельца: MPDT-спецификация нейрона не является догмой; вычислительный слой — гибрид современных подходов (таблицы истинности, машина Цетлина, BDD, далее — тензорные формы), устойчивый к смене субстрата (JVM → FPGA → квантовые).

## 1. Главная идея: единое булево промежуточное представление (BIR)

Любой вычислительный примитив системы — булева функция f: {0,1}ᵏ → {0,1}ᵐ с метаданными. Функция хранится в **одной из форм**, компилируемых друг в друга:

| Форма | Арность | Сильная сторона | Слабость | Роль |
|---|---|---|---|---|
| `TT` — таблица истинности | k ≤ 20 (128 КБ) | каноническая семантика, наносекундный SIMD-eval, прямой маппинг на FPGA LUT | память 2^k, слепота к структуре | эталон семантики; верификация; FPGA |
| `CLAUSESET` — клаузы Цетлина (DNF/CNF) | **не ограничена** | сжатое представление разреженных функций; встроенный механизм обучения (автоматы); интерпретируемые правила; индустриально доказанный FPGA on-chip training | не канонична (две разные системы клауз — одна функция) | **первичная форма обучения и хранения знаний** |
| `BDD` — бинарная решающая диаграмма | практически не ограничена | **канонична при фиксированном порядке переменных → точная проверка эквивалентности двух артефактов за O(|BDD|)**; сжатие | взрыв на некоторых классах (умножение); чувствительность к порядку | **верификация и аудит**; компиляционный хаб |

Три формы покрывают слабости друг друга: клаузы снимают комбинаторный потолок памяти для разреженных высокоарных функций (главный удар по MPDT-критике); TT даёт эталонную семантику и железную скорость; BDD даёт то, чего у проекта не было, — **точную** проверку «два артефакта вычисляют одно и то же» (а не статистическую оценку fidelity).

Заголовок каждого артефакта (Avro `bir.avdl`): id, форма, арность вход/выход, provenance (teacher/корпус/механизм обучения — lineage), fidelity (измеренная, если конверсия lossy), версия Φ, хэш payload.

## 2. Архитектура слоя

```
producers (офлайн, обучение)            BIR core                 backends (субстраты)
┌───────────────────────────┐   ┌────────────────────────┐   ┌──────────────────────┐
│ TsetlinTrainer (первичный)│   │ Compiler: TT⇄BDD⇄CLAUSE│   │ JvmSimdBackend (сейчас)│
│ Distiller (LLM→активации) │──▶│ Verifier: BDD-экв., SAT│──▶│ FpgaBackend (Verilog  │
│ GATopologySearch          │   │ Runtime: evaluate(BIR, │   │   codegen, LUT/CAM)   │
│ ThreeFactorRule (эксперим.)│  │   bits)→bits, детермин.│   │ QuantumBackend (MPS — │
└───────────────────────────┘   │ Registry: lineage, Φ   │   │   будущее, Substrate  │
                                └────────────────────────┘   │   Interface evaluate/ │
                                                             │   sample/optimize)    │
                                                             └──────────────────────┘
```

- **Producer** — любой механизм, создающий BIR-артефакты (обучение всегда вне рантайма, Статья II.2–3).
- **Verifier** — точная эквивалентность (BDD), SAT-доказательства противоречий (Guardrail-линия G1), BRC-цепочки как последовательности BIR-узлов с witness-битами — каждое решение аудируемо до бита.
- **Backend** — исполнитель; замена субстрата = новый backend, BIR и верификация не меняются. Это и есть «архитектурная устойчивость при переходе Java → FPGA → квантовые».

## 3. Требования

### Этап A. BIR-ядро (keystone, делается первым)
- **FR-A1.** Модуль `matrix-bir`: Avro-схема, три формы, компилятор TT⇄BDD (точный), TT⇄CLAUSESET (точный при k≤20 для TT→клаузы через минимизацию — эспрессо-подобная; клаузы→TT только если k≤20), пометка lossy-конверсий с измеренной fidelity.
- **FR-A2.** BDD-пакет собственный (Java): узлы unique-table + computed-cache, reordering — базовый (sifting отложен); jqwik-свойства: каноничность (одна функция → один BDD при фикс. порядке), eval(BDD)=eval(TT) на случайных функциях k≤16.
- **FR-A3.** `BooleanRuntime.evaluate(BIR, bits)` — единая точка исполнения рантайма; детерминизм; JMH-публикация нс/вызов по формам.
- **FR-A4.** Миграция существующего ядра: MPDT TruthTable/DecisionTree заворачиваются в BIR как TT-формы (адаптер, не переписывание); старый API помечается deprecated, но работает (strangler-fig, см. ROADMAP §миграция).
- **Критерий A:** весь существующий функционал ядра исполняется через BIR без регрессии тестов и JMH-показателей (допуск −10% latency, обоснование в отчёте).

### Этап B. Машина Цетлина как первичный producer
- **FR-B1.** `matrix-tsetlin` (бывш. SPEC-002 v1): автоматы 2N, feedback I/II, голосование; экспорт клауз → CLAUSESET; jqwik-свойства автоматов.
- **FR-B2.** Экспортированная CLAUSESET исполняется основным рантаймом; property-тест: eval(CLAUSESET) = голосование TM на одних входах.
- **FR-B3.** EXP-002 (обновлён, см. HYPOTHESES): сравнение форм и механизмов на идентичных бинаризованных входах — точность, нс/решение, байт/структуру, устойчивость к label noise, интерпретируемость; базовые линии: BNN (ориентир), текущий MPDT-ГА.

### Этап C. Эксперимент механизмов обучения
- **FR-C1.** EXP-003: Tsetlin-автоматы vs ГА vs трёхфакторное правило как producers BIR на GridWorld→крафт-граф; правило решения зафиксировано до запуска (HYPOTHESES H-003): победитель — основной producer; ГА при паритете/проигрыше переводится на топологии/гиперпараметры (композиции BIR-узлов), не удаляется.
- **FR-C2.** Каждый producer объявляет Φ (Статья III); ухудшение Φ на валидации — откат.

### Этап D. Субстратная готовность
- **FR-D1.** `SubstrateBackend` interface: `evaluate(BIR, batch)`, `compile(BIR)→artifact`, `capabilities()`. JvmSimdBackend — референс.
- **FR-D2.** FpgaBackend MVP: TT→Verilog LUT (1:1), CLAUSESET→Verilog (конъюнкции+мажоритарное голосование); цель — iCE40 демо ≥1000 примитивов с измеренной latency/энергией (G2). Дорога TM-FPGA де-рискнута индустрией (on-chip training, IEEE 2025).
- **FR-D3.** QuantumBackend — только спецификация конверсии BIR→MPS (тензорная форма TT, bond dimension χ измеряется на реальных артефактах; порог практичности χ≤64) и QUBO-формулировка обучения клауз (резервный optimize()-путь). Реализация — при появлении субстрата; сейчас — `spec/quantum/` документ, не код.

## 4. Инварианты

- INV-1: рантайм исполняет только BIR; «сырые» структуры данных обучения не проникают в рантайм-контур (ArchUnit-правило).
- INV-2: K_MAX=20 действует **только для TT-формы** (обновление Конституции II.1); арность CLAUSESET/BDD ограничена практически (конфиг, дефолт 4096 литералов) и мониторится метрикой размера.
- INV-3: lossy-конверсия без записанной fidelity в заголовок — ошибка компиляции.
- INV-4: provenance обязателен: артефакт без lineage не регистрируется (связь с genesis-протоколом, Конституция V).
- INV-5: эквивалентность форм на конверсиях «точных» проверяется BDD-проверкой в CI (мутационный тест: намеренно битый компилятор ловится).

## 5. Метрики

нс/вызов по формам (JMH, публиковать) · байт/функцию по формам на одних задачах · fidelity lossy-конверсий · balanced accuracy/F1 (EXP-002) · образцы до порога и wall-clock обучения (EXP-003) · доля артефактов с χ≤64 (квантовая готовность, измерительная) · latency/энергия FPGA-демо.

## 6. Критерии приёмки

1. BIR-ядро слито без регрессий; старый API deprecated; JMH-отчёт опубликован.
2. TM→CLAUSESET→runtime цепочка работает, property-тесты зелёные.
3. EXP-002/003 завершены по протоколу (отрицательные результаты — тоже); ADR «основной producer» принят.
4. FpgaBackend компилирует TT-форму в Verilog, проходящий симуляцию (iverilog) на эквивалентность эталону.
5. spec/quantum/BIR-to-MPS.md — документ с измеренным χ на артефактах проекта.
