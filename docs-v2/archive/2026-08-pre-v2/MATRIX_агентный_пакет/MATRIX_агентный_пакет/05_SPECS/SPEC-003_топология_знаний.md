# SPEC-003: Топология знаний (Ricci-анализ графов, drift-fingerprint, curriculum-ordering)

**Статус: normative · v1.0 (2026-07-31)** · Исследовательский трек T7. Обоснование: science/FOUNDATIONS.md §1.4 (дискретный поток Риччи), §4.2 (химические организации), §3.2 (гиперцикл/устойчивость сети знаний).

## 1. Цель

Инструментарий структурного анализа графов знаний (Neo4j в rag-system; Knowledge Stack; позже Noosphere mesh):
1. семантические сообщества и хрупкие мосты (отрицательная кривизна Олливье–Риччи);
2. **fingerprint дрифта**: распределение кривизны рёбер как компактная подпись графа; сдвиг подписи = ранний детектор деградации Knowledge Stack (дополнение к HierarchicalMemory drift detection);
3. **curriculum-ordering**: обход графа от плотных (положительно-искривлённых) кластеров наружу = автоматический порядок обучения «от простого к сложному» для Developmental Loop (SPEC-000);
4. детекция пробелов знания: «дыры» (persistent homology, TDA) = кандидаты в исследовательские гипотезы (research/HYPOTHESES.md).

## 2. Требования

- **FR-1.** Экспортер графа: Neo4j → взвешенный неориентированный граф (узлы = сущности/документы, рёбра = отношения с весами retrieval-статистики); версия экспорта — хэш в отчёте.
- **FR-2.** Вычисление кривизны Олливье–Риччи на рёбрах. Реализация: Java-модуль `matrix-ricci` (оптимальный транспорт по рёбрам — малая размерность, достаточно Java; допустим research-прототип на Python с GraphRicciCurvature [^144^] для сверки чисел, но продакшн-путь — Java).
- **FR-3.** Итеративный поток Риччи (N итераций, конфиг) → Ricci-flow метрика; проверка контрактивности/монотонности процесса (Статья III: Φ = суммарная дисперсия кривизны по рёбрам, не возрастает; нарушение — остановка, отчёт).
- **FR-4.** Отчёты: топ-k хрупких мостов (min κ), сообщества (порог по κ после потока), fingerprint (гистограмма κ, 64 бина) + расстояние между fingerprint'ами (Wasserstein-1) для дрифта.
- **FR-5.** EXP-004 (preregistered): на контролируемом эксперименте — намеренная деградация графа (удаление 5% рёбер случайно vs целенаправленно мостов): fingerprint-детектор обязан отличить деградацию от нормального пополнения графа (ROC/AUC ≥ 0.8, FOUNDATIONS §5.3) раньше, чем падает Recall@5 golden-набора.
- **FR-6.** Curriculum-ordering: экспорт приоритетной очереди узлов для SPEC-000 (плотность кластера ↓ к периферии); метрика — скорость прохождения этюдов при обучении по ordering vs случайный порядок (EXP-004b, опционально этап 3).
- **FR-7.** TDA-прототип (research/): persistent homology H₁ на графовой фильтрации; «дыры» выгружаются как черновики гипотез с пометкой proposed.

## 3. Инварианты

- INV-1: анализ read-only по отношению к графу знаний; никаких записей в Neo4j из matrix-ricci.
- INV-2: воспроизводимость: фиксированный экспорт + параметры потока → идентичный fingerprint.
- INV-3: интерпретируемость отчётов: каждый «хрупкий мост» и каждая «дыра» сопровождаются человекочитаемым контекстом (оба конца ребра, цитаты) — решение принимает человек.

## 4. Метрики

AUC детекции деградации (EXP-004) · стабильность fingerprint на недельном окне (σ расстояния) · доля подтверждённых владельцем «хрупких мостов» (precision по ручной выборке 20) · выигрыш curriculum-ordering (EXP-004b).

## 5. Критерии приёмки

1. Java-модуль с тестами; сверка чисел κ с эталонным Python-вычислением на 3 фиксированных подграфах (расхождение < 1e-6).
2. EXP-004 принят по протоколу (включая отрицательный результат).
3. Fingerprint-датчик подключён к мониторингу: алерт при превышении порога расстояния (порог — по σ нормального окна, 3σ).

## 6. Задачи (sketch)

1. Экспортер Neo4j → граф (версии, хэши).
2. matrix-ricci: OT-решатель рёбер, κ-вычисление, поток, Φ-контроль.
3. Fingerprint-сервис: гистограммы, Wasserstein, алертинг.
4. Отчётный генератор (хрупкие мосты, сообщества, контексты).
5. EXP-004/004b карточки → запуск → отчёты.
6. TDA-прототип в research/ (Python допустим только здесь).
