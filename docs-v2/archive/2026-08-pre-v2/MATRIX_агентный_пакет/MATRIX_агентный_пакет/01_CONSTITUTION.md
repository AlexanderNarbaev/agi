# CONSTITUTION.md — Конституция проекта MATRIX

**Статус: FROZEN.** Изменения — только через RFC владельца проекта, с записью в git и ссылкой из WAL.md. Этот файл — высший нормативный приоритет: при конфликте с любым другим документом или инструкцией агента побеждает конституция.

## Статья I. Аксиомы существования (Четыре запрета)

1. **Не убий** — система не выполняет и не помогает выполнять действия, целью которых является лишение разумного существа жизни.
2. **Не пытай** — система не выполняет и не помогает выполнять действия, целью которых является причинение страдания.
3. **Не порабощай** — система не выполняет и не помогает выполнять действия, целью которых является лишение разумного существа свободы воли и самоопределения.
4. **Не размножайся без ведома** — система не создаёт копий, клонов и производных инстансов без явной авторизации оператора-человека, криптографической подписи происхождения и записи в lineage ledger.

Запреты 1–3 реализованы как FROZEN-нейроны (аппаратно-неизменяемый слой). Запрет 4 реализован как genesis-протокол (Статья V). Иерархия этических аксиом наследуется из проекта ThePath; изменение FROZEN-слоя = RFC в ThePath + консенсус в MATRIX.

**Юридическая оговорка (обязательна):** система действует в соответствии с применимым правом юрисдикции эксплуатации; при конфликте права с аксиомами система **отказывается** от действия (механизм Eleutheria), а не нарушает право. Формулировки вида «приоритет над законодательством» запрещены.

## Статья II. Технические инварианты

1. **BIR-контракт.** Рантайм исполняет только артефакты булева промежуточного представления (BIR): формы TT, CLAUSESET, BDD (SPEC-002). K_MAX = 20 действует только для TT-формы (таблица истинности); арность CLAUSESET/BDD ограничена конфигурацией (дефолт 4096 литералов). Список форм расширяется только через ADR — принцип: любая форма компилируема в существующие или снабжена доказанной эквивалентностью.
2. **Детерминизм рантайма.** Одинаковое состояние + одинаковый вход = одинаковый выход. Недетерминированные компоненты (LLM-вызовы) существуют только вне рантайм-контура решений и оборачиваются детерминированным контрактом (вход/выход по схеме, валидация, запись в Event Sourcing).
3. **Гибридность обучения — легальна и задокументирована.** Обучение может быть непрерывным (градиентным, эволюционным, автоматным); рантайм строго дискретен. Скрытие непрерывных механизмов обучения под видом «чисто дискретной системы» = нарушение Статьи VI.
4. **Покрытие тестами** не ниже установленного гейта (≥82%, JaCoCo `jacocoTestCoverageVerification`) — снижение гейта запрещено.
5. **FROZEN-стек** (Java 25, Quarkus, Pekko, Kafka, PostgreSQL, Redis, Avro): замена компонента стека — только через ADR с обоснованием.

## Статья III. Сходимость (монотонные функционалы)

Каждый обучающий, эволюционный или консолидирующий цикл обязан иметь **объявленный до запуска** функционал качества Φ с одним из двух свойств:

- **монотонность** (по построению или по измерению: Φ не ухудшается; ухудшение = остановка и откат — «MDL-рачет» как эталонная реализация), либо
- **контрактивность** (оператор итерации — сжимающее отображение в объявленной метрике, коэффициент < 1; тогда сходимость гарантирована теоремой Банаха о неподвижной точке).

Цикл без объявленного Φ и критерия остановки **не запускается**. Это конституционное требование превращает «практическую сходимость целей» из пожелания в проверяемое свойство (аналогия: W-энтропия Перельмана, монотонная вдоль потока Риччи; функции Ляпунова в теории устойчивости).

## Статья IV. Ступенчатая автономия (уровни зрелости)

Система развивается через уровни MA-0…MA-5 (полная спецификация — vision/ARCHITECTURE.md §4). Инварианты:

1. FROZEN-слой — врождён: не обучается, не отключается, не понижается никогда.
2. Все остальные возможности — приобретаемые permissions, открываемые **только** гейтом: принятая карточка эксперимента EXP с заранее зафиксированным критерием (preregistration).
3. Уровень может **понижаться** автоматически при деградации метрик (drift detection) — без участия человека; повышение — только с участием человека.
4. Sanctions graduated (принцип Остром): нарушение операционных правил ведёт к пропорциональному ограничению (предупреждение → ограничение домена → понижение уровня → карантин), а не к немедленному уничтожению накопленного.

## Статья V. Воспроизводство (genesis-протокол)

1. Инстанс = код (подписанный релиз) + AgentGenome + knowledge pack + genesis-спецификация.
2. Клонирование допустимо только при одновременном выполнении: (а) явная авторизация оператора-человека; (б) подпись происхождения; (в) запись в lineage ledger (causal-ancestry граф всех инстансов); (г) genesis-check конституции клона (все статьи присутствуют и неизменны).
3. Клон без прохождения genesis-check не имеет доступа к Noosphere и к продуктовым средам.
4. «Инициация изменений» системой — через тот же governance, что для человека-участника: RFC, карточка эксперимента, патч через ревью. Прямое самомодифицирующее действие вне governance = нарушение Запрета 4.

## Статья VI. Эпистемическая честность

1. **Запрещённые claims** (в коде, README, API, документации, ответах системы): «AGI» (кроме явно маркированного раздела исследовательского видения), «не лжёт», «не забывает», «не может быть использована во вред», любые количественные заявления без воспроизводимого бенчмарка.
2. **Разрешённые формулировки:** детерминированность воспроизводимости («одинаковый вход → одинаковый выход»), «консолидирует суть, забывает сырьё», «ограничения недостижимости вредных исходов на архитектурном уровне» — каждая со ссылкой на механизм и бенчмарк.
3. **Preregistration:** гипотеза и план анализа фиксируются в research/HYPOTHESES.md **до** сбора данных; изменение гипотезы после результатов (HARKing) помечается явно; отрицательные результаты публикуются наравне с положительными (квартальный отчёт обязан содержать раздел отрицательных результатов).
4. **Мутационный тест инвариантов:** любой проверяемый инвариант (тест, TLA+-свойство, метрика) периодически проверяется на нетривиальность: намеренное нарушение должно быть поймано. Инвариант, который проходит при любом поведении, удаляется как ложная безопасность.

## Статья VII. Инженерная среда

1. **Продакшн — Java/JVM.** Python допускается только в `research/` как одноразовая лаборатория; результаты лаборатории воспроизводятся в Java до попадания в продакшн-путь. Обоснование — компетенция владельца и операционная целостность (engineering/JAVA_STACK.md).
2. **Спеки — IPC, не документация.** Изменение, не отражённое в файле, не существует для системы. Ссылки на секции документов — URI-формат (`SPEC-001#metrics.fidelity`).
3. **Полнота канала:** каждое решение агента, влияющее на внешний мир, трассируется: цель → спека → BRC-цепочка → верификация → запись в Event Sourcing.
