# ADR-005. Трёхзначный вердикт гейтов: accept / reject / undecided, witness обязателен, два класса отказа

- **Статус:** accepted (действует в контуре; зафиксировано как ADR для трассировки)
- **Дата:** волна 6 документации
- **Связи:** DESIGN-03 §3/§4, CONSTITUTION (Статья VI), HYPOTHESES H-017, C4 (контур запроса), FR-03, NFR-13

## Контекст

Каждый гейт системы (Φ-гейт обучения, M4-гейты интеграции, guardrail, BRC-шаги) выносит вердикт о приёме артефакта/решения. Двузначная схема (да/нет) вынуждает либо принимать при недостатке данных, либо отклонять как будто доказано плохое — оба исхода нарушают честность (Статья VI: «пробел — не ложь»). Нужна дисциплина вердиктов, совместимая с композицией (цепочки BRC), аудитом (witness) и отказами (Eleutheria).

## Решение

1. **Три вердикта:** accept / reject / **undecided**. UNDECIDED — первоклассный результат «недостаточно данных/бюджета», а не ошибка и не молчаливый reject.
2. **UNDECIDED заразителен по сильной связке Клини:** шаг с неполным witness → вся цепочка не может accept; итоговый ответ контура обязан нести метку standpoint (по какой точке зрения/при каких допущениях выдан).
3. **Witness обязателен при любом вердикте:** accept — свидетель приёма (что именно повлияло); reject — класс отказа + основание; undecided — чего не хватило (данные, бюджет, фрагмент).
4. **Два класса отказа:** reject-by-budget (исчерпан бюджет/фрагмент — мягкий, с меткой) и reject-by-proof (хранимый контрпример — сильный, сильное отрицание Заславского). Класс отказа — часть вердикта, не комментарий.
5. **Типология отказов** фиксируется по хетучакра (§30): каждый reject/undecided получает тип нарушения из закрытого реестра.

## Основания (атлас)

- Трёхзначная логика Клини и решётка фрагментов — польская школа (§10); сильная связка как закон распространения.
- Авактавья и сьядвада — джайнская линия (§30): «невыразимо» легитимно, вердикт префиксован standpoint («сьят»).
- BHK — нидерландская линия (§28): утверждение есть конструкция (свидетель) или честный отказ; нет конструкции — нет accept.
- Хетучакра Дхармакирти (§30) — типология невалидных оснований → реестр типов отказов гейтов.
- Сильное отрицание Заславского (§21) — отказ с контрпримером как хранимый артефакт lineage.

## Последствия

**Положительные:**
- Система никогда не вынуждена «угадывать»: при недостатке данных — измеримый, аудируемый UNDECIDED (метрика доли UNDECIDED входит в коридоры гомеостата, ADR-004).
- Отказы объяснимы по построению: класс + тип + witness — достаточно для внешнего аудита (G-C).
- Композиция безопасна: частичная неопределённость не маскируется в уверенный ответ.

**Отрицательные / цена:**
- Доля UNDECIDED может расти на бедных доменах; это сигнал коридоров, а не дефект — но требует дисциплины standpoint-меток во всех интерфейсах (NFR-13).
- Хранение контрпримеров (reject-by-proof) увеличивает lineage; митигируется политикой забывания сырья (DESIGN-05 §4) при сохранении самих вердиктов.

## Отвергнутые альтернативы

- **Двузначные гейты с порогами уверенности:** порог — скрытое допущение; при переносе домена порог лжёт (нарушение Статьи VI).
- **Вероятностные вердикты в ядре:** градации истины в ядре запрещены задокументированным отказом от fuzzy (§22, граница №4 SYSTEM-SYNTHESIS); мягкость — только в интерфейсе читаемости.
- **Молчаливый reject:** эквивалентен потере witness; запрещён — любой reject несёт класс и основание.

## Проверяемость

- Каждый BRC-шаг в трассе несёт вердикт + witness (контракт DESIGN-03); CI-проверка: цепочка с хотя бы одним undecided-шагом не выдаёт accept.
- Реестр типов отказов версионируется; новый тип — только с типологией хетучакра и ADR-правкой.
- LTL-инварианты контура (H-017) включают: «accept ⇒ полный witness» и «reject ⇒ (класс ∈ {budget, proof}) ∧ основание».
