# DESIGN-10. Бинарный резервуар

## 1. Назначение

Модуль динамической памяти для узлов с временны́м входом (сигналы, потоки
событий): необучаемое бинарное рекуррентное ядро (reservoir) поверх гипервекторов,
кодирующее историю окна в состояние фиксированного размера, + обучаемый за один
проход бинарный readout (TT / WiSARD-класс). Реализует линию intESN (ATLAS §5/§15)
в рамках BIR-совместимости: ни одного float, состояние — битовый массив, вся
арифметика — `long[]`-операции (JAVA_NATIVE).

**Место в системе:** M0 (динамика узла) и ReflexLayer (реактивные паттерны);
кандидатский субстрат для FNL (DESIGN-07) — ансамбль несвязанных резервуаров
с прогнозными кодами вместо обучения всей иерархии разом.

## 2. Интерфейс

```java
public final class BinaryReservoir implements SignalModule {
    public static final int D = 8192;            // размерность гипервектора

    BinaryReservoir(NodeId node, ReservoirConfig cfg, ItemMemory memory);
    void step(long[] packedInput);               // один такт: вход n бит (n ≤ 64)
    long[] state();                              // текущее состояние, D/64 = 128 слов
    void attachReadout(Readout ro);              // TT или WNN над окном из k бит
    Witness witness();                           // provenance: seed, такты, configHash
}
```

`ReservoirConfig` в ioSchema узла: `seed` (u64, фиксирован), `inputBits n`,
`readoutWindow k ≤ 20`, `readoutType ∈ {TT, WNN}`. `ItemMemory` — детерминированный
генератор атомарных гипервекторов: `u_HD(i) = splitmix64_expand(seed, i)` —
i-му входному значению соответствует битово воспроизводимый вектор.

## 3. Ядро: шаг обновления

```
state x ∈ {0,1}^D, инициализируется нулями.
Такт t, вход v_t (n бит):
    u ← itemMemory.encode(v_t)                 // атомарный гипервектор входа
    x ← bundle( Sh(x, 1), u )                  // циклический сдвиг + мажоритарность

bundle(a, b)[i] = a[i] OR b[i]  при tie → детерминированное разрешение:
    majority двух слагаемых не определён → правило: tie := бит i паритета такта (t AND 1)
    (правило фиксировано в config; любое фиксированное правило сохраняет
     детерминизм, выбрано простейшее)

Sh(x, s) — циклический сдвиг на s позиций внутри 128 слов:
    словесный сдвиг + межсловный перенос; O(D/64) = 128 словесных операций.
```

Стоимость такта: ≤ 4·128 = 512 словесных операций (сдвиг, OR, tie-маска, запись).
Состояние — 1 КБ. Память входа — экспоненциальное затухание: вклад v_{t−τ} в x_t
размывается мажоритарностью; глубина окна — гиперпараметр эксперимента EXP-015.

## 4. Readout

```
Окно: детерминированный выбор k ≤ 20 бит состояния: positions[i] = (i·D/k) mod D
(равномерная решётка, фиксирована в config — никакой случайности вне seed).

TT-readout:  k адресных бит → long[] LUT (как везде в BIR); обучение —
             один проход по обучающей последовательности, таблица частот;
             разрешение — мажоритарный класс; tie → класс с меньшим id (детерминизм).
WNN-readout: k бит разбиваются на t кортежей по τ бит (τ·t = k);
             каждый кортеж — адрес в RAM-узле; обучение — установка битов;
             ответ — сумма (порог) — бинарный классификатор без умножений.

Ограничение k ≤ 20 — то же, что у TT-линии: таблица ≤ 1 Мбит = 128 КБ.
```

## 5. Invariants

- **INV-BR1 (детерминизм):** при фиксированном seed и входной последовательности
  состояние после T тактов битово воспроизводимо на любой платформе (только
  `long`-операции, никаких float, никакого порядка суммирования).
- **INV-BR2 (бюджет):** такт ≤ 512 словесных операций + readout ≤ 2^τ обращений
  к RAM-узлам (WNN) или 1 чтение LUT (TT); состояние ровно 1 КБ; таблица ≤ 128 КБ.
- **INV-BR3 (изоляция seed):** seed живёт в ioSchema узла и входит в configHash;
  смена seed = новый артефакт (новый id), а не мутация.
- **INV-BR4 (BIR-совместимость):** модуль реализует ioSchema-контракт `SignalModule`;
  выход readout — биты/класс, свидетельство `Witness` (seed, такты, configHash)
  прикрепляется к каждому предсказанию (provenance для FNL/Cauldron).

## 6. Честные границы

- Резервуар — **не** идентификация системы: это эмпирический динамический
  признак, качество измеряется только экспериментально (EXP-015: разрыв точности
  ≤ 3 п.п. против float-ESN при энергии ≤ 0.1×).
- Глубина памяти окна зависит от D и правила tie; теоретической гарантии
  «помнит ровно τ тактов» нет — измеряется кривой запоминания на домене.
- WNN-readout чувствителен к выбору кортежей; решётка positions фиксирована,
  но её качество на конкретном домене — эмпирика, а не теорема.
- Если EXP-015 покажет разрыв > 3 п.п. на обоих доменах — фиксируется
  честный отказ (fork, §15.4 ATLAS): packed bit-matching / κ=3 intESN как
  отдельный кандидат с своей карточкой гипотезы.

## 7. Приёмочные тесты

| Тест | Содержание | Критерий |
|---|---|---|
| AT-BR1 | Детерминизм: 5 прогонов одной последовательности 10⁴ тактов | Битовое совпадение state() во всех прогонах (INV-BR1) |
| AT-BR2 | Бюджет: замер операций на такт и размера состояния | ≤ 512 словесных ops/такт; state = 1024 байта ровно (INV-BR2) |
| AT-BR3 | Воспроизводимость ItemMemory: u_HD(i) при seed из config | Совпадение с эталонным splitmix64_expand на 1000 входах (INV-BR3) |
| AT-BR4 | Затухание памяти: импульс на входе, отслеживание его следa в x | Кривая сходства монотонно убывает; глубина записана в witness |
| AT-BR5 | Readout: TT и WNN обучаются за один проход на синтетической временно́й задаче (parity по окну) | Точность ≥ базовой линии WNN-статьи; обучение — один проход, без итераций |
| AT-BR6 | Provenance: каждое предсказание несёт Witness | Поля seed/такты/configHash заполнены; configHash меняется при смене seed (INV-BR4) |
