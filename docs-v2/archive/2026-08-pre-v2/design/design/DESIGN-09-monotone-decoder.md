# DESIGN-09: MonotoneDecoder — producer монотонных CLAUSESET по схеме Ханселя/Кабулова–Норматова

**Статус: draft** · Уровень: producer BIR (SPEC-002 FR-C). Основания: ALGORITHM-ATLAS §6.1, §14 (математическая база); HYPOTHESES H-016, EXP-016. Реализация: Java 25 (правила JAVA_NATIVE), пакет `bir.producers.monotone`.

## 1. Назначение и область

Producer, восстанавливающий **монотонную булеву функцию** из запросов к оракулу (корпус / учитель / среда) с минимаксно-оптимальным числом запросов (теорема Ханселя). Выход — CLAUSESET (монотонная DNF: импликанты = минимальные единицы), заголовок provenance `producer=MonotoneDecoder`.

**Область применимости (жёсткие предусловия):**
1. Монотонность — задекларированный инвариант ioSchema домена (`monotone=true`, направление монотонности по каждому биту: ↑ или ↓; биты ↓ предварительно инвертируются перекодированием).
2. bitWidth n ≤ 20 (при n=20 худший случай ~352к запросов; рекомендуемый рабочий диапазон n ≤ 16 — ≤12870 цепей, минимакс φ(16) = 25755 запросов).
3. Оракул детерминирован (один и тот же запрос → одна и та же метка); шумные оракулы — вне области (кандидат: усреднение окном, отдельный EXP).

**Запрещено:** применять к доменам без задекларированной монотонности; скрыто расширять на немонотонные функции (декомпозиция на монотонные слои — отдельный документ, не здесь).

## 2. Структуры данных

```
record Chain(int id, int[] members)          // members — индексы вершин куба, упорядочены по возрастанию веса
record ChainState(int lo, int hi)            // интервал неопределённости внутри members: вершины < lo классифицированы 0, > hi — 1... 
```

Точнее, инвариант состояния цепи: вершины с индексом позиции `< loPos` — установленные нули, `> hiPos` — установленные единицы, диапазон `[loPos..hiPos]` — неопределённость. Инициализация: `loPos=0, hiPos=len-1`.

- **Представление вершин:** индекс вершины куба = int (n ≤ 20 → 2^20 значений, не материализуются; вершина — битовая маска входа, long).
- **Таблица принадлежности:** `chainOf[vertex] → chainId`, `posInChain[vertex] → позиция`. Память: 2 записи на вершину цепи, но вершины хранятся только в цепях — суммарно O(2^n) записей по 12 байт off-heap = 12 МБ при n=20, 0,8 МБ при n=16. Не материализуем полный куб: таблица строится лениво по запросам (hash-map vertex → (chainId,pos), заполняется при построении цепей — цепи строятся полностью, это O(2^n) вершин однократно).
- **Офф-хип:** арена цикла (DESIGN-07 §2): одна арена на сессию декодирования; после выхода — арена закрывается, результат компилируется в кучный CLAUSESET.

## 3. Построение цепей Ханселя

Детерминированная рекурсивная конструкция (ALGORITHM-ATLAS §14, [^333^]):

```
hanselChains(n):
    если n == 1: return [[{0},{1}]]                     // одна цепь из двух вершин
    C ← hanselChains(n-1)                               // цепи куба размерности n-1
    // каждая цепь c = [v1 < v2 < ... < vm] порождает до двух цепей размерности n:
    //   c'  = [v1·0, v2·0, ..., vm·0, vm·1]             // нижняя половина + верх старшего
    //   c'' = [v1·1, v2·1, ..., v{m-1}·1]               // верхняя половина без верха (если m > 1)
    для каждой цепи c в C (в порядке обхода):
        выдать c'
        если |c| > 1: выдать c''
```

Свойства (гарантии конструкции): цепи попарно непересекающиеся, покрывают Bⁿ, симметричны относительно средних слоёв; число цепей = C(n, ⌊n/2⌋); длины — n−2i+1 с мультипликитетом C(n,i)−C(n,i−1). Порядок обхода фиксирован кодом → побитовая воспроизводимость (NFR-04).

**Бюджеты построения:** время O(2^n), память O(2^n) записей; при n=16 — 65 536 вершин, 12 870 цепей, < 5 мс JVM; однократно на схему, кэшируется в реестре схемы (schema_hash → сериализованные цепи).

## 4. Алгоритм декодирования

```
decode(oracle, budget):
    chains ← hanselChains(n)
    states ← [ChainState(0, |c|−1) для каждой цепи]
    queue  ← все цепи с непустой неопределённостью, упорядоченные по (−|интервал|, chainId)
    asked  ← 0
    пока queue непуст и asked < budget:
        chain ← первый из queue
        (lo, hi) ← states[chain]
        // правило выбора запроса (детерминированное, фиксировано здесь):
        pos ← (lo + hi) / 2                                 // середина интервала, округление вниз
        v   ← chains[chain].members[pos]
        y   ← oracle.ask(v); asked++
        propagate(v, y, states)                             // см. ниже
        перестроить queue (цепи с пустым интервалом удаляются, порядок — тот же компаратор)
    если queue непуст: return PARTIAL(states, asked)        // бюджет исчерпан — частичный артефакт
    return COMPLETE(minOnes(states), asked)
```

**propagate(v, y):** для всех вершин u, сравнимых с v (u ≤ v при y=1 → u=1; u ≥ v при y=0 → u=0), обновить состояние их цепей. Реализация: наивный перебор 2^n сравнимых — O(2^n) на запрос неприемлем; используем структуру цепей: в каждой цепи бинарный поиск позиции v (если v ∈ цепи) и сдвиг границ; для вершин вне цепи v — распространение идёт через отношение порядка: реализация хранит для каждой цепи интервал, а propagate итерирует по **запросам-ключам** (в каждой цепи хранятся только два ключевых примера — текущий максимальный верхний нуль и минимальная нижняя единица, протокол Ковальчука–Триантафиллу шаги 3–7 [^332^]): вершина классифицируется выводимо, если она ≥ какого-то известного нуля (при y=0 логика зеркальна). Проверка выводимости вершины u: `u & ~knownOne == 0` для некоторой известной единицы — O(число ключевых примеров) на вершину; сами вершины не перебираются — только границы цепей.

**minOnes(states):** восстановленная граница: минимальные единицы = вершины, помеченные 1, все непосредственные нижние соседи которых — 0; компиляция в CLAUSESET: каждая минимальная единица с маской m (биты, равные 1) → клауза конъюнкции этих битов (монотонная, без отрицаний; биты ↓-направления восстанавливаются обратным перекодированием).

## 5. Выход и инварианты

- **COMPLETE:** CLAUSESET с provenance {producer: MonotoneDecoder, n, asked, schema_hash, oracle_id}; fidelity=1.0 относительно оракула (восстановление точное — свойство минимаксного алгоритма, не оценка).
- **PARTIAL:** не выпускается как артефакт; состояние интервалов сериализуется (resume-файл), декодирование продолжается при пополнении бюджета. Частичные предсказания возможны только на выводимых вершинах — вне контракта producer (см. дисциплину пробелов ATLAS §10).
- **INV-MD1 (оптимальность):** asked ≤ φ(n) = C(n,⌊n/2⌋) + C(n,⌊n/2⌋+1) для любого оракула (минимакс Ханселя). Проверяется утверждением в тестах на n ≤ 12 полным перебором случайных монотонных функций.
- **INV-MD2 (детерминизм):** при фиксированном оракуле и бюджете — побитово одинаковая последовательность запросов и итоговый артефакт (5 прогонов).
- **INV-MD3 (монотонность выхода):** результирующий CLAUSESET не содержит отрицаний (после обратного перекодирования ↓-битов — только задекларированные знаки).

## 6. Сложности и бюджеты (итоговые)

| Величина | n=12 | n=16 | n=20 |
|---|---|---|---|
| Цепей C(n,⌊n/2⌋) | 924 | 12 870 | 184 756 |
| Минимакс запросов φ(n) | 1 672 | 25 755 | 352 716 |
| Память (таблицы вершин) | 0,05 МБ | 0,8 МБ | 12 МБ |
| Построение цепей | <1 мс | <5 мс | ~80 мс |
| Запрос (выбор + propagate) | ~2 мкс | ~4 мкс | ~8 мкс |

Числа — оценки порядка (замеряются в EXP-016, JMH); оракул «корпус» — O(1) поиск по хэшу; оракул «учитель/среда» — внешняя latency вне бюджета JVM.

## 7. Интеграция

- **SPEC-002 FR-C:** регистрация producer'а `MonotoneDecoder` рядом с TsetlinTrainer/WNN-producer; выбор producer'а — конфиг домена (`producer=auto`: монотонные схемы с n≤16 → MonotoneDecoder, иначе — по лестнице EXP-002/010/016).
- **DESIGN-04:** оракул-учитель — тот же интерфейс TeacherOracle (интерактивное обучение); resume-файлы PARTIAL — в M2 (долгоживущее состояние обучения), не в M1.
- **Cauldron (DESIGN-07):** дешёвый producer для монотонных рядов — кандидатный шаг генерации (ряд «монотонных восстановлений»); бюджет запросов — из бюджета цикла (activity.budget).
- **EXP-016:** критерии H-016 (образцы до порога ≤0.2× TsetlinTrainer на ≥2 монотонных доменах); сверка формул propagate с первоисточниками [^332^][^334^] ATLAS перед реализацией — обязательный чек в ревью.

## 8. Приёмочные тесты

- **AT-MD1 (оптимальность):** 100 случайных монотонных функций n=12 (генерация — случайная антицепь); asked ≤ 1672 для всех; восстановленный CLAUSESET BDD-эквивалентен истинной функции.
- **AT-MD2 (детерминизм):** 5 прогонов на фиксированной функции — идентичная последовательность запросов (хэш списка запросов совпадает).
- **AT-MD3 (отказ бюджета):** budget=100 при n=16 → PARTIAL, resume-файл читается, продолжение с остатком бюджета даёт тот же результат, что непрерывный прогон.
- **AT-MD4 (отказ предусловия):** схема без `monotone=true` → отказ запуска с witness (immutability-ошибка конфигурации, не рантайм-исключение).
- **AT-MD5 (интеграция provenance):** заголовок артефакта содержит producer/n/asked/schema_hash; BDD-эквивалентность оракулу на golden-наборе n≤16.
