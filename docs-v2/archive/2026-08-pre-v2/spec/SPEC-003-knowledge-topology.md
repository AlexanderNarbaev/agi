# SPEC-003: Топология знаний (Ricci-анализ графов, drift-fingerprint, curriculum-ordering)

**Статус: normative** · Изменения — с changelog в шапке. Научные основания: docs/science/FOUNDATIONS.md §1.4 (поток Риччи), §3.2 (предел Эйгена, гиперцикл), §4.2 (химические организации).

## 1. Цель

Инструментарий структурного анализа графов знаний (экспорт графа из внешнего retrieval-сервиса — напр. Neo4j проекта rag-system — по контракту ADR-001; локальный индекс Knowledge Stack; позже Noosphere mesh):

1. семантические сообщества и хрупкие мосты (отрицательная кривизна Олливье–Риччи);
2. **fingerprint дрифта**: распределение кривизны рёбер как компактная подпись графа; сдвиг подписи = ранний детектор деградации Knowledge Stack (дополнение к HierarchicalMemory drift detection);
3. **curriculum-ordering**: обход графа от плотных (положительно-искривлённых) кластеров наружу = автоматический порядок обучения «от простого к сложному» для Developmental Loop (SPEC-000);
4. детекция пробелов знания: «дыры» (persistent homology, TDA) = черновики гипотез в research/HYPOTHESES.md (статус proposed).

## 2. Требования

- **FR-1. Экспортер графа:** внешний граф знаний (доступ по контракту ADR-001) → взвешенный неориентированный граф (узлы = сущности/документы, рёбра = отношения с весами retrieval-статистики); версия экспорта — хэш в отчёте. При отсутствии внешнего сервиса — граф строится из локального индекса памяти (DESIGN-05 §3).
- **FR-2. Кривизна:** вычисление кривизны Олливье–Риччи на рёбрах (оптимальный транспорт по рёбрам). Реализация — Java-модуль `matrix-ricci`; допустим research-прототип на Python (GraphRicciCurvature [^144^]) для сверки чисел, но продакшн-путь — Java (CONSTITUTION VII.1).
- **FR-3. Поток Риччи:** N итераций (конфиг) → Ricci-flow метрика; контроль сходимости (CONSTITUTION III): Φ = суммарная дисперсия кривизны по рёбрам, не возрастает; нарушение — остановка, отчёт.
- **FR-4. Отчёты:** топ-k хрупких мостов (min κ), сообщества (порог по κ после потока), fingerprint (гистограмма κ, 64 бина) + расстояние между fingerprint'ами (Wasserstein-1) для дрифта.
- **FR-5. EXP-004 (HYPOTHESES H-004):** контролируемая деградация графа (удаление 5% рёбер случайно vs целенаправленно мостов): fingerprint-детектор обязан отличить деградацию от нормального пополнения (ROC/AUC ≥ 0.8, FOUNDATIONS §5.3) раньше, чем падает Recall@5 golden-набора.
- **FR-6. Curriculum-ordering:** экспорт приоритетной очереди узлов для SPEC-000 (от плотных кластеров к периферии); метрика — скорость прохождения этюдов при обучении по ordering vs случайный порядок (EXP-004b, этап 3 ROADMAP).
- **FR-7. TDA-прототип (docs/research/):** persistent homology H₁ на графовой фильтрации; «дыры» выгружаются как черновики гипотез (proposed), решение принимает человек.

## 3. Инварианты

- INV-1: анализ read-only по отношению к графу знаний; никаких записей во внешний сервис из matrix-ricci.
- INV-2: воспроизводимость: фиксированный экспорт + параметры потока → идентичный fingerprint.
- INV-3: интерпретируемость: каждый «хрупкий мост» и каждая «дыра» сопровождаются человекочитаемым контекстом (оба конца ребра, цитаты).

## 4. Метрики

AUC детекции деградации (EXP-004) · стабильность fingerprint на недельном окне (σ расстояния) · precision подтверждённых владельцем «хрупких мостов» (ручная выборка 20) · выигрыш curriculum-ordering (EXP-004b).

## 5. Критерии приёмки

1. Java-модуль с тестами; сверка чисел κ с эталонным Python-вычислением на 3 фиксированных подграфах (расхождение < 1e-6).
2. EXP-004 принят по протоколу (включая отрицательный результат).
3. Fingerprint-датчик подключён к мониторингу: алерт при превышении 3σ нормального окна.

## 6. Задачи

1. Экспортер Neo4j → граф (версии, хэши).
2. matrix-ricci: OT-решатель рёбер, κ-вычисление, поток, Φ-контроль.
3. Fingerprint-сервис: гистограммы, Wasserstein, алертинг.
4. Отчётный генератор (хрупкие мосты, сообщества, контексты).
5. EXP-004/004b карточки → запуск → отчёты.
6. TDA-прототип в docs/research/ (Python допустим только здесь).
