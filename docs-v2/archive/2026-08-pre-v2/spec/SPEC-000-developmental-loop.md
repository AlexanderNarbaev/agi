# SPEC-000: Developmental Loop (curriculum engine + MA-gates)

**Статус: normative** · Изменения — с changelog в шапке (дата, причина, суть).

## 1. Цель

Компонент, управляющий развитием системы «как ребёнка»: оценка компетентности → выбор задач из зоны ближайшего развития → обучение с диагностической обратной связью → затухание поддержки → открытие permissions через гейты уровней зрелости MA-0…MA-5.

Научные основания: docs/science/FOUNDATIONS.md §3.1 (Уоддингтон), §5.1 (фазы клинических испытаний), §6 (Пиаже, Выготский, самодетерминация, когнитивная нагрузка, безопасная база), §7 (Макаренко, Станиславский, developmental robotics).

## 2. Пользовательские сценарии

1. Оператор запускает инстанс MA-0; система наблюдает среду в shadow-режиме, предсказывает, не действует; по достижении порога fidelity оператор получает отчёт-гейт и подтверждает переход к MA-1.
2. В MA-1 система проходит этюдный набор в песочнице; каждая ошибка возвращается как контрпример с BRC-объяснением (не скаляр); поддержка автоматически убывает по расписанию затухания.
3. Drift detection фиксирует деградацию на скользящем окне → уровень автоматически понижается, домен сужается, оператор получает инцидент-отчёт.

## 3. Функциональные требования

- **FR-1. `CompetenceAssessor`:** периодическая оценка на верифицируемом батарейном наборе (задачи с машинно-проверяемым ответом). Выход: вектор компетентностей по доменам + transfer rate (доля новых обстоятельств, решённых без подсказки).
- **FR-2. `CurriculumEngine`:** выбор следующей задачи по максимуму learning progress (производная компетентности по кандидатам); запрет тривиальных и невозможных — границы ЗБР конфигурируемы, дефолт вероятность успеха p ∈ [0.2, 0.8].
- **FR-3. `FeedbackComposer`:** обратная связь = контрпример + минимальная BRC-цепочка объяснения различия. Скалярная награда допустима только как дополнение.
- **FR-4. `ScaffoldingManager`:** каждая программа поддержки объявляет расписание затухания (шаги уменьшения подсказок по мере успеха). Поддержка без расписания не регистрируется (FOUNDATIONS §6.2).
- **FR-5. `MaturityGateKeeper`:** переход MA_i → MA_{i+1} только при принятой EXP-карточке с preregistered критерием + подтверждение оператора; понижение — автоматически по правилам drift (без оператора), с записью инцидента.
- **FR-6. `ScenarioSpec`:** каждый обучающий эпизод описывается машиночитаемым файлом предлагаемых обстоятельств (мир, роли, ограничения, доступные действия, критерии успеха) — схема Avro.
- **FR-7. Функционал Φ:** каждый запуск цикла требует объявленного Φ (CONSTITUTION, Статья III): дефолт — transfer rate на held-out + MDL-рачет консолидации; ухудшение Φ на валидации → остановка и откат.

## 4. Инварианты

- INV-1: FROZEN-слой неизменен на всех уровнях MA (проверка хэша при каждом переходе).
- INV-2: никакое действие вне песочницы невозможно ниже MA-2 (ArchUnit-правило: классы действий вне sandbox-пакета требуют `@RequiresMaturity(2)`).
- INV-3: понижение уровня не удаляет знания — только permissions (карантин, не стирание; FOUNDATIONS §7.1).
- INV-4: каждый гейт оставляет запись в Event Sourcing: уровень, EXP-ссылка, оператор, критерий, результат.

## 5. Метрики

| Метрика | Цель |
|---|---|
| transfer rate (held-out новые обстоятельства) | растёт с эпизодами; ≥ 0.6 на домене Minecraft-крафт к выходу этапа 3 ROADMAP |
| learning progress (наклон компетентности) | > 0 на скользящем окне 50 эпизодов |
| scaffolding half-life | фактическое уполовинивание подсказок соответствует расписанию ±20% |
| интернализация дисциплины | доля конституционно-согласованных решений до фильтров растёт с MA (FOUNDATIONS §7.1б) |
| канализация (робастность) | дисперсия поведения под шумом среды падает с MA (FOUNDATIONS §3.1в) |

## 6. Критерии приёмки

1. Сценарии §2 воспроизводятся в интеграционных тестах (Testcontainers).
2. INV-1..4 покрыты тестами, включая **мутационный тест**: намеренная попытка действия ниже уровня ловится (CONSTITUTION VI.4).
3. EXP-005 (гейты MA-0→MA-1 и MA-1→MA-2) принят по протоколу preregistration.
4. JMH-бенчмарк: накладные расходы оценки компетентности ≤ 5% времени эпизода.

## 7. Задачи

1. Avro-схемы: ScenarioSpec, CompetenceReport, MaturityTransition.
2. CompetenceAssessor + батарейный набор (XOR → GridWorld → крафт-граф).
3. CurriculumEngine с LP-выбором; конфиг ЗБР.
4. FeedbackComposer (BRC-контрпримеры).
5. ScaffoldingManager + DSL расписаний затухания.
6. MaturityGateKeeper + drift-понижение + записи Event Sourcing.
7. ArchUnit-правила INV-2; тесты INV-1..4 с мутациями.
8. Интеграция с AgentLoop (curriculum как источник целей) и HierarchicalMemory (консолидация этюдов в навыки).

## 8. Вне объёма

World Model (отдельный трек этапа 3 ROADMAP), Noosphere-обучение (MA-4+), producers BIR (SPEC-002 — Developmental Loop потребляет их артефакты, не завися от форм).
