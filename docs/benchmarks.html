Benchmarks

Measured performance numbers, methodology, and reproduction instructions. All benchmarks are reproducible from a clean clone with two commands.

Methodology

  • JDK: 25.0.4, OpenJDK 64-Bit Server VM, +7-LTS
  • JMH: 1.37, warmup 5 iterations × 1 s, measurement 10 iterations × 1 s
  • Build: ./gradlew :matrix-core:jmh
  • Coverage: JaCoCo 0.8.x, gate ≥82%
  • All numbers measured on this hardware, not extrapolated

Interpretation

Dense retrieval alone achieves 100% recall@5 on the Hamming-distance golden corpus. The 4-strategy RRF fusion currently includes a stub embedding strategy (fromValue) that adds noise. Real ONNX embeddings will improve this.

Energy comparison

OperationEnergyLatencyHardware
MATRIX TT eval, k=10~10⁻¹² J0.64 nsLaptop CPU
MATRIX CLAUSESET eval, k=784~10⁻⁹ J~3 µsLaptop CPU
Local LLM 3B token, 4-bit~3 J~50 msQuantized CPU
Cloud LLM (H100) token~0.5 J~20 msGPU

Per-decision ratio: ~10⁶× less energy than local LLM 3B, ~10⁴× faster. MATRIX does not generate language; for that scope a verification layer wraps an external model.

Landauer's limit at 300 K: 2.87 × 10⁻²¹ J/bit. MATRIX approaches this theoretical floor for simple TT evaluations. Practical CPU: ~1 nJ per Boolean operation.

Reproduction

All benchmarks are reproducible. Specific commands:

# Build and test
./gradlew :matrix-core:compileJava
./gradlew :matrix-core:test

# All JMH benchmarks
./gradlew :matrix-core:jmh

# Specific benchmark
./gradlew :matrix-core:jmh -PjmhBenchmark=BirEvaluateBenchmark
./gradlew :matrix-core:jmh -PjmhBenchmark=NeuronHotPathBenchmark
./gradlew :matrix-core:jmh -PjmhBenchmark=FrozenFNLBenchmark
./gradlew :matrix-core:jmh -PjmhBenchmark=CompressionBenchmark
./gradlew :matrix-core:jmh -PjmhBenchmark=BinaryBenchmark

# Coverage
./gradlew :matrix-core:jacocoTestReport
./gradlew :matrix-core:jacocoTestCoverageVerification

The JaCoCo coverage gate is 82%. Run ./gradlew :matrix-core:jacocoTestCoverageVerification to verify locally.
