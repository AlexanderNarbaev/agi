# Глоссарий MATRIX

Термины проекта с переводом на общепринятую терминологию. Брендовые имена сохранены, но каждая внешняя коммуникация обязана давать стандартный эквивалент.

| Термин | Стандартный эквивалент | Суть |
|---|---|---|
| **MPDT-нейрон** | Boolean function unit / truth-table neuron | Вычислительный примитив: булева функция k≤20 входов как таблица истинности или дерево решений. Наследник порогового нейрона Маккалока–Питтса. В целевой архитектуре — TT-форма BIR |
| **BIR** | Boolean Intermediate Representation | Единое представление булевых артефактов: формы TT / CLAUSESET / BDD + заголовок (provenance, fidelity, Φ, хэш). См. SPEC-002 |
| **TT** | Truth table | Плотная таблица истинности, k≤20, каноническая семантика, прямой маппинг на FPGA LUT |
| **CLAUSESET** | DNF/CNF clause set (Tsetlin-style) | Набор конъюнктивных клауз произвольной арности; первичная форма обучения (автоматы Цетлина); каноническая форма — антицепь минимальных клауз (потолок размера — средний слой Спернера); класс k-CNF/DNF ограниченной арности полиномиально PAC-обучаем (Валиант) — историческая санкция базового класса |
| **BDD** | Binary Decision Diagram | Решающая диаграмма; канонична при фиксированном порядке переменных → точная проверка эквивалентности |
| **BRC** | Boolean Reasoning Chain | Многошаговая цепочка булевых выводов (≤5 шагов) с witness-битами; аудируемое объяснение решения |
| **FNL** | Functional Neural Lobe | Кластер нейронов с единой функцией (макро-примитив: счётчик, компаратор, автомат) |
| **Cauldron** | Genesis/compression protocol | Автономное рождение FNL: сжатие кластеров в переиспользуемые функции |
| **HADES** | Damage detection & recovery | Обнаружение повреждений и восстановление кластеров из журнала событий |
| **Eleutheria** | Controlled refusal ritual | Механизм отказа от действия при конфликте требований с аксиомами |
| **FROZEN-слой** | Immutable safety layer | Неизменяемые булевы артефакты, кодирующие Четыре запрета; hash-locked |
| **Медиатор (InstanceMediator)** | Homeostatic driver controller | Существующий компонент (`mediator/InstanceMediator.java`): драйверы Energy/Curiosity/Safety; в целевой архитектуре — детерминированный RequestMediator (DESIGN-02 §6), драйверы — только сигналы куррикулума |
| **Noosphere** | Federated knowledge commons | P2P-сеть обмена знаниями: gossip + CRDT + византийский консенсус + кредитная модель; governance по принципам Остром |
| **Developmental Loop** | Curriculum engine | Управление развитием: оценка компетентности → задачи из ЗБР → затухание поддержки → гейты уровней зрелости |
| **MA-уровни** | Staged autonomy levels | Уровни зрелости MA-0…MA-5: от shadow-режима до наставника; переходы — через preregistered эксперименты |
| **Φ (функционал)** | Monotone quality functional | Объявленная до запуска монотонная метрика обучающего цикла; ухудшение = откат (CONSTITUTION, Статья III); теоретические основания — VC-ёмкость, MDL-форма, PAC-выборочная сложность (волна 14) |
| **MDL-рачет** | Minimum Description Length ratchet | Эталонный Φ: обновление знаний принимается только при уменьшении суммарной длины описания (Риссанен 1978: L(модель)+L(данные‖модель); штраф (k/2)·log n за параметры); кандидат оценивается как ΔL на контрольных эпизодах |
| **ЗБР** | Zone of Proximal Development (Выготский) | Диапазон задач между «тривиально» и «невозможно»; источник задач curriculum |
| **WAL** | Write-Ahead Log | Checkpoint сессии человек-агент (фокус, решения, следующее действие) |
| **Genesis-протокол** | Authorized cloning protocol | Клонирование инстанса: авторизация + подпись + lineage ledger + проверка конституции (Запрет 4) |
| **Lineage ledger** | Causal-ancestry graph | Родословная всех инстансов и артефактов; основа доверия в Noosphere |
| **Substrate Backend** | Hardware execution backend | Исполнитель BIR: JvmSimdBackend → FpgaBackend → QuantumBackend |
| **Preregistration** | Preregistration / registered report | Фиксация гипотезы и плана анализа до сбора данных (защита от HARKing) |
| **BirUnit** | Boolean function unit | Атомарная вычислительная единица: BIR-артефакт с контрактом evaluate (DESIGN-01); наследник термина «MPDT-нейрон» |
| **BirNet** | Boolean network (DAG) | Исполняемая сеть единиц с топологической оценкой — «кластер» (DESIGN-02) |
| **Capability** | Skill with contract | Именованный BirNet + ioSchema + метрики; минимальная единица обучения и замещения |
| **Точка зрения** | Viewpoint (weighted ensemble) | Взвешенный ансамбль Capabilities домена + роутер + калибратор уверенности (DESIGN-02 §4) |
| **Профессионал** | Persona (certified viewpoint) | Точка зрения, сертифицированная в домене (MA-3+), с профилем взаимодействия и accessPolicy (DESIGN-02 §5) |
| **BRC** | Boolean Reasoning Chain | Цепочка шагов размышления: каждый шаг — оценка BIR-узла с witness-битами и читаемым правилом (DESIGN-03 §3) |
| **Witness** | Witness bits / explanation | Подмножество входных битов, механически повлиявших на выход шага; основа объяснимости и отказов |
| **PERCEPTION / DELIBERATION / RENDERING** | Sense → reason → act pipeline | Три стадии контура запроса: кодирование в биты → BRC-размышление → декодирование в действие (DESIGN-03) |
| **Консолидация (CLS-цикл)** | Sleep consolidation | Ночное офлайн-окно: эпизоды → корпус → переобучение через Φ-гейт; забывание сырья политикой (DESIGN-05 §4) |
| **WNN / RAM-узел** | Weightless neural network (WiSARD/ULEEN) | Безвесовая сеть: узел — адресуемая таблица 2^n ячеек, структурно тождественна TT BirUnit; однопроходовое обучение записью по адресу (SUBSTRATE-MODELS §2.2) |
| **SDM** | Sparse Distributed Memory (Kanerva) | Разреженная распределённая память: запись/чтение по радиусу Хэмминга через счётчики с порогом; апгрейд recall в M1 (SUBSTRATE-MODELS §3, DESIGN-05 §3) |
| **VSA / HDC** | Vector Symbolic Architecture / Hyperdimensional Computing | Гипервекторы D=8192 бит: bind=XOR, bundle=majority, перестановка ρ для порядка/ролей; числовое хранение направленных знаний и сигнатур BRC-трасс (SUBSTRATE-MODELS §4.2) |
| **FCA** | Formal Concept Analysis (Ganter–Wille) | Формальный анализ понятий: решётка концептов над булевым контекстом «артефакт × атрибут»; иерархия доменов и кандидаты в инварианты (SUBSTRATE-MODELS §4.1) |
| **CMAC** | Cerebellar Model Articulation Controller (Albus) | Табличный аппроксиматор функций с перекрывающимися решётками; бинарный вариант квантуется в BIR с fidelity 1.0 — лёгкая модель мира (SUBSTRATE-MODELS §5.2) |
| **ReflexLayer** | Cerebellar reflex layer | «Мозжечковый» слой между PERCEPTION и DELIBERATION: expansion-перекодирование + µs-рефлексы, обучение по сигналу ошибки офлайн, FROZEN после сертификации (SUBSTRATE-MODELS §5.1) |
| **Модуль сигналов (SignalModule)** | Signal I/O module (codec with contract) | Изолированный преобразователь «мысль ⇄ медиа»: контракт id/version/direction/mediaType/bitWidth/bitMeaning; BIR внутри, биты+witness снаружи (DESIGN-06) |
| **ModuleRegistry** | Module registry (explicit, frozen) | Реестр модулей сигналов: явная регистрация (R1–R4), детерминированный resolve, freeze после сборки; без ServiceLoader/рефлексии — GraalVM-совместимо (DESIGN-06 §3, JAVA_NATIVE §2) |
| **Cauldron** | Cauldron (self-creation protocol) | Протокол самосоздания элементов: циклы рядов нарастающей сложности (МГУА-стиль) → селекция внешним критерием Φ → рождение BirNet/FNL → lineage; память — одна off-heap арена на цикл, пулинг, без GC-штормов (DESIGN-07 §2) |
| **FNL** | Fresh Neuron Layer | Реестр «свежих нейронов» — недавно рождённых элементов до интеграции: карантин, теневой прогон, promote/demote через M4-гейты (DESIGN-07 §3) |
| **TaskCell** | Task cell (ephemeral instance) | Задачно-специфичный эфемерный инстанс: детерминированный spawn, полный локальный срез контекста задачи, быстрый точный инференс, итог — в общий пул; инварианты INV-TC1/2/3 (нет прямой записи в M2/M3, смерть по бюджету, детерминизм) (DESIGN-07 §4) |
| **Route-drain** | Route drain (sleep) | Снятие роутинга с кластеров на фазу сна/консолидации: внешние сигналы заморожены, интерпретация опыта, атомарный своп снапшотов; инварианты INV-S1 (≤50% доменов), INV-S2 (crash-consistency) (DESIGN-07 §6) |
| **ELSP** | Element Link Security Profile | Профиль безопасности межэлементного протокола: идентичность по ключу Ed25519, подпись каждого сообщения, anti-replay seq, mTLS, ротация ключей; защита от перехвата и подмены (DESIGN-08 §3) |
| **Эдж-профиль (EDGE-0…3)** | Edge inference profile | Профили локального инференса: ноутбук (полный контур) → смартфон → очки/носимые (рефлексы + делегирование) → (перспектива) имплант; один BIR-артефакт на всех профилях (DESIGN-08 §2) |
| **intESN** | Integer Echo State Network | Целочисленная резервуарная сеть (Kleyko et al.): нейроны 3–4 бита, рекуррентность — циклический сдвиг вместо матричного умножения; бинарный вариант проекта — VSA-состояние + перестановка ρ + TT/WNN-readout (ALGORITHM-ATLAS §5, H-015) |
| **MonotoneDecoder** | Monotone function decoder | Producer идентификации монотонной булевой функции по схеме максимального верхнего нуля (территория теоремы Ханселя; школа Кабулова–Норматова, Ташкент) — обучение монотонных CLAUSESET малым корпусом; разбиение Ханселя дилворт-оптимально (ALGORITHM-ATLAS §6.1, §38, H-016) |
| **Нормальный алгоритм** | Markov normal algorithm | Упорядоченная система подстановок: применяется первая подходящая к первому вхождению; остановка — явный статус; модель детерминированных трансформаций артефактов и компилятора форм (ALGORITHM-ATLAS §6.3) |
| **Цепи Ханселя** | Hansel chains | Детерминированное разбиение булева куба Bⁿ на C(n,⌊n/2⌋) непересекающихся симметричных цепей; по Дилворту–Спернеру это минимально возможное число цепей (ALGORITHM-ATLAS §14, §38) — структура данных MonotoneDecoder |
| **Трёхзначный вердикт** | Three-valued gate verdict (Kleene) | Вердикт гейтов accept / reject / undecided: пробел («недостаточно данных») — не ложь; распространяется по композиции как сильная связка Клини (шаг с неполным witness → цепочка не может accept) (ALGORITHM-ATLAS §10, ADR-005) |
| **LTL-инвариант** | Linear temporal logic property | Темпоральная формулировка инварианта контура управления с классом safety/liveness (Манна–Пнуэли); проверяется model checking'ом в CI, не в рантайме (ALGORITHM-ATLAS §13, H-017) |
| **ГУХА** | GUHA (General Unary Hypotheses Automaton) | Метод машинного порождения гипотез (Гайек–Гавранек, 1966): систематический обход пространства гипотез над фиксированным языком атомов с количественной оценкой силы по четырёхпольной таблице сопряжённости; исторический предок генератора кандидатов Cauldron (ALGORITHM-ATLAS §17, H-018) |
| **ItemMemory** | Item memory (VSA) | Детерминированный генератор атомарных гипервекторов входа: u_HD(i) = splitmix64_expand(seed, i); seed живёт в ioSchema узла и входит в configHash артефакта (DESIGN-10, INV-BR3) |
| **LAD** | Logical Analysis of Data (логический анализ данных) | Комбинаторно-булев метод обучения (Хаммер 1986; Крама–Хаммер–Ибараки 1988): бинаризация → паттерны (конъюнкции; простой паттерн ≡ простой импликант) → теория (ДНФ) с обоснованием; прямая родословная CLAUSESET/TsetlinTrainer (ALGORITHM-ATLAS-WAVE4 §25, H-020) |
| **Расписание Левина** | Universal (Levin) search schedule | Чередование программ с долей времени 2^−l(p) на программу длины l: оптимально для задач инверсии с точностью до мультипликативной константы (Левин 1973); в проекте — эвристика распределения бюджетов рядов Cauldron с Kt-скорингом кандидатов (ALGORITHM-ATLAS-WAVE4B §27, H-019) |
| **Трайрупья** | Trairūpya (три признака валидного основания) | Критерий Дхармакирти (VII в.): основание валидно, если (1) присутствует в субъекте, (2) присутствует только в подобных случаях, (3) полностью («эва») отсутствует в неподобных, и это достоверно установлено («нишчитам»); в проекте — гейт приёма клауз продюсерами (ALGORITHM-ATLAS-WAVE4C §30, H-020) |
| **Звезда** | Star (ограниченная звезда AQ) | Множество максимально общих обобщений зерна (позитивного примера), не покрывающих ни одного негативного (Михальски, AQ, 1969); детерминированное расписание зёрен заменяет случайный выбор (ALGORITHM-ATLAS-WAVE4C §31, H-020) |
| **Сьядвада** | Syādvāda (условная предикация) | Джайнская логика: каждый вердикт префиксован «сьят» («в некотором отношении»); саптабханги — семь предикатов включая авактавья («невыразимо»); в проекте — легитимация UNDECIDED с обязательной меткой standpoint (ALGORITHM-ATLAS-WAVE4C §30) |
| **wp-исчисление** | Weakest precondition calculus | Исчисление Дейкстры (EWD 472, 1975): слабейшее предусловие wp(S, R), условия здравости, вывод программы из постусловия; в проекте — дисциплина correctness-by-construction компилятора форм: сторожа выводятся из инвариантов (ALGORITHM-ATLAS-WAVE4B §28) |
| **SOS** | Structural Operational Semantics | Структурная операционная семантика Плоткина (1981): семантика как система переходов, заданная правилами по структуре синтаксиса, со структурной индукцией; формат семантики BRC и исполнения форм (ALGORITHM-ATLAS-WAVE4C §29) |
| **Институция** | Institution (Бёрстолл–Гоген) | Формализация «логической системы»: сигнатуры + предложения + модели + удовлетворение, инвариантное при морфизмах сигнатур; в проекте — хартия сигнатурной/субстратной независимости BIR (NFR-12, ALGORITHM-ATLAS-WAVE4C §29) |
| **Hauptsatz** | Cut elimination theorem (Gentzen) | Теорема устранения сечения (Генцен, 1934/35): любое доказательство переводится в бессеченное со свойством подформулы; следствия — непротиворечивость, разрешимость фрагментов, root-first поиск; в проекте — локальность правил компилятора и бюджетируемость пространства поиска (ALGORITHM-ATLAS-WAVE5 §33) |
| **Принцип максимума** | Pontryagin maximum principle | Необходимое условие оптимального управления (Понтрягин–Болтянский–Гамкрелидзе–Мищенко, 1956–1961): сопряжённая система ψ как теневая цена состояния, игольчатые вариации, bang-bang режимы при линейном гамильтониане; в проекте — теневые цены бюджетов Cauldron и аудируемые предельные режимы (ALGORITHM-ATLAS-WAVE5B §36, H-021) |
| **Принцип оптимальности** | Bellman optimality principle / dynamic programming | Оптимальная политика такова, что оставшиеся решения оптимальны относительно результирующего состояния (Беллман, RAND, 1952–1957); уравнение Беллмана; «проклятие размерности»; в проекте — backward value iteration по бюджетам рядов Cauldron как составное (approximate) DP (ALGORITHM-ATLAS-WAVE5B §36, H-021) |
| **Гомеостат** | Homeostatic control loop (Wiener) | Контур отрицательной обратной связи: отклонение метрики от целевого коридора → минимальная коррекция (Винер, «Cybernetics», 1948; гомеостаз Кэннона); дисфункция = деградация сигнала, а не «сломанная деталь»; в проекте — контур самонаблюдения с версионируемыми коридорами и закрытым меню коррекций (ALGORITHM-ATLAS-WAVE5B §36, H-022, DESIGN-11) |
| **Дисциплина Пеано** | Peano notation design principles | Хартия дизайна нотации (школа Пеано, 1888–1908): один символ — одно значение; новая теория — новые знаки; примитивы по практичности и однозначности, не по минимальности; аудит Kern критерием невводимости Падоа (ALGORITHM-ATLAS-WAVE6 §39) |
| **Forget-restore** | Forget–restore principle (Sambin) | Принцип двухуровневого основания (Самбин–Майетти, MF): экстенсиональные понятия — абстракции интенсиональных с забыванием вычислительной информации, восстанавливаемой при возврате; в проекте — дисциплина связи «спеки ⇄ BIR»: любое экстенсиональное утверждение обязано восстанавливаться в исполняемый контракт (ALGORITHM-ATLAS-WAVE6 §39) |
| **Слои рефайнмента** | Refinement layers (seL4 method) | Лестница спецификаций с теоремами связи (абстрактная → исполняемая → реализация), каждая пара связана форвард-симуляцией при общем инварианте; инвариант доказывается раньше кода (опыт seL4, NICTA/UNSW); в проекте — цепочка SPEC → DESIGN → прототип → JVM-код с AT-тестами соответствия трасс (ALGORITHM-ATLAS-WAVE6 §40, H-017) |
| **Акцептор результата** | Action-result acceptor (Anokhin) | Опережающий эталон ожидаемого результата акта (Анохин, теория функциональных систем, 1935+): формируется до действия и сверяется с обратной афферентацией; в проекте — ожидаемый свидетель BRC-акта: тип/форма свидетеля, коридор телеметрии и критерий остановки объявляются до запуска; рассогласование ≡ UNDECIDED + перепланирование (ALGORITHM-ATLAS-WAVE7 §41, DESIGN-11/12) |
| **Три блока Лурия** | Luria's three functional units | Правило композиции (Лурия, «Основы нейропсихологии», 1973): любая функция требует совместной работы энергетического блока (тонус), информационного блока (приём/хранение) и блока программирования/контроля (сличение результата с программой); в проекте — каждый компонент обязан иметь бюджетный аспект, функцию над BIR и самоконтроль (сверку со спецификацией) (ALGORITHM-ATLAS-WAVE7 §41) |
| **Автоматизация (Бернштейн)** | Skill automatization (Bernstein levels) | Выработка фоновых уровней построения движения и их срабатывание с ведущим уровнем (Бернштейн, «О ловкости и её развитии»): внимание нужно только ведущему уровню; в проекте — FNL-продвижение ≡ автоматизация (k подряд accept'ов), DEMOTED при дрейфе ≡ интерференция уровней, перенос навыка ≡ реиспользование свидетельствованных подтрасс (ALGORITHM-ATLAS-WAVE7 §41, DESIGN-12) |
| **Импасс** | Impasse (Soar) | Ситуация недостатка знаний в решающем цикле (Лэрд–Ньюэлл–Розенблюм): типы state no-change / operator tie / operator no-change / conflict, автоматическое субцелеполагание; в проекте — классификация причин UNDECIDED, порождающая подцель-TaskCell с бюджетом и дедлайном (ALGORITHM-ATLAS-WAVE7 §42, ADR-005, DESIGN-12) |
| **Чанкинг** | Chunking (Soar) | Компиляция разрешённой подцели в переиспользуемую продукцию по back-tracing условий из суперсостояния; корректен только при детерминированности подсостояния; в проекте — свидетельствованная компиляция детерминированной подтрассы в SHADOW-кандидат FNL (origin=CAULDRON); недетерминированная ветвь — в журнал, но не в правило (ALGORITHM-ATLAS-WAVE7 §42, DESIGN-12) |
| **Фильтр Бродбента** | Early-selection filter (Broadbent 1958) | Селекция сенсорного потока по физическим признакам (канал, источник) до семантического анализа, с измеримой ценой переключения канала; в проекте — дешёвый предфильтр входного потока по типу/источнику/схеме, параметр коридора телеметрии; конституционные триггеры проходят всегда (аттенюация Трейсман) (ALGORITHM-ATLAS-WAVE7 §43, DESIGN-11) |
| **Интеграция признаков** | Feature Integration Theory (Treisman & Gelade 1980) | Признаки кодируются параллельно, связывание в объект требует фокуса; поиск по признаку — pop-out, по конъюнкции — сериален; иллюзорные конъюнкции при перегрузке; в проекте — двухстадийный поиск в памяти: скетч/индекс-кандидаты (pop-out) → обязательная точная проверка-связывание («кандидат ≠ факт») (ALGORITHM-ATLAS-WAVE7 §43) |
| **Глобальное вещание** | Global broadcast (Baars GWT 1988) | Публикация победившего в конкуренции содержания всем потребителям системы; в проекте — событийная шина свидетельств: «платный» broadcast только итогов, прошедших гейт; промежуточные состояния локальны и умирают с TaskCell; феноменальное сознание не моделируется (Статья VI) (ALGORITHM-ATLAS-WAVE7 §43) |
| **САА** | System of algorithmic algebras (Glushkov) | Двухосновная алгебраическая система (Глушков, 1961–1965): порождающая алгебра операторов + алгебра трёхзначных логических условий; теорема регуляризации (приведение произвольного алгоритма к структурированной форме); в проекте — формальная модель компилятора BIR: операторы композиции + трёхзначные вердикты, проходы = эквивалентные преобразования с BDD-сертификатом (ALGORITHM-ATLAS-WAVE8 §44) |
| **Happened-before** | Lamport causal ordering (1978) | Строгий частичный порядок событий распределённой системы: порядок в процессе, отправка→получение, транзитивность; логические часы дают a→b ⇒ C(a)<C(b) (обратное — только векторные часы); в проекте — нормативная семантика журнала M4: метка логического времени в событии, снимок ≡ согласованный срез, lineage ≡ причинный конус; часы — координаты аудита, не физическое время (ALGORITHM-ATLAS-WAVE8 §45, DESIGN-05/08) |
| **Бригада вёдер** | Bucket brigade algorithm (Holland 1985) | Распределение кредита в классификаторах: сработавшее правило платит ставку b=c·r(C)·s(C) предыдущим активным («поставившим сцену»), награда растекается по цепи назад; в проекте — исторический эталон теневых цен и ставок бюджетера, но сила правила — только гипотеза для ранжирования, никогда истина (ALGORITHM-ATLAS-WAVE8 §46, ADR-004, граница №10) |
| **Rote learning (Сэмюэл)** | Samuel's rote learning (1959) | Запоминание «позиция → backed-up значение» для амплификации глубины поиска (предок мемоизации) + «чувство направления» (дисконт по ply); в проекте — кэш свидетельств подцелей в TaskCell и дисконт по глубине доказательства в скоринге планов бюджетера (ALGORITHM-ATLAS-WAVE8 §46, DESIGN-11/12) |
| **Фрейм (Минский)** | Frame (Minsky 1974) | Структура стереотипной ситуации: слоты со значениями по умолчанию (ожиданиями, вытесняемыми наблюдением) и условиями на присваивания; фреймы связаны в системы (смена точки зрения); в проекте — типовой контекст M1 со слотами ожиданий: значение по умолчанию маркируется UNDECIDED и становится свидетелем только после замещения наблюдением (ALGORITHM-ATLAS-WAVE9 §47) |
| **K-line** | Knowledge-line (Minsky 1980) | Агент памяти, включающий запомненную конфигурацию агентов; формируется чанкингом эпизода решения, включая ложные старты («негативная экспертиза»); в проекте — индекс восстановления ансамбля эпизода в M3: извлекается состав участвовавших правил/скетчей/подцелей, а не единичный факт (ALGORITHM-ATLAS-WAVE9 §47) |
| **Общество разума** | Society of Mind (Minsky 1986) | Тезис: ум — композиция мелких неразумных агентов в агентства; нет центрального агента и «единого волшебного трюка»; управление — конфликт/конкуренция/цензоры; в проекте — санкция композиции без центра (ряды Cauldron под Φ-гейтом) и цензоры ≡ конституционные триггеры; эмерджентность не принимается как объяснение — BRC-акт обязателен (ALGORITHM-ATLAS-WAVE9 §47) |
| **Внешний критерий (Ивахненко)** | External criterion (GMDH) | Критерий качества структуры модели, вычисляемый на данных, не использовавшихся для оценки параметров (регулярности, минимального смещения/непротиворечивости, предсказательной способности); в проекте — исторический предок Φ-гейта: продвижение кандидата только по внешнему критерию на контрольных эпизодах, внутренняя «уверенность» — не основание; теоретическое обоснование — равномерная сходимость (Вапник–Червоненкис, волна 14) (ALGORITHM-ATLAS-WAVE9 §49, DESIGN-07/11) |
| **Многорядная селекция** | Multirow selection (GMDH) | Схема Ивахненко: ряды моделей нарастающей сложности, из ряда в ряд проходит ограниченное число лучших по внешнему критерию («как при селекции растений»); остановка «во избежание инцухта» — при замедлении выигрыша, до формального минимума; в проекте — ряды Cauldron с бюджетом арности частных описаний и правилом ранней остановки; совпадает со схемой SRM (иерархия вложенных классов растущей ёмкости, волна 14) (ALGORITHM-ATLAS-WAVE9 §49, DESIGN-07, H-021-модификатор) |
| **CSP-событие** | Synchronous communication event (Hoare CSP) | Событие синхронной передачи между процессами: обе стороны блокируются до общей готовности (Хоар 1978; процесс-алгебра BHR 1984); асинхронность — только явный буферный процесс с заявленной политикой переполнения; в проекте — дисциплина точек взаимодействия TaskCell/слоёв: каждая передача — событие журнала M4 (ребро happened-before), overwrite-буферы запрещены (ALGORITHM-ATLAS-WAVE10 §50, DESIGN-12) |
| **Дедлок / дивергенция** | Deadlock / divergence (CSP failures model) | Два различных класса отказа параллельной системы: дедлок — отказ от всех событий; дивергенция — бесконечное внутреннее поведение без события; в проекте — расширение классов отказа контура (вместе с reject-by-budget/reject-by-proof): детектор дедлока по отсутствию готовых событий, детектор дивергенции по расходу бюджета без коммуникации (ALGORITHM-ATLAS-WAVE10 §50, ADR-005) |
| **Subsumption (Брукс)** | Subsumption architecture (Brooks 1986) | Слоистое управление по поведениям: уровень 0 отлаживается и никогда не изменяется; верхние слои подавляют (suppress) входы и ингибируют выходы нижних, не выключая их; система разрезима на любом уровне; в проекте — дисциплина MA/FNL-иерархии: PROMOTED-слой заморожен, рефлексы безопасности неотключаемы, подавление только с журналированием, DEGRADED-режим ≡ работа на нижних слоях (ALGORITHM-ATLAS-WAVE10 §51, DESIGN-12) |
| **Средне-целевой анализ** | Means-ends analysis (GPS, Newell–Simon) | Стратегия GPS (Эрнст–Ньюэлл 1969): извлечь различия между моделью и целью, выбрать оператор, релевантный сокращению различия, поставить его предусловие как подцель; сочетает прямой и обратный поиск; в проекте — дисциплина рассогласования: структурированный остаток UNDECIDED типизирует импасс и порождает подцель-TaskCell (ALGORITHM-ATLAS-WAVE10 §52, DESIGN-11/12) |
| **STRIPS-оператор** | STRIPS operator (Fikes–Nilsson 1971) | Контракт действия: предусловие + delete-список + add-список; модель-потомок представляется дельтой (DELETIONS/ADDITIONS); доказательство внутри модели отделено от поиска по пространству моделей; в проекте — действия узла как контракты с трёхзначным предусловием и явной декларируемой дельтой состояния; план проверяется до исполнения; недекларированное считается неизменным (допущение фрейма фиксируется в контракте) (ALGORITHM-ATLAS-WAVE10 §52, DESIGN-05/11) |
| **Ситуационная модель (Поспелов)** | Situational model (Pospelov situational control) | Явно собранное описание текущего состояния объекта и среды, над которым принимается решение рассуждением, а не вычислением по фиксированной формуле (школа ситуационного управления, 1971–1986); язык описания ситуаций (RX-коды) — прообраз онтологий; в проекте — собранный срез контекста (M1 + ожидания фрейма + коридоры гомеостата) перед BRC-актом: «ориентация» цикла OODA; рабочее описание для решения, не хранилище истины (ALGORITHM-ATLAS-WAVE11 §53) |
| **Мета-уровень / связка мониторинг–контроль** | Meta-level & monitoring–control coupling (Nelson–Narens 1990) | Рамка метапамяти: объектный уровень и мета-уровень, содержащий динамическую модель объекта (Конант–Эшби); два асимметричных потока — мониторинг вверх, контроль вниз; мониторинг и контроль могут диссоциировать; в проекте — гомеостат как мета-уровень: связка обязана быть продемонстрирована (метрика типа withdraw delta: различие поведения по классам исходов), бланкетная политика без дискриминации ≡ незрелость контура; мета-модель ≡ модель собственного поведения (коридоры), не модель мира (ALGORITHM-ATLAS-WAVE11 §54, DESIGN-11) |
| **EOL/JOL/FOK/RC** | Metamnemonic judgments (ease-of-learning / judgment-of-learning / feeling-of-knowing / retrospective confidence) | Типономика суждений метапамяти по времени обучения/извлечения (Нельсон–Наренс; Данлоски); в проекте — типизированные скоринги качества: EOL ≡ скоринг ЗБР куррикулума, JOL ≡ метрика готовности кандидата в рядах, FOK ≡ скоринг извлечения M1/M2, RC ≡ калибровка итогового свидетеля; все — сигналы ранжирования, не истины (граница №10); мониторинг не порождает знание (ALGORITHM-ATLAS-WAVE11 §54) |
| **Прерывание (Саймон)** | Interruption mechanism (Simon 1967) | Механизм реакции серийного процессора на срочные потребности в реальном времени — функциональная роль эмоции в рамке Саймона: внезапный интенсивный стимул откладывает текущую программу; в проекте — конституционные триггеры и приоритетные события как первоклассный механизм контура: прерывание входит в серийный процессор по дизайну (не как сбой), с событием журнала; аттенюация §43: триггеры проходят любой фильтр; приоритет ≠ истина, ложные срабатывания корректируются гомеостатом (ALGORITHM-ATLAS-WAVE11 §55, DESIGN-11) |
| **Satisficing / иерархия целей** | Satisficing & goal hierarchy (Simon 1956/1967) | Мотивация как механизм создания и контроля строго организованной иерархии целей: управление вниманием, порядком целей и критериями завершённости (удовлетворение вместо оптимизации, «нетерпение» как тайм-бюджет); в проекте — драйверы (Energy/Curiosity/Safety) как сигналы, упорядочивающие очередь целей (не директивы); каждая цель/TaskCell обязана иметь критерий завершённости (акцептор результата) и порог «достаточно хорошего» свидетеля — иначе монополизация серийного контура; satisficing — остановка поиска, не критерий истины (ALGORITHM-ATLAS-WAVE11 §55, DESIGN-02/12) |
| **Рабочая память (Баддели)** | Multicomponent working memory (Baddeley & Hitch 1974) | Модель: центральный исполнитель + модальностно-специфичные подчинённые хранилища (фонологическая петля с репетицией, визуально-пространственный блокнот), доказанные селективной интерференцией; в проекте — раздельные медиа-линейки сигнальных модулей с раздельными бюджетами интерференции, refresh-политика TTL контекста M1 (репетиция), активация Коуэна ≡ скоринг извлечения; центральный исполнитель НЕ переносится как центр — функции распределены на арбитраж/бюджетер/гейты (три санкции без центра) (ALGORITHM-ATLAS-WAVE12 §56, DESIGN-05/06) |
| **Эпизодический буфер** | Episodic buffer (Baddeley 2000) | Четвёртый компонент модели Баддели: хранилище ограниченной ёмкости, связывающее подчинённые системы и долговременную память в единую эпизодическую репрезентацию; в проекте — второе независимое обоснование ситуационной модели (§53): явно собранный связный мультимодальный срез перед BRC-актом с бюджетом ёмкости; «осознание как способ извлечения» отвергнуто — извлечение механическое, по схеме со свидетелем (ALGORITHM-ATLAS-WAVE12 §56) |
| **Эпизодическая / семантическая память** | Episodic vs semantic memory (Tulving 1972) | Различение Тулвинга: эпизодическая — «временно датированные» события с контекстом, автобиографична, реконструктивна; семантическая — знание, отвлечённое от эпизода, устойчивее к забыванию; системы взаимозависимы; в проекте — эпизодическая ≡ журнал M4 и эпизоды M2 (метка логического времени ≡ «датированность»), семантическая ≡ верифицированный пул M3/FNL; семантизация ≡ консолидация «сон»; реконструктивность человека обращена в инвариант append-only журнала (извлечение не перезаписывает запись); автоноэтика/хронестезия отвергнуты (Статья VI) (ALGORITHM-ATLAS-WAVE12 §57, DESIGN-05) |
| **Семиотическая модель (χ-правила)** | Semiotic model with change rules (Pospelov–Osipov) | Модель C = ⟨M, χT, χR, χA, χP⟩: формальная модель (элементы, синтаксис, аксиомы/знание, прагматика) + явные правила изменения каждого компонента (прикладная семиотика, 1996–2002); в проекте — декларированные закрытые меню допустимых изменений каждого слоя (схемы/правила/знание/дисциплины вывода), совпадающие с меню коррекций гомеостата: любое изменение — свидетельствованный акт через M4/Φ-гейты; смена языка ≡ миграции ioSchema как первоклассные события с tombstone и lineage; FROZEN неизменяем (ALGORITHM-ATLAS-WAVE12 §58, DESIGN-11) |

| **Универсал как инвариант по группе** | Universal as group invariant (Pitts–McCulloch 1947) | «How We Know Universals»: распознавание формы есть вычисление инварианта по явной группе преобразований (перенос, масштаб, тон) — механизм «преобразование → усреднение/вычитание по орбите» (спектральная схема слуха, сканирование зрения); ни отрицание универсалов, ни платонизм: универсал — вычислимая функция представления; в проекте — дисциплина признаков ioSchema: каждый предикат декларирует, по каким преобразованиям домена он инвариантен (проверяемый тест на орбитах), смена группы — миграция схемы (§58); анатомическая гипотеза статьи ≡ образец предиктивного теста переноса (AGENTS-RESEARCH); феноменология восприятия за границей (ALGORITHM-ATLAS-WAVE18 §76, DESIGN-06) |
| **Contention scheduling / SAS** | Горизонтальная конкуренция схем + супервизорная система (Norman–Shallice 1986) | Действие управляется конкуренцией схем без центра; супервизия требуется только в пяти классах ситуаций (планирование, коррекция ошибок, новизна, опасность, преодоление привычки); в проекте — четвёртая санкция композиции без центра: рядовое исполнение — арбитраж PROMOTED-схем (REFLEX), полный BRC-контур включается по версионируемому перечню триггеров эскалации; типология срывов (захват, потеря активации) — расширение журнала отказов (ALGORITHM-ATLAS-WAVE19 §77, DESIGN-03/11) |

| **PDDL / доменный язык планирования** | Planning Domain Definition Language (McDermott et al. 1998; линия ADL Педнолта 1989) | Декларативное описание домена действий (типы, предикаты, параметризованные действия с предусловиями и эффектами), отделённое от решателя и от задачи; стандартизация развязала развитие решателей и сравнение на общих корпусах; в проекте — основание кандидата DESIGN-13: реестр действий с ioSchema отделён от исполнителей, три версионируемых артефакта (домен/задача/исполнитель) фиксируются тремя хэшами в журнале M4, grounding на малом пространстве (k≤20) — явная строка бюджета (ALGORITHM-ATLAS-WAVE20 §81, DESIGN-13-кандидат, FR-15) |
