## Карточки экспериментов

### EXP-001 — Дистилляция после карантина pretrain_neurons.py
- **Пререгистрация:** до запуска — зафиксировать: корпус этюдов, критерий fidelity, набор golden-векторов (DJL/ONNX, CONSTITUTION VII.2).
- **Протокол:** этап A SPEC-001 (карантин) → этап B (quantile-бинаризация, важность-признаки, TREPAN/автоматы) → сверка BDD-эквивалентностью (где k≤16) и golden-векторами.
- **Бюджет:** 3 итерации корпуса.
- **Результат:** fidelity-отчёт; по итогу — ADR «дистилляция как инициализация» или закрытие линии с переносом вывода в OP-3 (vision/OPEN_PROBLEMS.md).
- **Риски:** fidelity-«средняя по больнице» — обязателен разбор worst-case подмножеств; авто-оценка источника обучающих данных (distilled ≠ verified).

### EXP-002 — Формы BIR на идентичных входах
- **Пререгистрация:** задачи (бинаризованный Minecraft-перцепт; synthetic k∈{8,12,16,20}); метрики: balanced accuracy, F1, нс/решение (JMH), байт/структуру, устойчивость к label noise (10% flip), интерпретируемость (ручная выборка клауз, владелец оценивает 20 штук).
- **Базовые линии:** MPDT-ГА (существующий), BNN — внешний ориентир (числа из литературы с пометкой).
- **Протокол:** одинаковая бинаризация (метод из SPEC-001 этап B); 5 сидов; публикация всех сидов.
- **Обязательный предэтап:** воспроизведение эталонных чисел Granmo 2018 на toy-задачах (MUX, noisy-XOR) до доменов — наивная реализация TM в прототипе не сошлась (`prototype/RESULTS.md` §5); без эталонного воспроизведения доменные результаты недействительны.
- **Критерии H-002.**

### EXP-009 — Паритет BIR-классификации с LLM ≤3B на ноутбуке
- **Пререгистрация:** задачи (guardrail-классификация, intent-роутинг, домен-классификация владельца); базовая линия — локальный LLM ≤3B (4-bit, фиксированная модель+версия); метрики: balanced accuracy, latency p50/p99 (JMH vs llama.cpp-лог), энергия (оценка по ANALYSIS §5: ops × нДж против FLOP × пДж), память резидентная.
- **Протокол:** те же входы, та же бинаризация; 5 сидов; LLM промпт фиксируется; обе системы на одном железе.
- **Критерии H-009.** Отрицательный результат публикуется (CONSTITUTION VI.2) и уточняет границы §6 ANALYSIS.

### EXP-014 — VC-размер отложенного окна Φ-гейта
- **Пререгистрация:** классы кандидатов (CLAUSESET с m клауз × арность ≤a; TT-единичные k∈{8,12}); контролируемые «ложные улучшения» (кандидаты, подогнанные под шум); метрики: accept-ошибка гейта vs размер окна n; предсказание по формуле n*(ε=0.05, δ=0.05) с оценкой VC-размерности класса.
- **Протокол:** синтетический домен с известной функцией; гейт работает по DESIGN-04; 5 сидов; публикуется кривая accept-ошибка(n) и предсказанный порог.
- **Критерии H-014.** Результат — нормативная формула размера окна в METRICS.md или опровержение с честной границей.

### EXP-015 — Бинарный резервуар intESN-типа для временны́х доменов
- **Пререгистрация:** домены (последовательности событий SCADA; телеметрия кластера; синтетический temporal-XOR); метрики: точность vs float-ESN той же ёмкости (внешний ориентир из литературы, помеченный), энергия/решение (оценка по ANALYSIS §5), детерминизм (5 сидов, побитовая повторяемость трасс).
- **Архитектура кандидата:** состояние — VSA-гипервектор; рекуррентность — перестановка ρ + XOR-связывание входа; readout — TT/WNN-единица, обучаемая однопроходово; вся динамика бинарна, seed фиксирован (ALGORITHM-ATLAS §5).
- **Критерии H-015.**

### EXP-016 — Монотонное декодирование против TsetlinTrainer
- **Пререгистрация:** домены с монотонностью как инвариантом схемы (минимум 2: синтетический монотонный + домен владельца с задекларированной монотонностью признаков); метрики: образцы до порога точности, точность на holdout, интерпретируемость (выборка из 20 клауз).
- **Кандидат:** MonotoneDecoder — идентификация монотонной функции через поиск максимального верхнего нуля (схема Ханселя; узбекская школа Кабулова–Норматова, ALGORITHM-ATLAS §6.1); реализация по первоисточнику со сверкой формул.
- **Критерии H-016.**

### EXP-017 — LTL-верификация контура управления
- **Пререгистрация:** инварианты (INV-S1/S2, INV-TC1/2/3, INV-F1/F2, бюджеты proactive-планировщика) переформулируются в LTL с классификацией safety/liveness (Манна–Пнуэли); модель контура — конечный автомат режимов узла (активен/спит/консолидирует/карантин), детерминированный; инструмент — model checker класса SPIN/NuSMV (внешний шаг CI, не рантайм).
- **Протокол:** контрпримеры из чекера воспроизводятся в Java-прототипе контура; каждый найденный класс нарушений → новый AT-тест в DESIGN-07/08; отсутствие контрпримеров при полном обходе — доказательство для конечной модели, фиксируется в отчёте.
- **Критерии H-017.**

### EXP-018 — GUHA-генератор кандидатов против случайного сэмплирования
- **Пререгистрация:** домены (≥2: синтетический корпус с известным полным множеством правил малой арности + домен владельца с зафиксированным golden-множеством); язык атомов фиксирован до запуска (предикаты над булевыми признаками, арность ≤3); бюджет — число оценённых кандидатов; метрики: покрытие (доля найденных правил из исчерпывающего перебора), доля дубликатов, доля тривиальных (сила ниже порога таблицы сопряжённости), стоимость на валидный кандидат.
- **Кандидат:** детерминированный генератор в стиле ГУХА (Гайек–Гавранек, 1966): систематический обход пространства гипотез «поддержка → следствие» над языком атомов; сила кандидата — количественные оценки по четырёхпольной таблице (a/(a+b) и пороги поддержки); кандидаты рождаются только с witness (таблица сопряжённости прикреплена); контроль — равновероятный сэмплер с тем же языком и бюджетом.
- **Протокол:** оба генератора прогоняются с 5 сидами; итог сравнивается с эталонным исчерпывающим перебором; отрицательный результат фиксируется в reports/ (конвенция FR-15).
- **Критерии H-018.**

### EXP-019 — Расписание Левина для бюджетов рядов Cauldron
- **Пререгистрация:** домены (≥2, те же, что в EXP-018, для сопоставимости); суммарный бюджет (число оценённых кандидатов и джоули, замеряемые энергосчётчиком узла); метрики: покрытие эталонного множества правил, покрытие на джоуль, распределение бюджета по рядам (фактическое против планового); язык атомов и оценщик Φ фиксированы до запуска.
- **Кандидат:** планировщик рядов Cauldron с расписанием Левина: ряд с кандидатом описания длины l получает долю бюджета ∝ 2^−l; очередь внутри ряда — по Kt-скорингу (длина описания + log стоимости проверки); контроль — равномерное расписание по тем же рядам с тем же суммарным бюджетом; оба планировщика детерминированы (сиды фиксируются).
- **Протокол:** 5 сидов на расписание; обрезание бюджета по NFR-07 обязательно (никакой ряд не блокирует остальные); фактическое распределение бюджета логируется в witness запуска; отрицательный результат фиксируется в reports/ (конвенция FR-15).
- **Критерии H-019.**

### EXP-020 — AQ/LAD-генератор (звезда-от-зерна) против ГУХА-генератора
- **Пререгистрация:** домены (≥2: синтетический корпус с известным полным множеством правил средней арности + домен владельца); расписание зёрен детерминировано до запуска (порядок обхода позитивных примеров фиксирован хешем конфига); бюджет — число оценённых кандидатов; метрики: покрытие, дубликаты (клаузы, эквивалентные по BDD), тривиальные, стоимость на валидный кандидат.
- **Кандидат:** детерминированный генератор в линии LAD (Хаммер–Крама–Ибараки) и AQ (Михальски): для каждого зерна строится ограниченная звезда максимально общих обобщений; гейт приёма по трайрупья (Дхармакирти): кандидат принимается при поддержке в позитивном классе и полном («эва») отсутствии покрытий негативов — либо отклоняется с зафиксированным типом нарушения (хетучакра как типология отказов); кандидаты рождаются только с witness (зерно + звезда + проверка гейта); контроль — ГУХА-генератор из EXP-018 с тем же бюджетом.
- **Протокол:** оба генератора прогоняются с 5 сидами; сравнение с эталонным исчерпывающим перебором средней арности; эквивалентность клауз проверяется канонизацией (BDD); отрицательный результат фиксируется в reports/ (конвенция FR-15).
- **Критерии H-020.**

### EXP-003 — Механизмы обучения как producers BIR
- **Пререгистрация:** среда GridWorld→крафт-граф; бюджет 10⁶ шагов/механизм; метрики: образцы до порога, wall-clock, байт/структуру, точность, F1.
- **Механизмы:** автоматы Цетлина; ГА; трёхфакторное правило.
- **Правило решения:** SPEC-002 FR-C1 (зафиксировано здесь до запуска).

### EXP-004 — Ricci-fingerprint детектор деградации
- **Пререгистрация:** сценарии деградации (случайное удаление 5% рёбер; целенаправленное удаление мостов); нормальное окно — недельное пополнение графа; метрика ROC/AUC [^медицина]; сравнение с Recall@5 golden-набором как референс-детектором.
- **Протокол:** SPEC-003 FR-5. Дополнительно EXP-004b: curriculum-ordering vs случайный порядок (SPEC-003 FR-6).

### EXP-005 — Developmental Loop vs случайная выборка задач
- **Пререгистрация:** 50 этюдов крафта (зафиксированный набор); метрики: время до решения, transfer rate, доля решённых; контроль: случайная выборка задач, тот же агент.
- **Протокол:** SPEC-000 FR-7; scaffold fading обязателен (без fading эксперимент недействителен).

### EXP-006 — Guardrail из BIR-композиций
- **Пререгистрация:** вредоносный корпус (фиксированная выгрузка), невредоносный контрольный (тот же домен); метрики: TPR/FPR, p99 latency, контрпримеры BRC.
- **Базовые линии:** GPT-4-as-judge (внешний ориентир), TF-IDF классификатор.
- **Протокол:** этап 2 ROADMAP; SAT-доказательства противоречий обязательны в отчёте.
