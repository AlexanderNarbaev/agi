## 2. Отклонённые технологии (не предлагать без нового ADR)

| Технология | Причина отказа | Чем заменено |
|---|---|---|
| Python в продакшн-контуре | второй рантайм = двойная верификация, деплой, дрейф; у владельца экспертиза Java | DJL+ONNX (инференс), собственные Java-реализации (обучение) |
| DL4J | тянет DL-парадигму, противоречащую булеву ядру; слабая поддержка | matrix-tsetlin, matrix-bir |
| TensorNEAT / NEAT-библиотеки | эволюция топологий покрывается GATopologySearch; зависимость без выигрыша | собственный evolution-модуль |
| GPU-зависимость рантайма | целевые среды — CPU/MCU/FPGA; GPU = невоспроизводимость и недоступность на краю | Vector API (CPU SIMD); FPGA для latency-критичного |
| Агентные фреймворки (LangChain и аналоги) как ядро | скрывают контракты, мешают детерминизму и верификации | собственный Agent Loop с Avro-контрактами (SPEC-000) |
| Neo4j внутри MATRIX | граф — забота rag-system; двойное хранилище = рассинхрон | matrix-ricci — read-only экспорт (SPEC-003) |
| Сторонние CRDT-библиотеки | маленькие, плохо аудируемые; протоколы просты | matrix-crdt (свой, с property-тестами) |
| Langfuse и т.п. SaaS-трейсинг | данные уходят наружу; противоречит приватности контура | OpenTelemetry self-hosted |
| Zookeeper | лишний сервис | Kafka KRaft |

## 3. Контракт с внешними моделями (DJL/ONNX)

1. Teacher/верифицируемые LLM вызываются из JVM через DJL + ONNX Runtime — не через Python-процессы.
2. **Golden-векторы:** фиксированный набор входов и ожидаемых выходов (хэши) хранится в репозитории; CI сверяет поведение модели при обновлении версии ONNX/модели (CONSTITUTION VII.2).
3. Обновление модели/рантайма без прохождения golden-векторов — блокер релиза.
4. Дистиллированные артефакты помечаются provenance (модель, версия, корпус) и проходят fidelity-гейт (SPEC-001 FR-B6).

## 4. Правила добавления зависимости

1. Зависимость появляется только с ADR: задача, альтернативы, лицензия (совместимость с AGPLv3 + ethical policy), поверхность аудита.
2. Любая зависимость в контуре верификации/безопасности — с фиксированной версией и хэшем артефакта.
3. Ежеквартальный аудит: неиспользуемые зависимости удаляются.
