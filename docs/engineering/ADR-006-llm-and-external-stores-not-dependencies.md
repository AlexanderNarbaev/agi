# ADR-006. LLM и внешние хранилища — не зависимости системы

- **Статус:** accepted (уточняет и сужает ADR-001; при противоречии действует этот ADR)
- **Дата:** волна 6 документации
- **Связи:** ADR-001, SPEC-001, DESIGN-03 §5, DESIGN-05, HYPOTHESES H-001/H-009, C4 (контекст), G-A/G-B/G-C, NFR-04/06

## Контекст

В ранних документах LLM и rag-system фигурировали как элементы контекста системы (фасад, прокси, «внешняя зависимость по контракту»). Владелец поставил вопрос принципиально: в проекте **нет необходимости** в LLM и внешних хранилищах как зависимостях — внутри системы живут булевы функции (BIR), а не веса и не эмбеддинги. Нужно зафиксировать ровно те роли, которые внешним системам разрешены, и запретить остальные.

## Решение

**Внутри системы — только булевы функции (BIR).** Никакой компонент контура не ссылается на LLM, векторную или графовую СУБД как на необходимое условие работы. Разрешены ровно три внешние роли:

1. **LLM как донор весов (однократно, через карантин).** Предобученные веса могут быть источником начальных артефактов: конвертация → дистилляция по активациям → BIR, только через карантин SPEC-001 (этап A/B), с fidelity-отчётом (H-001). После дистилляции система работает **без** LLM; повторное обращение не требуется.
2. **LLM как базовая линия сравнения (экспериментально).** Локальный LLM ≤3B — эталон в EXP-009: система обязана достигать **паритета качества** (±3 п.п. balanced accuracy) на структурированных задачах при ≥10⁴× меньшей энергии и ≥10³× меньшей latency, работая только на CPU (H-009). Критерий успеха проекта формулируется против LLM, но не через LLM.
3. **Векторные и графовые СУБД как концептуальные доноры (не зависимости).** Из мира vector DB заимствуются: ANN-recall как метрика качества памяти, top-K контракты, индексные бюджеты. Из графовых СУБД: навигация по графу знаний, запросные паттерны, Ricci-топология дрейфа (SPEC-003). Реализация всего этого — внутри, на булевых структурах: SDM/гипервекторы (битовые, SM §3–§4), граф знаний как булев контекст FCA и решётка концептов (SM §4.1), recall через радиус Хэмминга — никаких внешних движков.

**Запрещено:** вызов LLM в онлайн-контуре (PERCEPTION/DELIBERATION/RENDERING); хранение знаний системы во внешних хранилищах; любой кодовый путь, где отказ внешней системы делает контур нерабочим. rag-system — внешний проект владельца; заимствование принципов — по контракту ADR-001, зависимости кода нет.

## Основания (атлас и реестры)

- G-B «без GPU» и G-A «энергопаритет»: целевое сравнение — «не хуже LLM на GPU, работая на CPU» (H-009, EXP-009; ANALYSIS-laptop-feasibility §6).
- Булево ядро как единственный носитель: ADR-002; бит как элементарный тип — Цузе (§33); конечные функции исчерпываются алгеброй — Мойсил (§26).
- Дистилляция как единственный мост от весов: SPEC-001; «distilled ≠ verified» — авто-оценка источника обучающих данных (HYPOTHESES, риски EXP-001).
- Память без внешних СУБД: SDM Канервы (SM §3, DESIGN-05 §3, H-011), VSA (SM §4.2), FCA-решётки вместо graph DB (SM §4.1).

## Последствия

**Положительные:**
- Полная суверенность узла: работа офлайн, без сети, без лицензий на модели, на ноутбуке (G-E); воспроизводимость побитовая (NFR-04).
- Честная энергометрия: сравнение с LLM ведётся по измеренным джоулям, а не по маркетинговым числам (EXP-009, обе системы на одном железе).
- Накопления vector/graph DB индустрии превращаются в метрики и паттерны, а не в код и сервисы.

**Отрицательные / цена:**
- Холодный старт без донорских весов медленнее: компенсируется интерактивным обучением с учителем (DESIGN-04 §4) и curriculum (SPEC-000).
- Генеративный фри-форм текст — вне ядра: исходящие сигналы собираются декодерами из BIR (DESIGN-03/06); качество языка — отдельная ставка, не зависимость.

## Проверяемость

- CI-гейт: в контуре запроса нет импортов/вызовов внешних LLM/DB SDK (статический анализ зависимостей; список разрешённых пакетов — JAVA_STACK).
- EXP-009 фиксирует паритет «CPU+BIR против GPU+LLM» как публичный критерий; отрицательный результат публикуется (FR-15).
- Любое предложение вернуть LLM/DB в контур — только новым ADR с опровержением H-009/H-001.
