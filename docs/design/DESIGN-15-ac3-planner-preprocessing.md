# DESIGN-15. AC-3 предобработка ограничений для ExecutablePlanner

**Статус:** proposed → skeleton implemented (living)
**Основание:** атлас §101 (arc consistency, Mackworth AC-3 1977); интеграционная точка зарегистрирована в WAL.

## 1. Назначение

Планы генерируются только над пруннутыми консистентными доменами: перед
генерацией плана ExecutablePlanner прогоняет переменные предусловий через
AC-3; пустой домен = CSP неразрешим ⇒ планировщик сразу возвращает отказ,
не тратя контур генерации.

## 2. Реализация (skeleton)

`io.matrix.agent.planning.Ac3Solver` — автономный детерминированный модуль:
- переменные = индексы; домены = BitSet значений [0..maxValue);
- бинарные ограничения = предикаты парами (vi,val,vj,val);
- solve(): ACED FIFO-очередь всех дуг, revise до фикс-пойнта;
- false ⟺ какой-то домен опустел.

Свойства (тесты Ac3SolverTest): дуговая согласованность как инвариант
после solve (каждое оставшееся значение имеет поддержку у соседа),
детекция противоречия, идемпотентность. jqwik-генерация случайных CSP.

## 3. Путь интеграции (следующая итерация)

1. PlanStep получает опциональные `preVarIds/preDomains/constraints`
2. executePlan(): перед extractSteps — solve(); false ⇒ fast-fail результат
3. Спецификация ограничений — из декларативного описания задачи (SPEC при фиче)

## 4. Критерии приёмки

- [x] Детерминизм (без Random/wall-clock)
- [x] Инвариант дуговой согласованности после solve (property + unit)
- [x] Детекция противоречия и пустых доменов
- [ ] Интеграция с ExecutablePlanner (отдельная волна, SPEC)
