H-009 · BIR-classifier

running
Source: io.matrix.bir.BirClassifier · HYPOTHESES §H-009

Claim: A binary classifier that uses BIR as the underlying representation achieves parity with LLM ≤3B (±3 p.p. balanced accuracy) on structured tasks at ≥10⁴× less energy and ≥10³× less latency on laptop hardware.

How it works: For each class, train a CLAUSESET BIR unit from positive examples. Classification picks the class whose BIR unit matches the input with the highest score above a learned threshold.

// Train
BirClassifier classifier = new BirClassifier(64);
classifier.train("intent", positiveExamples);

// Infer
Optional<String> predicted = classifier.classify(features);

Reproduction: ./gradlew :matrix-core:test --tests "io.matrix.bir.BirClassifierTest"

H-010 · WNN/WiSARD

running
Source: io.matrix.tsetlin.WisardProducer · HYPOTHESES §H-010

Claim: A single-pass Weightless Neural Network (WiSARD-style address-RAM ensemble) achieves accuracy within 2 p.p. of TsetlinTrainer at ≥10× faster training on structured tasks.

How it works: Input bits are partitioned across N RAMs. Each RAM stores a vote per address. Training writes 1 on positive, -1 on negative. Classification sums votes across all RAMs.

WisardProducer wnn = new WisardProducer(64, 16, seed);
wnn.train(input, 1);                  // single-pass
double score = wnn.classify(input);    // sum of RAM votes

Why it matters: Training is a single pass over examples. No gradient, no backprop. Deterministic given fixed seed.

H-011 · SDM / Kanerva

running
Source: io.matrix.memory.SdmReader · HYPOTHESES §H-011

Claim: Sparse Distributed Memory (counter-based with Kanerva radius) gives precision@5 ≥+5 p.p. over flat Hamming top-K at the same memory budget.

How it works: Random-address locations store counters per bit. Writes only affect locations within Hamming radius. Reads sum counters from active locations and take majority vote.

SdmReader sdm = new SdmReader(
    1024,    // address bits
    256,     // data bits
    10000,   // num locations
    350.0,   // Kanerva radius
    seed
);
sdm.write(address, data);
long[] retrieved = sdm.read(address);

Why it matters: Approximate nearest-neighbor with bounded error. Exploits the geometry of high-dimensional Hamming space.

H-015 · intESN (Binary Reservoir)

running
Source: io.matrix.reservoir.IntEsNetwork · HYPOTHESES §H-015

Claim: An integer Echo State Network (VSA state + permutation recurrence + TT/WNN readout) achieves accuracy within 3 p.p. of float-ESN at ≥10× less energy per decision.

How it works: The state is a high-dimensional binary vector. Recurrence is XOR with permuted versions of the state. Learning happens only in the readout.

IntEsNetwork reservoir = new IntEsNetwork(2048, 32, seed);
long[] state = reservoir.update(input);   // XOR + permutation, ~ns

Why it matters: Reservoir computing with binary operations is one of the cheapest recurrent neural models that exists. Deterministic given fixed seed.

H-016 · Monotone Decoder

running
Source: io.matrix.monotone.MonotoneDecoder · HYPOTHESES §H-016

Claim: On monotone domains, identifying the monotone Boolean function by maximal upper zero circuit requires ≥5× less corpus than TsetlinTrainer for the same target accuracy.

How it works: Monotone Boolean functions live in a smaller hypothesis space. The maximal upper zero circuit captures the canonical representation. PAC bounds are tighter.

Why it matters: Many real-world domains (preference, threshold, ranking) are monotone. Specializing the learner to this structure is a free win.

H-017 · LTL Model Checker

running
Source: io.matrix.verification.LtlModelChecker · HYPOTHESES §H-017

Claim: Formalizing the lifecycle invariants from DESIGN-07/08 in LTL and bounded model checking discovers at least one class of violation not covered by acceptance tests, or proves the absence of such violations for the finite model.

How it works: Build a Kripke structure of the control loop (planner, sleep route-drain, K8s operator). Submit LTL formulas (safety, liveness, invariance). DFS for bounded depth finds counterexamples.

LtlModelChecker mc = new LtlModelChecker();
KripkeStructure structure = ...; // build from observed transitions
LtlFormula safety = LtlModelChecker.safetyProperty("data_loss");
boolean holds = mc.check(structure, safety);

Why it matters: LTL is the right tool for system-level invariants. Smaller state spaces than full Stack VM, but covers the right abstraction.

H-018 · GUHA Candidate Generator

running
Source: io.matrix.cauldron.GuhaCandidateGenerator · HYPOTHESES §H-018

Claim: Systematic enumeration of structured hypotheses (Hájek-Havránek GUHA method) covers ≥90% of the rule space at ≤30% of the budget of random sampling.

How it works: Generate all antecedent combinations up to max arity. For each, compute support and confidence against the example set. Filter by GUHA thresholds (support ≥ √n, confidence ≥ 0.8).

GuhaCandidateGenerator gen = new GuhaCandidateGenerator(atoms, 3, seed);
List<CandidateRule> candidates = gen.generate(examples, budget);

Why it matters: Random sampling wastes budget on low-support candidates. Systematic enumeration respects the structure of the hypothesis space.

H-019 · Levin Schedule

running
Source: io.matrix.cauldron.LevinSchedule · HYPOTHESES §H-019

Claim: Allocating budget proportional to 2⁻ˡ (length) gives ≥+15% coverage per joule vs uniform scheduling on ≥2 domains at equal budget.

How it works: Shorter candidates are cheaper to verify. They get proportionally more budget. The combined effect is more candidates evaluated per joule.

LevinSchedule levin = new LevinSchedule(seed);
List<ScheduledCandidate> scheduled = levin.schedule(candidates);
// Each candidate gets a budget fraction

Why it matters: Universal search (Levin 1973) is optimal under total budget. In practice it dominates uniform.

H-005 · LearnedMinecraftPilot

done
Source: io.matrix.pilot.minecraft.LearnedMinecraftPilot · HYPOTHESES §H-005

Claim: A Minecraft pilot trained through the Developmental Loop solves craft puzzles ≥30% faster than random task selection at not worse final accuracy.

How it works: The pilot records (state, observation, action, reward) tuples. A BIR classifier learns to map from (state, obs) → action. Fitness: blocksPlaced + itemsCollected + distanceTraveled/100 − 5×deaths.

LearnedMinecraftPilot pilot = newLearnedMinecraftPilot();
pilot.train(episodeHistory);
ActionResult action = pilot.step(state, observation);
