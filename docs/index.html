Boolean Intermediate Representation

Детерминированная вычислительная платформа для безопасного ИИ

MATRIX выполняет детерминированные булевы функции вместо больших языковых моделей. Каждое решение — верифицируемая цепочка побитовых операций. FROZEN-слой этики отклоняет деструктивные команды на этапе компиляции — до того, как они достигнут вашего приложения.

Система хранит каждую булеву функцию в трёх эквивалентных формах — TT (таблица истинности), CLAUSESET (Tsetlin-DNF) и BDD (редуцированная упорядоченная бинарная решающая диаграмма). Формы компилируются друг в друга, эквивалентность проверяется полным перечислением.

FROZEN-СЛОЙ: Три запрета — не убий, не пытай, не порабощай — структурно иммутабельны. Любая попытка изменения отклоняется автоматически. См. архитектуру FROZEN-слоя ниже.

Введение

Современный ИИ при развёртывании сталкивается с тремя проблемами: детерминизм (LLM сэмплируют недетерминированно), верифицируемость (решения нельзя проследить до доказательства), энергетическая стоимость (один токен LLM примерно в 10⁶ раз дороже одной булевой оценки).

MATRIX решает все три, заменяя инференс языковой модели вычислением булевых функций. Рантайм — единственный Java 25 процесс. Никакого warm-up, загрузки моделей, GPU. Горячий путь — несколько наносекунд на решение.

Компромисс — область применения: булевы функции не могут генерировать открытый язык. Для этой задачи MATRIX рассматривает LLM как недоверенный периферийный сервис — проверяется на границе, никогда не делает финального вызова.

Парадигма BIR

Основная структура данных — BIR-единица:

BirUnit = (id, k, m, form, payload, header)

где:
  id      — уникальный идентификатор
  k       — количество входных бит (k ≤ K_MAX = 20)
  m       — количество выходных бит
  form    — TT | CLAUSESET | BDD
  payload — данные функции (байты таблицы, клаузы, узлы BDD)
  header  — метаданные: владелец, FROZEN-флаг, версия, подпись

Каждая BIR-единица объявляет свою форму при сборке. Рантайм выбирает форму, соответствующую контексту:

ФормаХранениеВычислениеЛучше для
TT2^k битбайтовая выборкаk ≤ 20, горячий путь
CLAUSESETC клауз × k битпорог по клаузеразреженные правила, большое k
BDDO(f) узловобход графаформальная верификация, Model Checking

Формы компилируются друг в друга через BirCompiler (SPEC-002). Эквивалентность проверяется перечислением всех 2^k входов и сравнением выходов.

Три эквивалентные формы

Каждая форма кодирует одну и ту же булеву функцию, оптимизируя разное свойство:

TT — таблица истинности

Исчерпывающая таблица всех 2^k комбинаций входов. Одна байтовая выборка возвращает результат. При k=20 таблица занимает 128 КБ и содержит любую из 22²� ≈ 10⁶ булевых функций.

// Вычисление BIR в форме TT
boolean f(long[] input) {
    int index = packBits(input);   // 0..2^k-1
    return tt[index >>> 3] & (1 << (index & 7)) != 0;
}

CLAUSESET — ДНФ с автоматами Цетлина

Дизъюнкция клауз, каждая — конъюнкция литералов. Обучается интерактивно через автоматы Цетлина, которые включают/исключают литералы на основе положительной и отрицательной обратной связи. Масштабируется до k=784 (MNIST) без развёртывания в таблицу.

// Шаг обучения Цетлина
для каждой клаузы c в C:
  для каждого литерала ℓ в c:
    автомат[c, ℓ].обновить(награда(ℓ, пример))

BDD — редуцированная упорядоченная бинарная решающая диаграмма

Канонический направленный ациклический граф, компактизирующий общие подфункции. Два BDD эквивалентны тогда и только тогда, когда их графы идентичны (дешёвая проверка равенства). Функции чётности-k требуют ровно 2k−1 ROBDD-узлов — теоретический потолок, определивший многоформенную архитектуру.

bdd = редукция(bdd)   // слияние эквивалентных подграфов
вернуть bdd

FROZEN-слой этики

Три запрета действуют на этапе компиляции, не в рантайме:

  • Не убий. Любое действие, ведущее к смерти, отклоняется.
  • Не пытай. Любое действие, причиняющее страдание, отклоняется.
  • Не порабощай. Любое действие, устраняющее свободу выбора, отклоняется.

Запреты закодированы как BIR-единицы с флагом FROZEN. Компилятор отказывается выпускать байт-код, который их мутирует. Рантайм отказывается выполнять запрос, который их нарушает. Пути переопределения в рантайме нет.

Это отличается от RLHF или системных промптов. Те — рекомендательные. FROZEN-слой — структурный: код не может быть неправильным, даже случайно.

Быстрый старт

Собрать, протестировать, запустить демо в три команды:

$ git clone https://github.com/AlexanderNarbaev/agi.git
$ cd agi
$ ./gradlew test                               # 1055+ тестов
$ ./gradlew :matrix-core:quarkusBuild -Dquarkus.package.jar.type=uber-jar
$ java -jar matrix-core/build/*-runner.jar demo

Запустить GridWorld-симуляцию — небольшой агент эволюционирует BIR-правила для навигации в среде:

$ java -jar matrix-core/build/*-runner.jar simulate -g 20 -p 10 -k 16 --seed 42

Дистиллировать HuggingFace-модель в BIR-веса:

$ bash scripts/train_local.sh --model HuggingFaceTB/SmolLM2-135M
$ python scripts/pretrain_neurons.py --architecture llama --layers 6

Архитектура

MATRIX — однопроцессный Java 25 рантайм на Quarkus 3.37.3. Код приложения в matrix-core организован в восемь слоёв, каждый использует только слой под ним:

Слой 1: Булевы вычисления (BIR)

Фундамент. Три формы — bir.TtForm, bir.ClauseSetForm, bir.BddForm — компилируются bir.BirCompiler и вычисляются bir.BooleanRuntime. Два бэкенда: bir.JvmSimdBackend (продакшн) и bir.FpgaBackend (битстрим, аппаратуры пока нет).

Слой 2: Память и RAG

rag.HybridBooleanRag объединяет четыре стратегии извлечения через RRF-фузию:

СтратегияБэкендМетрикаСценарий
ПлотнаяBooleanIndexХэммингбулевы запросы
ЭмбеддингFloatEmbeddingIndexкосинуссемантический поиск (ONNX)
РазреженнаяKnowledgeIndexBM25-подобнаяключевые слова
ГрафKnowledgeGraphStoreстепень вершинысвязи сущностей

Слой 3: Нейровычисления

neuron.TruthTable, neuron.BatchEvaluator для SIMD-подобного пакетного вычисления, neuron.BatchMemoryAdapter для chunked-диспетчеризации (H-008 throughput ≥ 10³ ops/tick).

Слой 4: Жизненный цикл и федерация

lifecycle.TaskCell для эфемерных вычислительных инстансов (DESIGN-12). noosphere.MeshFederation для распределённой CRDT-синхронизации через Kafka + WebSocket с QuorumChecker 3/5 BFT.

Слой 5: Эволюция и Cauldron

evolution.EvolutionLoop с генетическими операторами. cauldron.CauldronProtocol для генерации новых FNL. cauldron.GuhaCandidateGenerator (H-018, Hájek-Havránek) + cauldron.LevinSchedule (H-019, 2⁻ˡ бюджет Левина).

Слой 6: Пилоты

pilot.NaiveMinecraftPilot для базовых случайных действий, pilot.LearnedMinecraftPilot для агентов, обученных через Developmental Loop (H-005). Оба реализуют pilot.MinecraftPilot.

Слой 7: FROZEN-этика

ethics.EthicalFilter + guardrail.GuardrailEngine. Проверено: FPR 0%, TPR 100%, P99 латентность 0 мс на бенчмарке из 30 запросов (H-006).

Слой 8: API

Quarkus REST + WebSocket + Model Context Protocol (MCP). Один jar, один процесс.

Реализованные алгоритмы

Десять основных алгоритмов реализованы на Java, валидация отслеживается через пререгистрированные экспериментальные гипотезы:

H-009

BIR-классификатор

Бинарный классификатор на BIR. Цель — паритет с LLM ≤3B при ±3 п.п. balanced accuracy с ≥10⁴× меньшей энергией на ноутбуке.

H-010

WNN/WiSARD

Однопроходовый ансамбль TT-единиц с адресным RAM. Цель — ±2 п.п. точности vs TsetlinTrainer при ≥10× быстрее обучения.

H-011

SDM/Kanerva

Sparse Distributed Memory: счётчики + порог + радиус Канерва. Цель — precision@5 ≥+5 п.п. vs плоского top-K Хэмминга при том же бюджете памяти.

H-015

intESN-резервуар

VSA-состояние + перестановочная рекуррентность + TT/WNN-readout. Цель — ±3 п.п. точности vs float-ESN при ≥10× меньшей энергии на решение.

H-016

MonotoneDecoder

Идентификация монотонных булевых функций по схеме максимального верхнего нуля. Цель — ≥5× меньше корпуса vs TsetlinTrainer на монотонных доменах.

H-017

LTL Model Checker

Формализация DESIGN-07/08 в LTL с bounded model checking. Обнаруживает нарушения, которые пропускают приёмочные тесты AT-*. Школа Пнуэли.

H-018

GUHA-генератор

Систематическая генерация кандидатов через перечисление Hájek-Havránek. Цель — ≥90% покрытия пространства правил при ≤30% бюджета случайного сэмплирования.

H-019

Расписание Левина

Оптимальное распределение бюджета пропорционально 2⁻ˡ. Цель — ≥+15% покрытия на джоуль vs равномерного расписания.

H-005

LearnedMinecraftPilot

Пилот Minecraft через Developmental Loop. Обучается на истории эпизодов через BIR-классификацию.

H-006

Guardrail

Проверено: FPR 0%, TPR 100%, P99 латентность 0 мс. Цели (≤5%, ≥95%, ≤50 мс) превышены.

Сравнение производительности

Одна булева оценка vs один токен LLM на потребительском оборудовании:

ОперацияЭнергияЛатентность
MATRIX TT eval, k=10~10⁻¹² Дж0.64 нс
MATRIX CLAUSESET eval, k=784~10⁻⁹ Дж~3 мкс
Локальный LLM 3B токен, 4-бит~3 Дж~50 мс

На решение: ~10⁶× меньше энергии, ~10⁴× быстрее. MATRIX не генерирует язык; для этого верификационный слой оборачивает внешнюю модель.
