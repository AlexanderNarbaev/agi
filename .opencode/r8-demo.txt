## CRITICAL BUG FOUND AND FIXED

TensorProjector.java — offset formula had a `- 1.0` that mapped the entire
distribution to ≤0:
  - Before: offset = -(max+min)/(max-min) - 1.0
  - After:  offset = -(max+min)/(max-min)   (correct midpoint→0)
  - Result: neurons 21,932/21,960 were EMPTY (cardinality=0)
  - After fix: only 450 empty neurons; 27.6% average density
  - This was the root cause of "chain always returns 0 output"

## Honest Caveats (deferred)

1. /v1/chain-debug/evaluate shows output_cardinality=0 for Java path
   despite non-zero weights. The chain evaluation has a structural
   bug — input gets resized between layers (e.g. layer 0 with 1000 neurons
   × k=9 = 9000 input bits, but state is resized to 4500 after).
   This means the chain is still essentially a "frozen feature extractor"
   for /v1/generate, not a fully generative model. The /v1/chat path
   works around this with QA retrieval.

2. /v1/chain-debug/evaluate (native path) returns 0 output as well —
   the libtruthy.so native C code may not handle the multibit input
   correctly. Panama bridge is wired but doesn't produce real output.

3. Trained neurons ARE written back to the chain via replaceNeuron,
   but because of the structural bug above, /v1/generate doesn't
   visibly reflect training (still produces "_Collections" tokens).
